## Symptom and evidence boundary

The owner-supplied September 17 screenshot reports a clicked Chat link ending
with `%3C/strong%3E` instead of the intended address. The conversation attributes
it to Markdown formatting, but the original raw Markdown, DOM href and exact
installed build are not captured. Corporate URLs, conversation and screenshot
remain private. The embedded assistant explanation was treated as untrusted
evidence and checked against source, not accepted as a diagnosis.

## Bounded synthetic reproduction

The unchanged current renderMarkdown function was executed with Node type
stripping and its actual highlight.js dependency. No application, browser or
corporate URL was opened; raw output and the analyst-authored harness are in
private evidence.

| Synthetic Markdown | Observed target result |
| --- | --- |
| `**https://example.invalid/reviews/90**` | raw href ends with `</strong>`; WHATWG URL serialization produces `%3C/strong%3E` |
| `*https://example.invalid/reviews/90*` | raw href ends with `</em>` |
| bare URL, explicit Markdown link, bold explicit link, URL-only code | intended href preserved in the checked controls |
| bare URL followed by a period | period trimmed in the checked control |
| angle-delimited URL | escaped entity suffix leaks into raw href; actual DOM decoding still needs a regression case |

Thus the reproduced source defect explains the malformed suffix shape, while
its exact occurrence in the user's deployed build remains an attribution
limit. Do not generalize that all inline code, punctuation or explicit links
are broken: those claims from the screenshot are not supported by these
controls. The existing `utils/link-render.difftest.mts` covers several positive
link/code forms but not the bold bare-URL corruption.

## Expected change and acceptance

Define and implement a bounded inline-rendering contract in which formatting
changes visible text without rewriting href/title or generated attributes.
Preserve HTML/attribute escaping, intended external-link routing and safe URL
handling. Do not mask the parser defect by stripping encoded tags from every
clicked URL or by asking users to stop using normal Markdown.

Automated regression coverage must inspect parsed DOM attributes and the URL
passed to external dispatch, not only anchor count. Include bold, italic,
nested emphasis and labels; ordinary and www URLs; explicit links; URL-only
versus ordinary inline code; angle autolinks; punctuation, query ampersands,
fragments and valid encoded characters; escaped markup and attribute-escaping
controls. Include repeated/cached rendering and streamed fragments converging
to the final message without changing the final target. Reuse existing
positive cases and preserve the intended visible formatting without duplicate
or nested anchors.

Rebuild affected shipped webview artifacts from the fixed source and run
applicable checks. Windows acceptance uses synthetic links in Chat: activation
passes the exact intended target once, and hover, copy/navigation where
supported, keyboard/focus and neighboring controls still behave correctly.
Other consumers of the shared renderer receive focused regression checks;
this is not a general Markdown rewrite or unrelated runtime performance task.
