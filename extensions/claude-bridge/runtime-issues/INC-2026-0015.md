# INC-2026-0015 — Usage chart accepts responses for an obsolete range

- **Status:** confirmed (source and controlled promise-order proof; not fixed)
- **Priority:** P2

- **Acceptance:** automated deferred-response tests; isolated dashboard runtime
- **Corporate observation owner:** none

## Symptom

Rapidly changing the dashboard Usage chart period can leave a Yearly label above
an older Daily response. The chart can show empty or incorrect values, and its
loading indicator can disappear while the selected period is still loading.

## Confirmed facts

Audited source: `a34ab4892058bcacc00de8d97ae951fb60551780`.
Paths below are relative to `extensions/claude-bridge/server/src/ui/src/`.

- `components/dashboard/UsageChart.tsx:44–46` keeps selected period, raw data and
  loading in independent module-level signals. Lines 62–68 unconditionally
  publish every response/error and clear loading without request ownership.
- Lines 189–192 start a new request on each period change. The controls remain
  usable during loading; lines 196–207 interpret the last response using the
  currently selected period's slots.
- `services/api-client.ts:17–21` supplies no cancellation or response-generation
  guard. An actual-source VM test resolved Yearly first, then the earlier Daily
  request: the selected period remained Yearly but the stored bucket was hourly.
  A second ordering confirmed loading=false while the current request was pending.
- Independent caller/source review confirmed reachability in the mounted Usage
  chart. `StatsCard` has its own cancellation guard; this finding does not claim
  all dashboard cards have the same race.

## Hypotheses

No frequency, network-latency threshold or production visual sample is claimed.
BR-21 already tracks metric semantics, timezone and server ingestion freshness;
this is a distinct client request-ownership failure. Coordinate implementation
to avoid filing the same acceptance twice.

## Expected outcome

Only the current request may publish data, errors or loading completion. Tie the
data's range identity to the rendered range and invalidate callbacks on teardown
or replacement; preserve any deliberate cache behavior explicitly.

Test inverted success order, obsolete failure after current success, obsolete
completion while current request is pending, rapid repeated selections and
unmount/remount. Assert bucket identity as well as loading/error state. An
isolated browser gate with delayed responses must keep the label and rendered
dataset consistent. Native Windows acceptance and production analytics are not
required to prove the request-order contract; visual runtime validation is pending.

This card adds research evidence only; it does not implement BR-21 or a fix.
