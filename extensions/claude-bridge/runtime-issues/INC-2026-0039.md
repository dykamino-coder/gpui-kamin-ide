## Symptom and bounded evidence

The owner reports that a teammate's substantive report is followed by an available/idle message that causes another parent response despite the report having been handled. A September 8 screenshot shows the available presentation and such a response.

Allowlist extraction independently checked seven owner-indexed report/idle pairs in one supplied parent transcript. For each identity, a text teammate message is followed by idle_notification(available), both in user-type transcript wrappers. The private extract retains line numbers, timestamps and anonymized identity correlation, without report bodies, commands or credentials. It establishes ordering, not a product defect or a leak between parent chats.

## Limits and deduplication

Persistent teammates may correctly become available after reporting. Do not remove idle events or suppress model input until the pinned CLI contract and actual event owner are known. The supplied transcript contains only one parent and cannot prove cross-parent routing correctness or failure. UI presentation in CliXmlContent.tsx and status derivation in useAgentTree.ts do not themselves show what injects a model turn.

BR-09 already covers report-before-idle and bounded recovery for missing reports; BR-15 owns later selection policy. INC-2026-0007 concerns transcript-reader identity, and INC-2026-0009 concerns replay generation. This task owns the distinct report/presence/model-turn decision and checks the boundary to those existing tasks rather than duplicating their fixes.

## Maintainer research deliverable

Map Agent spawn, child result, mailbox, parent transcript and UI/status handling with exact CLI/Bridge versions. Establish whether the second input is native CLI behavior, Bridge-generated or a replay duplicate. Document which events require a model response and which only update availability, and preserve follow-up work cycles and recovery when a report is actually missing.

Use an isolated synthetic matrix with two concurrent parents, same-name children if supported, active-tab switches, inactive parents, reconnect/replay and nested lineage if supported. Demonstrate correct parent/instance/event identity; cross-chat leakage remains an unproven risk until this test. Establish ownership before proposing any routing or dedup fix.
