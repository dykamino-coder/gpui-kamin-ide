## Symptom and scope

The permissions menu offered the same Claude-oriented labels on Codex and could show another tab's choice. Distinguish the runtime's own modes from approval decisions on the workspace host. Claude mode changes use the existing interactive console where the CLI checks session and account eligibility. For Codex, discover Default and Plan from its app-server and apply a chosen preset to the next turn. Keep the read-only native sandbox and host tool ownership. Test per-session persistence, preset acknowledgement and the approval decision on the host.

## Follow-up on the engine switch

In 1.0.131 the primary button always named the workspace approval policy. A
Codex to Claude switch therefore kept the same label even when the native
engine changed. The host policy belongs to the chat and is stored across
engine switches. An explicit **Bridge tools** control owns this setting.

The engine menu must show the active engine's state. Codex offers the presets
from its app-server. Claude offers the modes advertised for the current native
session and retains the interactive Console option. Keep a requested mode
distinct from a mode observed in the native CLI. A report for a previous
session or a sidechain must not select the mode for the current Claude chat.

Check the change on one tab through Claude, Codex and Claude again. Preserve
the independent approval rule, reject stale actions and confirm both the
requested mode and the effective mode of the resumed CLI. Older Bridge servers
continue to use the interactive Console for Claude mode selection.
