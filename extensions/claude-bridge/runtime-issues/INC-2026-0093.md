## Symptom

2026-11-11 owner screenshot. In one Bridge chat block with two client-side MCP
tool calls (Read and Bash), the Read of an existing 7 KB file showed no result
for about a minute. Both calls then returned `Error: Session destroyed`. The CLI
recorded this as a tool result and the conversation went on.

## Confirmed facts

- Only `cleanupSession()` produces `Session destroyed`. It runs from
  `finalizeTeardownFor()` and rejects every pending client call of the session.
- `POST /api/hooks/:sessionId/SessionEnd/:hookId` called the finalizer for any
  SessionEnd relayed by a non-Bridge hook, even when no teardown was in
  progress. `finalizeSessionTeardown()` did not check that the session was
  tearing down or that the PTY had exited.
- The published CLI bundle (2.1.312, image 6.3.164, checked in a disposable
  container) fires SessionEnd with reason `clear` for `/clear` and `resume` for
  in-session `/resume`. The process keeps running in both cases. The owner's
  global settings include a SessionEnd command hook, so every such event reached
  the finalizer. The finalizer then rejected in-flight calls, removed the session
  and unregistered its hooks and MCP endpoint. The live CLI was not stopped.
- An `mcp:call` frame was marked delivered as soon as the socket accepted it.
  This was true even for a half-open socket or a client that was later replaced
  by a restart or self-update. Reattach only resent undelivered calls, so a lost
  delivered call stayed pending until the 30-minute heavy-tool timeout. The
  client reports the ids it holds every second, and the server did not compare
  them.
- Model or effort restart rejects with `Session restarting`, only after the old
  PTY has exited. Detach grace and explicit end go through `destroySession()`.
  That path kills the PTY and escalates to SIGKILL before the 5 s backstop.

## Hypotheses

The capture does not show which trigger ended the session after the hang. It
could have been a SessionEnd from the live CLI or an ordinary teardown after
a reconnect. Old server logs are not required to fix either path.

## Expected outcome

- Only a real PTY exit can finalize a session that is not tearing down.
  SessionEnd and the timeout close only an open teardown window.
- A call delivered to an earlier socket is redelivered once to the current
  client when that client's complete report does not hold it. Calls the client
  still holds, or calls delivered on the current socket, are never resent.
