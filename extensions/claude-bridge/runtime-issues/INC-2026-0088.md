## Symptom

A reported final assistant response is complete in Bridge Console, but chat
appears to start at a later section. Determine whether earlier content is absent
from the received records, the stored message, the rendered DOM or only the
current viewport. This incident is a follow-up to [INC-2026-0087](INC-2026-0087.md).

## Confirmed facts

- Both hosts use `webview/src/signals/jsonl.ts` and the same JsonlViewer pipeline.
  The workspace forwards the real BridgeHost events rather than parsing its own
  alternate transcript format.
- `appendJsonlEntries` deduplicates canonical UUIDs and concatenates assistant
  content for a shared `message.id`, including across event batches. Streaming
  snapshots cannot replace an already canonicalized message.
- A controlled long answer with three text blocks survives streaming deltas,
  message completion and four separate canonical records sharing a message ID.
  The shipped IDE `chat.html` was exercised in throwaway Linux Podman Chromium.
- The first canonical record replaces all proxy content. If that record contains
  only thinking, already displayed streamed prose temporarily disappears until
  the later canonical text records arrive. This is a distinct observed transition;
  it does not yet explain the reported persistent prefix loss.

## Hypotheses

Investigate canonical/stream interleaving and partial-record deduplication,
render-model or vnode staleness, and clipping/scroll anchoring. Do not select a
fix solely because one of these mechanisms could produce a similar symptom.

## Expected outcome and implementation boundary

Keep the existing client handlers and single webview UI. Fix the first confirmed
lossy layer for both hosts; avoid host-specific text reconstruction. A regression
must demonstrate the failure before the change and retain every text block after
stream completion, split JSONL ingestion and replay. Container acceptance must
inspect received content, store content and DOM separately, and verify that the
opening can be brought into view. Record exact source and bundle provenance.

## Acceptance decision for the bounded source fix

The registration assigned shared reducer/rendering regressions and Linux Podman
production bundles as acceptance. Its adjacent rationale explicitly excluded
Windows CEF proof. CI nevertheless inferred a required Windows gate from that
limitation because the legacy classifier reads adjacent lines as one field.

The bounded [#674](https://github.com/dykamino-coder/gpui-kamin-ide/pull/674) changes
only `useChatScrollPin`'s stale ignore-next-event state, its unit regression,
generated chat bundle and a two-host Linux browser regression. A no-op scroll
assignment produces no browser event; a retained boolean then consumes the first
reader scroll and permits the next mutation to snap down. Unit and production
bundle tests reproduce this transition before the fix in both hosts.

Use an automated merge gate for that source contract. This does not change native
delivery, CEF lifecycle, focus or hit-testing. The existing Linux production
bundle scenario and shared hook tests remain required; CI checks are unchanged.
Lead approval of this separate decision PR must precede product merge. Future
findings that depend on native behavior require their applicable gate.

This decision does not close the missing-prefix report. The previously open
owner page remains unattributed, with bridgeweb responsible for investigation
and the lead responsible for supplying the existing private screenshot. No
Windows runtime or field-success claim is made and no owner retest is requested.
