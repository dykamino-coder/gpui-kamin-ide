## Symptom

A reported final assistant response is complete in Bridge Console, but chat
appears to start at a later section. Determine whether earlier content is absent
from the received records, the stored message, the rendered DOM or only the
current viewport. This incident is a follow-up to [INC-2026-0087](INC-2026-0087.md).

## Confirmed facts

- Both hosts use `webview/src/signals/jsonl.ts` and the same JsonlViewer pipeline.
  The workspace forwards the real BridgeHost events rather than parsing its own
  alternate transcript format.
- `appendJsonlEntries` deduplicates canonical UUIDs and folds assistant
  content for a shared `message.id`, including across event batches. Streaming
  snapshots cannot replace an already canonicalized message.
- A controlled long answer with three text blocks survives streaming deltas,
  message completion and four separate canonical records sharing a message ID.
  The shipped IDE `chat.html` was exercised in throwaway Linux Podman Chromium.
- The first canonical record replaces all proxy content. If that record contains
  only thinking, already displayed streamed prose temporarily disappears until
  the later canonical text records arrive. This is a distinct observed transition;
  it does not yet explain the reported persistent prefix loss.
- A shared scroll defect is independently reproduced: a no-op bottom snap arms
  an "ignore next scroll" flag, but Chromium emits no scroll event for that snap.
  The flag then consumes the reader's first upward scroll. The next text mutation
  snaps back to the bottom even though the reader moved up. All prose remains in
  the store and DOM. This affects both production webview bundles.

## Bounded fix and regression

Remove that stale scroll-event guard in `useChatScrollPin`; the existing landed
offset comparison already distinguishes the programmatic snap from an upward
reader movement. A unit regression fails before the change. A production-bundle
Linux Chromium regression also fails before the change in both hosts: offsets
78 and 1220 jump to 528 and 1670 after a late mutation. The fixed bundles preserve
the reader's offset and allow scrolling to the opening paragraph.

The Linux test also delivers a synthetic long answer with thinking and three text
blocks, separate canonical records sharing one message ID, and duplicate replay.
It also delivers a delayed suffix-only proxy snapshot and delta after canonical
ingestion, so the existing canonical guard must prevent a stale stream flush
from replacing the completed answer.
It checks exact final store content, every prose line in the DOM and opening
visibility. These results establish the scroll fix, not attribution or resolution
of the owner's previously open page. The incident remains `investigation`.

## Hypotheses

Investigate canonical/stream interleaving and partial-record deduplication,
render-model or vnode staleness, and clipping/scroll anchoring. Do not select a
fix solely because one of these mechanisms could produce a similar symptom.

## Expected outcome and implementation boundary

Keep the existing client handlers and single webview UI. Fix the first confirmed
lossy layer for both hosts; avoid host-specific text reconstruction. A regression
must demonstrate the failure before the change and retain every text block after
stream completion, split JSONL ingestion and replay. Container acceptance must
inspect received content, store content and DOM separately, and verify that the
opening can be brought into view. Record exact source and bundle provenance.

## Shared transcript follow-up — 2026-11-10

The lead reported missing recent prompts/answers, incorrect chronology, incomplete
assistant prose and an unreadably narrow chat beside browser Preview. The bounded
follow-up changes the shared `chat-root` ingestion/projection and browser layout.
It keeps the single UI and existing host message contract.

Three mechanisms are reproduced on the baseline production bundles:

- When a window mixes positioned live records and legacy history without `_pos`,
  the ordering helper puts every unpositioned row after the live tail. With 151
  older rows, the 150-row drawable window excludes the recent prompt and answer.
- Split assistant blocks are concatenated in arrival order. Older-page ingestion
  bypasses canonical folding. The derived projection can recover the opening
  under an unchanged ending UUID, but the vnode cache reuses its earlier suffix
  because it never checks the replaced entry. In both hosts the store contains
  the opening while the DOM lacks it after an actual older-page request.
- Browser Preview reserves space against the whole shell rather than its chat
  column. At a 1440 px viewport the reproduced chat is 204 px wide; at 1100 px
  it collapses to zero.

The fix uses file order for fully positioned windows and timestamp chronology
for mixed legacy history, retaining parent edges through folded UUID aliases.
Canonical blocks retain their source positions and merge in source order across
append, older-page and archived-segment paths. Immutable entry replacement
invalidates the rendered row cache. Preview reserves room for the shell columns
and chat, and stacks below the workspace on smaller viewports.

Five automated regressions exercise the actual store/order/render-model logic,
including mounted-tail membership, reverse replay, page-boundary merging,
archived segment replacement, deduplication and parent aliases. No cosmetic unit
test is added. Own isolated Linux Podman headless Chromium runs exercise both
production chat bundles. Before: opening in store but absent from DOM. After:
opening, middle and ending all present in the same rendered answer. A real
BridgeHost fixture with synthetic upstream records and MCP `preview_mount` keeps
the recent prompt and answer mounted; chat measures 446 px at both viewport
widths, with Preview alongside at 1440 px and below at 1100 px.

The screenshots, private fixtures and source/bundle fingerprints stay in private
evidence linked from the Change PR. These controlled results establish the
shared defects and their correction. They do not attribute the historical owner
page, establish live-model transcript equivalence, or verify native CEF pixels.
The owner's running container and sessions were excluded from this work.
