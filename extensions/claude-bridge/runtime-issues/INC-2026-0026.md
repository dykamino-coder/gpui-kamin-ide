# INC-2026-0026 — Bridge incident records split across log rotation

- **Status:** confirmed (actual-module filesystem reproduction; no fix)
- **Priority:** P2
- **Diagnostic PR:** this PR
- **Fix PR:** none
- **Private evidence:** [INC-2026-0026](https://github.com/dykamino-coder/gpui-kamin-ide-priv-evidence/tree/1a30b2d8f3b3da85c84da9589a4df2c5362afcee/incidents/INC-2026-0026)
- **Dependencies:** follow-up to BR-30; related INC-2026-0020
- **Acceptance:** extension emitter boundary/UTF-8/restart tests + Windows filesystem gate
- **Corporate observation owner:** not required for synthetic filesystem acceptance

## Symptom

Bridge renderer samples and connection transitions can be split between two
retained incident.log generations. Each file then contains an invalid JSONL
fragment, weakening the diagnostic trail needed for long-session crash research.
This is a confirmed source defect, not proven corruption in the owner's logs.

## Confirmed facts

- Audited main `a34ab4892058bcacc00de8d97ae951fb60551780`:
  `extensions/claude-bridge/extension/src/incident-diagnostics.ts:124–125`
  sends a complete formatted incident line through `RollingLogWriter.write`.
  Both renderer samples and connection transitions use this emitter. Installation
  at lines 155–169 sets a 1 MiB cap, three backups and rotation on open.
- `src/kamin-host/rolling-log.ts:107–132` fills the current generation's remaining
  bytes, then rotates and writes the remainder. Unlike `writeRecord` at lines
  81–105, this raw-stream API does not preserve structured-record boundaries.
- The tracked shipped artifact `builtin-extensions/claude-bridge/extension.js`
  contains the same `emit` call to `.write`; the defect is not confined to unused
  TypeScript. The emitter is also present in documented installer source
  `c599cae23afb8393ed1377a67f91b13082902115`.
- An isolated harness loaded the actual TS writer and extension diagnostics module,
  registered the real sample callback and used temporary synthetic files. At
  the production cap, 80 bytes of remaining capacity split a 314-byte sample
  into 80 bytes in `.1` and 234 in current. Neither fragment parsed independently;
  their concatenation parsed as a renderer-sample. Root rerun passed.

## Counterchecks and scope

BR-30 added the correct record-aware API and migrated the host emitter in
`src/kamin-host/incident-log.ts`. Its existing host filesystem acceptance remains
valid. The Bridge extension still bypasses that path, despite the broader
all-emitters expectation in `RUNTIME_RELIABILITY.md:1391–1396`; current extension
diagnostics tests do not cover real rotation files. This is a bounded follow-up,
not grounds to discard the host fix or its Windows results.

The host `data/incident.log` and extension
`data/globalStorage/dykamino-studio.claude-bridge/incident.log` are different files.
One host startup record is expected while the child remains alive; this defect
does not explain that observation or establish the cause of CEF termination in
INC-2026-0020. No user Bridge generations or native Windows run were available.

## Expected outcome

Route the extension's structured emitter through the record-aware contract,
define bounded handling of oversized records, and regenerate its shipped bundle.
Preserve the raw host.log stream behavior and retention limits. Add tests through
the actual extension emitter for samples and transitions, ASCII/UTF-8 boundaries,
restart, and individually parseable retained generations. Run the filesystem
gate on Windows; native GUI access is unnecessary for this acceptance.

This Diagnostic PR contains research only. Keep the incident open until a
separately authorized Change/Fix PR implements and verifies the complete path.
No registry update, production change, version bump or release is included.
