## Reported symptom and hypotheses

The owner reports occasional hangs of Read/Write/Edit/Glob/Grep/Bash tools
executed locally through the Bridge server and KaminIDE client. A socket issue
is suspected. No failing request ID, paired transport trace or local reproduction
is yet available. Socket failure, process lifetime and server overload are
hypotheses, not established causes.

## Investigation and exact next evidence

Trace server MCP proxy, WebSocket admission/delivery, extension-host dispatch,
local execution and terminal response correlation. Examine deadlines, queued
cancellation, buffered bytes/backpressure, reconnect during a call, stale or
duplicate IDs, heartbeat, large results and Bash children that do not exit.

Use isolated local processes and synthetic fixtures: throttle socket consumption,
break it before and after dispatch, reconnect while a call runs, return a large
output and run a controllably stalled child process. Assert every admitted call
has exactly one explicit terminal outcome, bounded retained memory, cancellation
that releases owned resources and no accidental repeated Write/Edit/Bash effect.

If this does not reproduce a cause, add or enable bounded metadata diagnostics
for the next field occurrence: request/session IDs, connection generation,
dispatch/send/response timestamps, queue depth/bytes, bufferedAmount, heartbeat
age, timeout/cancel/disconnect reasons and process exit state. Correlate both ends
without recording tool inputs, file contents, output, credentials or environment
values. Lead captures the failing request interval and exact versions, then the
worker matches the last acknowledged lifecycle stage to a local fault scenario.
Do not request unrestricted logs or access the owner's environment.
