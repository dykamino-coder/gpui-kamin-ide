## Symptom and cause

During the initial rollup build, `loadRoster()` in the dashboard users controller
groups the entire `session_tokens` table by `user_name` on each request. The
lead's 10 GB synthetic run measured p95 781 ms and max 1141 ms.

## Bounded implementation

Persist one roster row per live owner, with session count and first/last dates.
Seed existing databases once at schema migration. Update the owner row in the
same serialized transaction as session discovery, attribution healing and
deletion. Read this small table during the rollup build. A short TTL cache is
outside the requested solution.
