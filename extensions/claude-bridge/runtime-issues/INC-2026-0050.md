## Symptom

While interacting with an embedded element, pressing Tab navigated outer IDE
controls instead of the intended controls inside the view. The old note does
not identify the embedded panel, element, initial focus or whether tab text
insertion rather than focus traversal was expected. A current regression is
not asserted.

## Checked source and historical fix

[Commit 66a0eb2](https://github.com/dykamino-coder/gpui-kamin-ide/commit/66a0eb22ea93289da6b884d365b0cc7c7de70997)
added Enter/Tab character events in the older 1.0.21 history and is included
in the 1.0.55 source ancestry. At `14a154b477c92cee5905db6d0e951126a10fb408`,
[crates/shell/src/web/input.rs](https://github.com/dykamino-coder/gpui-kamin-ide/blob/14a154b477c92cee5905db6d0e951126a10fb408/crates/shell/src/web/input.rs) still maps Tab to a character event,
and [crates/shell/src/web/element.rs](https://github.com/dykamino-coder/gpui-kamin-ide/blob/14a154b477c92cee5905db6d0e951126a10fb408/crates/shell/src/web/element.rs) forwards ordinary key events
to CEF and stops outer propagation, except an intentional global shortcut.
This does not prove that the correct native/CEF element owns focus when the
key is pressed. Do not add another unconditional Tab forwarding path.

## Research deliverable and expected outcome

Use representative current Chat composer and Customize input/list controls;
these are a reconstruction matrix, not claimed original affected controls.
Compare focus established by click, keyboard navigation, opening/switching
sessions and returning from a modal or reconnect. Record the focused native
view, CEF document/element, key/modifier delivery and resulting focus owner
using synthetic contents. Test Tab and Shift+Tab, and distinguish normal DOM
traversal, tab insertion in controls that explicitly support it and intentional
navigation out of a view. Native terminal Tab completion is a separate path;
only include it if the original surface is later identified as Console.

Preserve a usable keyboard path into and out of ordinary embedded views and
intentional global shortcuts; do not trap focus everywhere to hide outer
navigation. Modal containment remains BR-10. A later fix must avoid dropped
or double key events and preserve Enter, Shift+Enter, Escape, mouse focus,
adjacent native controls and other sessions. If the historical transport fix
already satisfies the reconstructed case, provide versioned Windows evidence
for maintainer verification instead of changing code. If it does not reproduce
and the missing original element matters, request only that element/gesture
and record the exact resumption condition.
