## Symptom and evidence limits

On KaminIDE 1.0.75 / Bridge 6.3.152 a successful auto compact did not create a
new Current history segment until reconnect/application restart. A later
capture shows the new boundary, auto trigger, reduced context and summary.
The compact completed and the boundary survived. The earlier Console also
reported transcript trimming and a separate non-blocking hook error. Those
outputs do not establish the exact file-write order, exception or common cause.

## Confirmed source defect

At baseline `6c3e5a6a`, `JsonlWatcher.checkForNewContent()` returns when the file
size is no greater than `lastOffset`, and never invalidates the consumed cursor
when the same file shrinks. If a rewritten compact boundary lies below that old
cursor, subsequent appends can resume delivering later messages while skipping
the boundary. The index rebuild is triggered only by a boundary in the delivered
tail, so the segment strip can retain its old authoritative index until replay.

An actual-watcher probe uses a disposable synthetic file: original offset
50316 bytes, rewritten size 434 with a second boundary. No new range is read.
After growth to 50990 bytes the later ordinary message is delivered, but the
new boundary is absent and no index rebuild occurs. A full replay discovers
both boundaries. Existing append-only watcher tests pass and do not cover this
rewrite sequence. Relevant source is unchanged from released 1.0.75 to 1.0.76.

## Expected result

Recognized shrink/replacement invalidates the old offset and in-flight replay
work. Reset the client cache/mirror and replay generation before delivering the
new authoritative file, rebuild its segment index and resume tailing from the
actual consumed offset. Preserve backpressure retries, genuine empty files,
subsequent growth and stats exactly once. Do not change conversation identity
for a same-path rewrite, edit a real transcript, or run an unknown cleanup hook.

Do not infer that every rewrite can be detected from size alone: same-size or
larger in-place changes need an explicit bounded identity/cursor validation
contract or a documented residual limit. New-file compaction must retain its
existing conversation-link behavior. Tests must expose the recovery path and
prevent stale asynchronous reads from committing an old cursor after reset.

Field observation after release: in an isolated user session with multiple
compact segments and an active child, observe a natural compact, continued
messages, history/parent switches and reconnect using the linked checklist.
Do not run an unknown cleanup hook or force compact against production data.
Hook exception provenance remains INC-0037.

## Prepared bounded implementation — 2026-10-19

The watcher detects an observed size decrease or a changed filesystem identity
(device/inode), emits the existing client cache/mirror reset event and replays
the authoritative file without changing conversation identity. Tail reads,
index rebuilds and final fingerprint completion are generation-scoped, so a
superseded asynchronous read cannot publish obsolete rows or commit its offset.
Replacement during an asynchronous read is rechecked before delivery. Recovery
retains the existing backpressure and per-replay stats reset behavior.

Five new cases failed on the baseline. The prepared suite additionally covers
replacement during an in-flight tail read: six recovery/ownership tests cover
shrink, empty rewrite/growth, larger atomic replacement, recovery backpressure,
replacement during read and a superseded same-path tail read. Formatting of the
touched watcher follows the required server formatter; unrelated server files
are not reformatted. Full validation is recorded in the Change/Fix PR.

Residual limit: an in-place rewrite that preserves device/inode and has already
regrown to at least the consumed offset before observation is not detected by
this bounded patch. It does not claim arbitrary content-change detection or
uniquely attribute the owner's field write sequence. A later content checkpoint
contract can address that case without pretending the current size check does.
Native Windows observation has not been run. Source acceptance follows the
separate #381 decision; source acceptance was completed on 2026-10-20 below.
