## Symptom

In a Bridge session a user hook with a tool matcher does not run. Found
during the live gate of INC-2026-0103 (PR #743): the test profile had a
`PostToolUse` hook with the matcher `Edit|Write`; over 9 `Write` calls it ran
0 times, while the hook without a matcher ran for every call.

## Environment and versions

- KaminIDE client built from `main` at PR #743, Windows 11; Bridge server
  image 6.3.170 with Claude Code 2.1.322 in the container.

## Confirmed facts

- Bridge replaces the native file and shell tools by its own MCP server
  `user-tools` and denies the native ones (`--disallowedTools`,
  `server/src/core/pty/session-env.ts`). The model calls
  `mcp__user-tools__Write`, `mcp__user-tools__Bash` and so on.
- The CLI evaluates the hook matcher against that tool name. By the Claude
  Code hooks reference a matcher made only of letters, digits, `_`, `-`,
  spaces, `,` and `|` is a list of exact names; anything else is an
  unanchored JavaScript regular expression. `Edit|Write` is therefore two
  exact names and does not match `mcp__user-tools__Write`.
- The server copies the user's matcher to the CLI settings unchanged
  (`server/src/core/hooks/proxy-rewriter.ts`: `matcher: m.matcher`).
- The hook input also carries the MCP name: every recorded `PreToolUse` and
  `PostToolUse` input of the gate had `tool_name` =
  `mcp__user-tools__<Tool>`. A hook without a matcher that compares
  `tool_name` with `Bash` or `Write` takes the wrong branch.
- The owner's own settings have one hook of this kind (`PostToolUse`,
  `Edit|Write`); the hook examples shipped by Bridge
  (`server/src/core/hooks/library.ts`) use `Edit|Write` and `Bash` too.

## Hypotheses

- None for the matcher. Not checked: the `if` field of a hook
  (`Bash(git *)`), which the CLI also evaluates against the MCP tool name.

## Expected outcome

- A matcher that would match a native tool also matches the Bridge tool that
  replaces it. A matcher that already matches the MCP name, and a hook
  without a matcher, behave as now and do not run twice.
- The hook input names the native tool (`Write`, not
  `mcp__user-tools__Write`) when the hook was written for the native name.
- Gate on the exact candidate: `PostToolUse` with `Edit|Write` and
  `PreToolUse` with `Bash` each run exactly once per matching tool call, and
  a hook without a matcher still runs once.
