## Prepared convergence fix (2026-10-09)

Synthetic tests of the actual refresh implementation failed before the change: an unchanged source pull left version 1 installed while source version 2 was already present; cache-copy failure was not reflected in the sweep. Four actual PluginsPanel fixtures also failed: Active had no completion subscription, an older request could replace a newer result, and late replies wrote UI/persistent cache after disposal or tab change.

The prepared fix records a validated source commit revision after a successful supported Git pull. An installed cache is synchronized even after an unchanged pull when no matching revision/version/path/directory has been published. Completed-copy metadata is stamped only after successful copy; the next launch can repair a prior failed copy. A matching revision avoids a full recopy each launch. Missing/non-Git sources, directory marketplaces, disabled auto-update and uninstalled plugins retain their existing exclusions. Independent sources/marketplaces continue after failure, and partial source/cache failures use the existing INC-0041 result contract. This stamp describes a clean committed Git source; it is not an audit of arbitrary later cache-file deletion or uncommitted edits (INC-0040 remains separate).

Active owns a marketplace-completion subscription even with its chips hidden. It rereads the installed list after completion, reports failure honestly, and accepts only the latest view/request result. A completion burst uses one in-flight read plus one trailing read; unmount/bridge replacement, selection and tab changes invalidate late writes and loader updates. Other tabs retain their existing completion path.

Tests cover ten cache/result cases and five actual panel lifecycle cases. A disposable local Git fixture, using only synthetic commits and local origins, injects one cache-copy failure; a subsequent real unchanged pull repairs version/bytes, publishes the source revision and a third launch does no recopy. Windows extension/webview typechecks and full suites passed. Shipped artifacts are rebuilt in the prepared PR. Native GPUI/CEF pointer-free startup acceptance and internal remote integration remain pending; these tests do not attribute the historical owner's report or certify live MCP catalog convergence (INC-0042).

## Cache failure regression repair (2026-10-10)

Independent review reproduced loss of the working installed payload when an unchanged startup pull attempted cache repair and copying failed. The updated repair copies to a unique staging sibling, writes new metadata to an exclusive temporary file, publishes a complete immutable cache generation by rename, and atomically replaces installed metadata as the commit point. Copy, partial metadata write, payload rename and metadata rename failures leave the previous installPath, bytes and metadata unchanged. Same-version repair does not rename the old directory, including when it is locked by a running Windows consumer. Cleanup removes only unpublished files owned by this attempt; old installed generations are deliberately retained for existing consumers. Automatic retirement of those generations is outside this fix, so disk usage can grow across actual source updates. Matching published source revision/version/path still avoids repeated copies.

Eight fault-injection regression cases fail on the reviewed PR implementation and pass after repair, including same-version and changed-version failures followed by successful retry and no-copy repeat. Startup fixtures also assert old bytes and metadata survive a copy failure. These automated results do not satisfy the required exact-candidate native Windows pointer-free startup gate. The incident remains open with that runtime acceptance outstanding, owned by the maintainer with an authorized disposable candidate.
