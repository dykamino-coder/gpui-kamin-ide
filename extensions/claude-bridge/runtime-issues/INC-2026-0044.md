## Report and limits

The owner reports that some installed plugins occasionally remain at an older version after KaminIDE starts despite believing activation and automatic updates are enabled. A later manual Update exposes a newer version. The supplied screenshot is after that manual update and pointer movement, showing the Active plugin listing on KaminIDE 1.0.55. It does not establish the time the backend finished, the startup auto-update flag, or whether the installed files were stale while the UI showed an old version.

The visible **Enabled** card control activates a plugin; **Auto-update on startup** belongs to the separate marketplace menu. Verify both persisted settings rather than equating them or presuming the owner configured them incorrectly. The spinner waiting for pointer activity is tracked in BR-06, not claimed as proof that startup Git work failed. No extra owner logs are required to register this investigation.

## Bounded source findings

Baseline: `158a28aa152c7be1ab1ec82cde06d59d42d03a5c`. Paths below are relative to `extensions/claude-bridge/`.

- `extension/src/main/ipc/marketplaces.ts:60` schedules an existing startup sweep after 8 seconds. `extension/src/main/marketplace/refresh.ts:94` refreshes sequentially with `autoUpdate !== false`; directory-backed marketplaces return an explicit no-op. Automatic refresh is implemented, not universally absent. Verify registration/lifecycle, eligibility and source type in reproduction.
- `extension/src/main/marketplace/refresh.ts:58` synchronizes installed cache only when a sub-clone reports changed. `extension/src/main/ipc/plugins/handlers-source.ts:170` performs that synchronization after every successful non-skipped manual source pull, even unchanged. Therefore a previously advanced sub-clone with an outdated cache is a candidate that manual Update can repair while another unchanged startup pull does not attempt cache synchronization. Test an interrupted/failed prior cache sync; do not claim this happened in the owner's case.
- `extension/src/main/plugins/sub-clone.ts` scans existing plugin directories, skips absent/non-Git sources, and only updates installed cache entries. Determine behavior for supported remote versus inline/directory sources; do not broaden auto-update eligibility by assumption.
- `webview/src/components/customize/plugins/PluginsPanel.tsx:78` paints a cached installed list and revalidates asynchronously. Its mount/tab effect (`:116`) and card callbacks trigger reads. The direct `marketplaces:updated` listener is in `MarketplaceChip.tsx:28`; `PluginsPanel.tsx:165` hides that marketplace row in Active. There is no equivalent completion listener in the inspected Active list. Test opening Active before the delayed sweep completes: the displayed version may lag even when disk state updated. This source gap does not determine the user's disk state.
- INC-2026-0041 already proves that the sweep loses refresh failures. Reuse its result contract; do not build another generic error-reporting fix here. INC-2026-0042 separately covers runtime reload/tool discovery after plugin changes. A new version label alone does not prove those runtime consumers changed.
