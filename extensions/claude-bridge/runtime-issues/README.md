# Карточки runtime-инцидентов Claude Bridge

Новые Diagnostic PR добавляют один файл `INC-YYYY-NNNN.md` на одну проблему.
Сырые материалы находятся в private evidence repository; здесь остаются только
sanitized symptom, проверенные факты, status, acceptance и private URL.

Автор самостоятельно проверяет и мержит регистрацию по
[CONTRIBUTING.md](../../../CONTRIBUTING.md#task-registration), затем проверяет
карточку в свежем `origin/main`. Отдельная приёмка постановки мейнтейнером
не нужна. Мейнтейнер доисследует зарегистрированную проблему либо принимает
решение/verification в отдельном связанном PR.

Допустимые статусы:

- `reported` — симптом зарегистрирован автором, причина ещё не подтверждена;
- `confirmed` — дефект или нарушенный контракт подтверждён;
- `investigation` — симптом подтверждён, но данных для fix недостаточно;
- `blocked` — явно перечислены недостающие данные или prerequisite;
- `resolved` — связанным Change/Fix PR исправлено и проверено;
- `rejected` — duplicate, invalid или проверяемо не воспроизводится.

Существующие BR-карточки пока остаются в `RUNTIME_RELIABILITY.md`; их не нужно
механически переписывать для начала нового flow.

Все карточки `INC-*` в `origin/main` со статусом `reported`, `confirmed`,
`investigation` или `blocked` автоматически образуют зарегистрированный
backlog. Авторский Diagnostic PR создаёт или уточняет только свою открытую
карточку и не редактирует общий `../RUNTIME_EXECUTION.md`. В карточке указаны
автор регистрации, Diagnostic PR, следующий шаг и dependencies. Merge
регистрации не закрывает incident. Статусы `resolved` и `rejected` принимаются
мейнтейнером по результату исследования/verification или исправления.

Выбранные ID продвигаются в текущую или планируемую runtime-пачку отдельным
coordination PR. Maintainer agent фиксирует snapshot при запуске: входящие
карточки и PR после него относятся к следующему запуску. Собственная находка
мейнтейнера может выполняться сразу внутри порученного scope после явного
добавления к snapshot по
[maintainer flow](../../../docs/MAINTAINER_PR_FLOW.md#задача-обнаруженная-мейнтейнером).
