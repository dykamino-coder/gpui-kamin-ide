# INC-2026-0004 — Layout-hidden webviews remain visible to CEF and bypass eviction

- **Status:** confirmed (source-level; not fixed)
- **Priority:** P2
- **Diagnostic PR:** this incident's enclosing Diagnostic PR (indexed in the research report)
- **Fix PR:** none
- **Private evidence:** [INC-2026-0004](https://github.com/dykamino-coder/gpui-kamin-ide-priv-evidence/tree/b773831dc3a75719109652a89bea8fc1777e2a69/incidents/INC-2026-0004)
- **Dependencies:** none; related performance observation INC-2026-0001
- **Acceptance:** automated visibility matrix + Windows CEF runtime merge gate
- **Corporate observation owner:** none

## Symptom

After a contributed webview has been shown, hiding its containing panel with a
layout toggle can leave the document classified as visible. Its browser then
bypasses the existing sleep and 20-second eviction policy. An animated or
streaming hidden document remains eligible to produce work and retain resources.
This is a source-confirmed scenario, not a measured production CPU incident.

## Confirmed facts

Source revision: `a34ab4892058bcacc00de8d97ae951fb60551780`.
Short `state/`, `ui/` and `web/` paths below are relative to `crates/shell/src/`.

- `crates/shell/src/state/file_tree_body.rs:82–105` collects webviews from every
  active slot without checking parent/child layout visibility. Its separate
  browser-panel branch does check visibility at line 107.
- `state/events/layout_presets.rs:102–134` changes panel flags without removing
  active tools. A previously shown RightBottom remains selected after hiding.
- Actual RightBottom rendering is gated at `state/columns/right.rs:25,115`;
  MainBottom is gated at `state/columns/main.rs:25`. Whole-column gates also
  exist at `state/columns/body.rs:193–209`.
- `web/visibility.rs:105–109` skips CEF/exthost hidden notifications for IDs in
  the calculated visible set. `web/mod.rs:210–214` skips eviction and clears
  their hidden timer. Therefore the TTL never starts for the missed hide path.
- Deterministic source assertions and a layout-state model confirmed that
  toggling RightBottom visibility leaves the collected ID unchanged. Native
  rendering and memory measurements were not performed.

Normal tool replacement can remove a view and exercise working sleep/reap.
Chat's explicit NEVER_REAP policy is intentional; it does not explain retaining
non-Chat views as visible. Customize also intentionally preserves warm views;
that policy must be considered separately from whether hidden pages animate.
No claim is made that every application session owns a Chromium process.

## Hypotheses

The CPU and memory cost depends on the hidden page's workload and supported
Windows hardware. This source path could contribute to INC-2026-0001, but no
causal link to its existing field measurements has been established.

## Expected outcome

Derive visibility from the rendered slot set while keeping intentional warm
retention separate. Tests must cover all slots, parent/child flags, no active
session, incomplete registry updates and a view displayed elsewhere.

The Windows gate shows then hides real contributed views using layout controls,
verifies hidden-state notifications and stopped background paints after grace,
and verifies eligible eviction after TTL. Reveal must rehydrate correctly with
working input and no unexpected Chat replay. Record bounded document/process and
memory counters without assuming one process per browser. Diagnostic publication
does not satisfy this gate or claim the source is fixed.
