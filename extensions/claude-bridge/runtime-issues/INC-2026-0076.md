## Symptom

On the owner's machine (KaminIDE 1.0.78) the app was closed and started again
within seconds. The new window opened, but no web view was ever created. The
chat, Bridge Console, Tools and Agents panels stayed empty. Its periodic
`[views]` diagnostics line listed no views for more than 150 s. Meanwhile the
previous main process stayed in the process list for about 40 s after it was
stopped and could no longer be opened. A later start, after that process had
disappeared, created all four views normally.

## Confirmed facts

Source audited at `origin/main` `9f07472`.

1. `crates/shell/src/web/process.rs` calls `cef::initialize` with a persistent
   `root_cache_path` and `cache_path` in the profile cache directory. The
   comment there says the directory is shared with any tail of a previous
   instance.
2. If `initialize` does not return 1, the app logs
   `initialize вернула … — веб-содержимое будет недоступно` to stderr and
   continues without CEF (`LIVE` stays false). There is no retry and no message
   in the UI. stderr of the packaged app is not captured in the diagnostics log.
3. The installer's own update code measured up to 22.4 s between `taskkill /F`
   and the last `kaminide-gpui.exe` exiting (CEF/GPU teardown, comment in
   `crates/installer/src/steps.rs`).

## Hypotheses

- Chromium's process singleton on `root_cache_path` was still held by the
  exiting instance, so `initialize` failed and the new process ran without web
  content.
- The UI does not tell the difference between "CEF unavailable" and "views
  still loading".

## Expected outcome

- When `initialize` fails because the profile is in use, the app waits with a
  bounded retry, or tells the user and offers a retry.
- The diagnostics log records the `initialize` result.

## Missing evidence and blockers

- The stderr line with the `initialize` result was not captured in this
  occurrence. The research step must reproduce the overlap on a profile copy
  and record it. Owner: maintainer.
- 2026-10-22: the overlap was reproduced in the research for #413 (exit codes 24 and 21), and
  every start now writes `[cef] initialize=<ok> exit_code=<code> outcome=…` to `diag.log`.
  Nothing is missing for this card.
