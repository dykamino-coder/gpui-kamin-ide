## Symptom

Если tab закрывается или connection прекращается во время asynchronous server
startup, новая session может завершить создание уже с закрытым WebSocket и
остаться без штатного detach grace. Приоритет P2: лишние PTY, watcher и proxy
ресурсы сохраняются после ухода клиента, а socket indexes содержат устаревшую
привязку. Production длительность и потребление памяти не измерены.

## Confirmed facts

Source snapshot: `a34ab4892058bcacc00de8d97ae951fb60551780`. Все пути ниже
относительны `extensions/claude-bridge/`.

- `server/src/core/pty/session-ws.ts:149–176` и 404–434 ожидают
  `createSession`, затем устанавливают `authenticatedSessionId` и maps.
  Между завершением ожидания и установкой нет проверки socket lifecycle.
- Close handler в строках 849–851 очищает heartbeat и выходит, если ID ещё
  не назначен. `session:end` в строках 205–209 также не отменяет такой startup.
  Поздняя continuation назначает ID/map, когда единственное close event уже
  обработано, и не вызывает `detachSession`.
- Обычный клиент прекращает неподтверждённое соединение через 25 секунд
  (`extension/src/main/ws/connection-manager.ts:459–467`); закрытие tab и
  network drop возможны раньше. Guards перед client-side отправкой startup
  корректны, но не отменяют уже исполняющийся server request.
- Actual-source handler harness задержал create, отправил close, затем
  завершил create. Итог: socket `CLOSED`, новая session зарегистрирована с этим
  socket, `detachCalls=0`. Независимый cross-review подтвердил результат.
- Проверена потенциальная защита: поздний `ws.send(session:created)` без
  callback на CLOSED socket не вызывает второе error event. Inert test
  настоящего установленного `ws` без сети получил `synchronousThrow=false` и
  `errorEventsAfterTick=0`; соответствующий `sendAfterClose` уведомляет только
  переданный callback. Следовательно поздняя отправка не восстанавливает cleanup.
- Обычный detach ставит десятиминутный timer (`session-core.ts:552–565`). Здесь
  остаются только reaper и другие lifecycle paths: обычно 30 минут idle,
  абсолютный предел 24 часа. Последующий успешный resume той же conversation
  может reattach существующую session. Это не доказательство вечного или
  невосстановимого процесса. `session:destroyed` listener только публикует tree
  update и сам не удаляет stale socket indexes.

## Hypotheses

Не измерены production задержки sync/native/proxy startup и частота совпадения
с close/25-second watchdog. Нативный PTY, настоящий Linux load и Windows
close-tab сценарий не запускались. Synthetic ordering proof не оценивает CPU/RSS.

## Expected outcome

Отдельный Change/Fix PR должен явно владеть cancellation/generation startup:
после ухода владельца завершившаяся session получает корректный cleanup или
bounded detach, а ID/token/socket indexes согласованы. Functional code этой
диагностикой не исправлен.

Automated gate проверяет close и end до/внутри/после каждого await, позднее
завершение startup, replacement/reconnect, startup error и отсутствие stale
indexes после teardown. Добавить CLOSED-send case настоящего `ws`, который не
генерирует повторную cleanup ошибку. Disposable Linux gate: искусственно
задержанный startup, client timeout/reconnect и проверяемое освобождение PTY.
Если заявляется исправление пользовательского close-tab/recovery, дополнительно
нужен Windows runtime gate с точными версиями и evidence.

Связать с BR-05 close-tab/reconnect verification и BR-18 lifecycle teardown.
Это отдельное окно startup, не BR-18A local SessionEnd и не BR-19 shell-RPC
cancellation; их acceptance остаётся самостоятельной.

## Prepared fix and verification (2026-10-09)

Branch `fix/inc-2026-0013-startup-ownership`. Actual WS handler tests failed
before the fix for late create and cold resume after close (no detach call,
stale map). Each create/resume and async model/effort restart owns a generation.
After auth, resume lock and startup, ownership is checked before binding. Close
invalidates pending startup; a late session receives detach grace, explicit
end/replacement destroys it. A session already stolen by another socket is
untouched. Token indexes are removed even on stale socket close; session
teardown removes its indexes. Resume locks release on every exit. This does
not abort arbitrary native/sync awaits: an already running create completes
and receives bounded cleanup, rather than being falsely bound to the departed
socket. INC-0012 owns core admission and optional pre-spawn cancellation.
