## Symptom

Connection diagnostics report an unknown disconnect cause even when the socket
provided a numeric close code that the diagnostic normalizer knows how to classify.
This weakens failure attribution in the Bridge incident trail.

## Confirmed facts

- Source `365a56ade9915811b2034cc205ac7eea11ae466e`:
  `extensions/claude-bridge/extension/src/main/ws/connection-manager.ts:382–401`
  sets `closeCode` on non-intentional socket closure. With an empty reason,
  `error` is undefined; the numeric code remains the useful classifier input.
- `setState:1103–1111` publishes `getState:606–614`, which uses
  `main/ws/connection-state.ts:13–26`. That mapper copies status/error/retry and
  authority fields but omits closeCode, despite its presence in both state types.
- `bridge-host.ts:168–173` records that already-mapped outbound state.
  `incident-diagnostics.ts:59–70,79–87` classifies by error and closeCode; the
  latter can no longer reach it. The tracked bundled `extension.js` contains
  the same omission in `toRendererConnectionState`.
- A harness loaded the real TS mapper and diagnostic normalizer with synthetic
  states. Code 1006 without reason classified directly as network, but after
  mapping as unknown. Code 1000 similarly changed remote-close to unknown.
  Both cases passed, together with working text-reason/authenticated controls.

## Field evidence and counterchecks

The owner-provided INC-2026-0020 trail contains 327 disconnected state records,
all with unknown cause. The source defect explains an information-loss path,
but these rows do not reveal their original codes. Explicit local disconnects
can also legitimately produce unknown; do not label all rows network outages,
infer a server failure or claim this caused the CEF crash.

Nonempty reason text can still classify through `error`. Authenticated maps to
the renderer's connected state correctly. Existing mapper and normalizer tests
exercise their contracts separately, without protecting this numeric close-code
handoff. No socket, server or Windows GUI was started for the proof.

## Expected outcome

Preserve the optional numeric close code through the production mapper into the
diagnostic classifier, with tests through both functions for empty reason/1006,
empty reason/1000, a text reason, and an intentional disconnect lacking a code.
Keep status/authority/retry behavior and sanitized output intact. Regenerate the
shipped extension bundle and run the applicable extension checks. No raw close
reason, token or hostname needs to enter the public diagnostic record.

Research only. Keep the incident open until a separately authorized Change/Fix
PR implements and verifies the missing handoff. No product fix, registry update,
version bump, native runtime acceptance or release is included.
