## Problem and owner contract

The server can own Claude CLI sessions in a container, while the client still
needs KaminIDE to execute tools and display conversation. Provide the same
client capabilities with the container as its local machine and persistent
`/workspace`, serving the existing Bridge UI in an ordinary browser.

Owner requirement, 2026-11-09 (verbatim): «важно что бы страница в браузере
тонкой была и если ее закрыть и открыть работа с агентом не прервется».
Sessions, server connections, tools/shells, MCP/LSP/monitors, queues, pending
prompts, files/watches and terminal scrollback belong to the host. Browser loss
detaches delivery only. Reopen restores complete current state before live
updates. Explicit End/Disconnect and host shutdown are terminal boundaries.

The tracked agent-controlled **PREVIEW panel with HMR** follow-up remains open
until source and executed acceptance are incorporated. Existing file rendering
does not satisfy it.

The inventory classifies native KaminIDE editor/reveal/openInVscode separately.
The Bridge FilePanel and editor-context workflow remain required.

## Implemented bounded source

The executable composes the real BridgeHost and tool registry with browser
environment effects, pinned server administration, container file/watch services
and host-owned local PTYs. It serves the same App/channel tables through the
authenticated HTTP/WebSocket boundary. There is no second UI or copied handler
implementation. `/workspace` is the default cwd; tools can access ordinary
container paths. Isolation is the container and its explicit mounts.

Project and client HOME/settings persist separately from server CLI auth. A
standalone opt-in Compose file supports an existing server or separate combined
client/server containers. Listener/host publication defaults and exact Origin/Host
validation are documented in [PACKAGING.md](../workspace/PACKAGING.md).

Browser detach preserves local Bash/MCP work, pending prompts, retained logical
file watches and host PTYs. Re-attach synchronizes shared transcript/streaming
caches and presentation metadata. Submission identities prevent duplicate
execution, and unknown mutation outcomes are not replayed. Host PTYs restore a
bounded screen/scrollback snapshot. Explicit Disconnect/shutdown cancels owned
shell/MCP work; saved server sessions remain resumable.

Client credentials are held in memory and omitted from workspace ConfigStore
JSON/atomic temporary files; stale stored tokens are ignored before migration.
Browser config/events redact them. Native credential policy is unchanged; no
secure-erasure claim is made for older persisted files.

Automated real-runtime fixtures cover bounded shared-handler and lifecycle
contracts. Production-bundle browser smoke covers assets, authentication and
transport with an explicit synthetic backend. Neither replaces live-model
acceptance or establishes exhaustive behavior coverage by itself.

## Current browser layout scope

The owner correction replaces the obsolete standalone App with a thin wrapper
around the current KaminIDE ChatRoot, Console and Agents roots. Its structure
follows the GPUI shell: left navigation rail, sessions/projects sidebar, open
session tabs and a resizable panel dock. The workspace host owns persisted dock
and sidebar preferences; sessions and pins use the existing shared client APIs.
Chat CSS follows the current chat entry's canonical theme chain.

FilePanel and the project explorer are removed from browser scope by the owner.
Their existing services remain for tools and attachments. Desktop window controls,
DevTools and update UI are absent. Cosmetic removal tests are not required;
Linux Podman screenshots verify the visible composition. Exact pixel comparison
still requires a current KaminIDE reference; an old browser screenshot is not
that reference. Command palette and enhanced Agents presentation are coordinated
with the peer shell-components change; full parity remains open.
