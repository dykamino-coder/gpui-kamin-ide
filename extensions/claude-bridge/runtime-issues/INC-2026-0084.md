## Symptom

`cargo html-test --features wpt-harness` stops with `STATUS_STACK_OVERFLOW` (exit `0xC00000FD`, `3221225725`) in
`depth_tests::special::inline_grid_math_table_and_multicol_paint_at_browser_depth_on_eight_mib`.
The process dies, so every test after it in the suite is not run. Agents therefore cannot get a complete local HTML suite result.

## Confirmed facts

- Reproduced on exact `origin/main` `636f3f5f` in a clean detached worktree. The test binary's PE stack reserve is 8,388,608 bytes. The source code was not modified.
- The same test overflows on a branch whose production `crates/html/src` is byte-identical to `origin/main`, so it is not caused by that branch.
- The test was added by #430 (`bb944577`). It paints documents nested 1026 levels deep for `inline`, `grid`, `math`, `table` and `multicol` inside `regression::on_eight_mib` (`crates/html/src/depth_tests/special.rs:59`).
- `cargo html-test` is defined in `.cargo/config.toml` as `test -p kamin-html --lib --profile agent`. The `agent` profile builds `kamin-html` with `opt-level = 0` (`Cargo.toml`, `[profile.agent]`).
- CI runs `cargo test --workspace` in the `dev`/`test` profile, where `kamin-html` has `opt-level = 2`. The Windows Rust tests pass there on `main`, so CI does not see this failure.
- In the same agent-profile run, other depth tests pass, for example `depth_tests::limit::beyond_box_limit_paints_the_remainder_and_keeps_the_whole_dom`.

## Measured diagnostic checkpoint (2026-10-30)

- Reproduced again on unchanged `d9dcc677` with the existing agent profile and 8 MiB stack. Inline/grid/math/table finish paint; multicol finishes layout and overflows before prepaint completion.
- Existing depth-1026 diagnostic probes pass 33/35 kind/phase endpoints; multicol prepaint and paint endpoints overflow. The paint endpoint includes prepaint, so an independent paint overflow is not established. This is not a passing full suite.
- N=16/32 native entry-RSP measurements show a repeating multicol prepaint chain of 8256 bytes per level: 8,470,656 bytes at depth 1026 before fixed setup. Compiler COFF unwind records confirm `ColumnStack::prepaint_frags` at 1520 bytes, `paint_frags` at 2080 bytes and the column-stack Hooks paint method at 928 bytes. The figures are native entry-RSP deltas checked against compiler unwind records.
- Product shell source/dependency analysis shows CEF, with no kamin-html dependency. The same Rust engine path is unreachable there; a live opt-level 0 shell depth experiment was not performed under the no-screen/no-focus constraint.
- The original measurements above precede the fragment frame reduction below; they are not a passing full-suite result.

## Owner decision and expected outcome

- Owner decision 2026-10-30: «надо сделать чтоб и без оптимизации работало не хуже».
- Reduce the real recursive frame cost so the same contract holds at opt-level 0 and 2. No profile-specific depth contract, test weakening, stack increase or profile override is allowed.
- Cover block, inline, float, grid, math, table and multicol in every phase covered by the depth tests.
- Completion means full agent and dev HTML suites on 8 MiB, the required static checks, zero exact-RGB losses and release paint measurements on deep documents and a normal page.

## Final implementation and acceptance

- Keep the existing fragment painting implementation. Extract multicol fragment geometry/layout/background preparation into a non-inlined helper, then borrow the prepared replay route during ordinary child prepaint. This removes retained temporaries and an extra by-value route slot from the recursive step. Existing optional decoration/repeated-band preparation can still perform nested work; no traversal semantics change.
- No tests, native stack sizes, profile settings, depth limits or shared scripts change. There is no new per-kind depth branch, heap traversal state or dependency.
- Normally merged exact main `2526be1f99d8b480a3e523e15c953399278bdc33`. All results below use that integrated candidate and exact controls; earlier acceptance runs are historical.
