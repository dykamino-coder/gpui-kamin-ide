- **Status:** candidate verified in isolated fixtures; lead review pending.
- **Registration author:** bridgeweb, lead-assigned restart persistence follow-up.
- **Completion target:** one tested Change PR for lead review and merge; no release.
- **Diagnostic PR:** known-cause registration accompanies the Change PR.
- **Fix PR:** [#682](https://github.com/dykamino-coder/gpui-kamin-ide/pull/682).
- **Next step:** lead reviews/merges the Change PR, then observes the owner deployment.
- **Private evidence:** not required for source diagnosis and synthetic fixtures; owner observation is attributed to the assignment.
- **Dependencies:** INC-2026-0087 browser host; existing persistent workspace home volume.
- **Acceptance:** automated real BridgeHost process/disk restart and isolated Linux Podman headless browser.

- **Deployment observation owner:** lead.

## Symptom and confirmed causes

The lead reports that a named conversation became a generated numbered label
after restarting the container with the same volumes, and that open tabs were
missing after page reload. The browser history action drops its label argument.
The shared resume handler does not consult saved-session labels; a subsequent
conversation identity callback can save the generated label over that title.
The existing `tabs-state.json` restores presentation preferences and sleeping
pins only: no startup path recreates the host's open tab set or active tab.

## Expected outcome and design

Persist a credential-free, account/server-scoped open-session snapshot under
the configured workspace storage. Observe host tab-list/switch events, including
title and conversation identity updates while no browser exists. Restore through
the shared TabManager, using background resume for stored conversations and
activating only the selected tab. Preserve labels, creation times and title;
closed tabs stay closed. Shutdown must not replace the snapshot with an empty
set. Reuse the existing pin/order persistence and conversation matching.

The shared resume IPC uses the saved title when the caller has no explicit
label, preventing history reopen from overwriting it with a numbered label.
Reject malformed or differently scoped restart state, and never persist a token.

## Candidate verification and limits

Unmodified main `1e9c36ac` reproduced both failures in the agent-owned
`bridgeweb-acc-restart-persist-20261110`: after an actual `podman restart` with
the same persistent bind mount, the open set was empty; history resume changed
the saved `pwd в файл` title to `#1`. The candidate preserved both sessions,
titles, numbered labels, identities, creation times, selected tab and pin through
container restart and page reload. The upstream was a synthetic protocol peer;
the client host, disk stores, production browser and Chromium were real.

`session-restart.test.ts` exercises real BridgeHost processes and persistent
storage across an abrupt kill, subsequent clean restarts, empty tabs, close,
history resume and explicit disconnect. It fails on main at the missing open
set. `session-state.test.ts` checks scoped disk round trips, malformed state and
credential omission. `session-restart.smoke.mjs` checks real production browser
actions across host restarts, pins, active selection, reload and history reopen.

The first upgrade cannot reconstruct an open set never persisted by older hosts
or recover titles already overwritten in history. This change restores session
identity lazily; it does not resume in-flight tools or preserve PTY processes
across host restart. No owner container/session was accessed. This bounded
change does not close full browser parity or establish owner-deployment results.
