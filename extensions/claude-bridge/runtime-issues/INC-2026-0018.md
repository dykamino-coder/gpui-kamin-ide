# INC-2026-0018 — Dashboard JSONL export reads entire transcripts synchronously

- **Status:** confirmed (source-level; not fixed)
- **Priority:** P2
- **Diagnostic PR:** this incident's enclosing Diagnostic PR (indexed in the research report)
- **Fix PR:** none
- **Private evidence:** [INC-2026-0018](https://github.com/dykamino-coder/gpui-kamin-ide-priv-evidence/tree/83f8570637c1780388d36a50ebeb7d9e22a4d72a/incidents/INC-2026-0018)
- **Dependencies:** none; coordinate export policy with INC-2026-0019
- **Acceptance:** automated route/stream tests + disposable Linux HTTP and browser gate
- **Corporate observation owner:** none

## Symptom

An ordinary dashboard user downloading an available session JSONL triggers a
whole-file synchronous read and UTF-8 decoding in the shared server process.
The dashboard also consumes the complete response before initiating the browser
save. Large exports therefore have work and retained-data requirements
proportional to transcript size rather than a bounded streaming window.

## Confirmed facts

Source revision: `a34ab4892058bcacc00de8d97ae951fb60551780`. Paths below are
relative to `extensions/claude-bridge/`.

- The shipping dashboard button at
  `server/src/ui/src/components/dashboard/StatsCard.tsx:475` calls
  `downloadJsonl`. Its disabled state only checks whether JSONL is available.
- At lines 377–399 that function fetches the session endpoint using the dashboard
  Authorization header, awaits `res.blob()`, then creates and clicks a download
  link. It revokes the object URL after one second.
- `server/src/core/dashboard/controllers/stats.ts:562–578` resolves session
  ownership and an indexed path, checks existence, then calls
  `fs.readFileSync(row.file_path, 'utf-8')` at line 575. It passes the complete
  string to the response at line 578. There is no size gate or streaming path.
- The route is registered at `server/src/core/dashboard/routes.ts:30`. HTTP and session
  WebSocket services share the Node server/process (`server/src/index.ts:70–95`).
  Declaring the handler async does not make its subsequent synchronous filesystem
  operation asynchronous.

This is normal authorized UI reachability, not a hypothetical unauthenticated
request. Owner and file-existence guards are real and must remain. Small files
may be cheap. URL revocation prevents the claimed permanent object-URL leak;
none is alleged. Browser Blob storage may use backing storage, so this card does
not claim the entire Blob necessarily occupies JavaScript heap.

## Hypotheses

Read latency, concurrent-session disruption and memory cost depend on transcript
size, storage and workload. No real transcript, measured heap/RSS, CPU percentage,
latency benchmark or production OOM causation was established. The deterministic
resource issue is the unbounded whole-file synchronous step in a shared process.

## Expected outcome

Stream the HTTP attachment with cancellation/backpressure and a defined snapshot
while the source file grows. Preserve authorization; a plain download link is
not automatically equivalent to the current authenticated fetch. Bound repeated
clicks and avoid unnecessary complete-data copies in the dashboard save flow.

Tests use synthetic large files, slow/cancelled clients, concurrent small status
requests, repeated clicks, authorization failures, deleted-file responses and
byte-exact downloaded output. Validate through a disposable Linux HTTP server and
browser download gate. Dashboard-only changes do not inherently require Windows
CEF acceptance; any added native integration must declare its applicable gate.
Keep BR-21 analytics semantics and historical memory-envelope investigation
separate. Diagnostic publication supplies source evidence, not a fixed or
performance-accepted implementation.
