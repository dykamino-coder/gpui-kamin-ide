## Symptom

On KaminIDE 1.0.78 / Bridge 6.3.155 after changing servers, the owner reports
that resuming a conversation absent from the server opens a fresh empty CLI.
The tab retains its old conversation identity and title and offers Start new
conversation / Retry, while describing the displayed CLI as temporary. This
confuses the conversation association and consumes shared-server resources.
The deployment may serve 20 users with 5–10 sessions each; this is capacity
context, not a measured process count.

## Confirmed facts

The owner reported the behavior on 2026-10-21. INC-0070 preserves stored IDs on
resume-not-found, timeouts and rapid exits. This registration does not claim
an independently reproduced field failure or a completed fix.

## Hypotheses

Source audit must establish the exact path from failed transcript lookup to
fresh process creation and define compatibility with both older peers.

## Expected outcome

An opted-in resume-not-found response creates no CLI/session. The client holds
the old conversation ID, shows a recovery notice, disables input with an
explanation and displays no empty CLI. Start new conversation explicitly sends
session:create; Retry repeats session:resume. No identity is silently replaced.
A new client must handle a legacy server that already spawned a temporary CLI;
an old client must retain its existing protocol behavior with the new server.

## Missing evidence and blockers

GitHub CLI authentication is unavailable: the lead must create and merge the
Diagnostic PR from the registration branch after green CI and replace its
pending link. Server verification must use only a new isolated Podman
container and owned volumes; no Claude login or owner container access.
