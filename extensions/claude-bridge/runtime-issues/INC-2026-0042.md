## Symptom and provenance

The owner supplied an agent report of a September 8 Windows incident. Following a plugin version change and removal of the old version directory, a connector attempted a lazy start using the old executable path and failed with `MODULE_NOT_FOUND`. The report says that tools then remained unavailable to the agent in an existing conversation even after the local connector recovered; explicit session disconnect/connect eventually restored them. It includes catalog-count changes, diagnostic excerpts and a successful later call, but not the original logs/transcript or an exact installed bundle.

Treat this as a reported sequence, not proof that all plugin updates fail, that IDE restart never helps, or that every reconnect respawns Claude. Source baseline is `41a60646956e6e2f9fd518e7860f90db20d517b8`; its manifests identify app 1.0.55 / server 6.3.132, and the supplied report independently names server 6.3.132. Bind the reproduction to exact deployed artifacts and container CLI version. A Windows Claude CLI installation is not required by this architecture.

## Confirmed server boundary

- [session-ws.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/server/src/core/pty/session-ws.ts#L672) accepts repeated `mcp:register-external-tools` messages and replaces the session snapshot. It already logs registration counts and names. [tools/list](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/server/src/core/pty/mcp-http-handler.ts#L435) reads that current server snapshot; this does not prove the client snapshot or CLI's view is current.
- The same HTTP handler advertises `tools: {}` without `listChanged` in initialize and returns 405 for GET. No server-side `notifications/tools/list_changed` producer was found. POST already supports SSE for a request response; that is not a persistent catalog-change channel. The server therefore has no implemented proactive tool-list invalidation path to the live CLI.
- GET 405 is permitted by [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#listening-for-messages-from-the-server). It is not, by itself, a protocol violation or an unauthenticated data exposure. [Tool-list notifications](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#list-changed-notification) provide a possible refresh mechanism; actual compatibility must be checked against the negotiated protocol and supported CLI. Adding SSE alone does not prove that deferred ToolSearch updates in the same conversation.
- [Live reattach](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/server/src/core/pty/session-ws.ts#L342) deliberately reuses the existing CLI and updates its stored external-tools snapshot. Distinguish WS reattach, MCP reconnect, explicit disconnect/resume and CLI respawn in evidence.

## Confirmed client behavior and narrower gaps

- **Dynamic registration already exists.** [BridgeHost](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/bridge-host.ts#L348) wires `onToolsChanged` to send a complete snapshot to every authenticated tab. Connect completion/failure, stdio exit, explicit toggle and received upstream list-change notifications have callback paths. This code is also in the checked-in extension bundle. Do not implement a duplicate registration mechanism based on the report's claim that only session startup sends tools.
- **Runtime reload exists on explicit plugin actions.** [Plugin IPC](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/ipc/plugins.ts#L26) connects install/uninstall/options/source handlers to `reloadPluginRuntime`, which calls MCP discovery again. Manual plugin-source update invokes it after a changed source. This disproves a universal stale-path defect on every update.
- **The marketplace sweep has a distinct stale-config path.** [Marketplace refresh](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/marketplace/refresh.ts#L45) can invoke `syncPluginCacheFromSubClone`. [That helper](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/plugins/sub-clone.ts#L100) removes the version-cache parent, copies the new version and changes `installed_plugins.json`. The marketplace IPC has no runtime-reload callback. Discovery resolves plugin-root arguments in advance; [stdio spawn](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/mcp/transports/stdio.ts#L13) uses the existing `state.config` without re-reading installation metadata. Unless another discovery path intervenes, that in-memory command can refer to the removed version. The report does not establish which updater ran in the field.
- **Failure recovery is not process-restart-only.** `MODULE_NOT_FOUND` suppresses automatic reconnect in stdio exit handling, but [doConnectServer](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/mcp/manager.ts#L892) clears `permanentFailure` on explicit connect. The existing [connector Test/toggle UI](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/webview/src/components/customize/connectors/ConnectorActions.tsx#L55) reaches these paths; error status and the Test log are already shown. Retrying a stale config still does not re-resolve the path. Preserve bounded retries and circuit breakers rather than replacing them with an infinite loop.
- **Schema-cache behavior is documented but needs an explicit availability contract.** [state-persistence.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/mcp/state-persistence.ts#L85) stores schemas by connection fingerprint; command/argument changes naturally select another key. [Manager export/cache logic](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/mcp/manager.ts#L463) serves connected schemas and eligible lazy cached schemas. Cached error/disconnected states remain eligible, connecting states are excluded, and harvesting skips empty tool lists. This does not support the report's blanket claim that a failed server's tools always disappear.
- **Some cache-only changes miss the registration callback.** `removeServer` deletes a dormant connector/cache and calls only `notifyChanged`; no live process exists to produce an exit callback. Discovery also calls only `notifyChanged`, and `initAll` can skip all warm-cache stdio connections. `notifyChanged` harvests cache and updates the renderer, not `onToolsChanged`. A changed effective catalog in these paths may stay on the server until some other registration event. Check the relevant [manager methods](https://github.com/dykamino-coder/gpui-kamin-ide/blob/41a60646956e6e2f9fd518e7860f90db20d517b8/extensions/claude-bridge/extension/src/main/mcp/manager.ts#L676) and test empty snapshots explicitly.

## Research deliverable and implementation boundary

Map and instrument the distinct states: installed plugin version/config, local MCP process and cached schemas, client-exported catalog, server `registeredTools`, CLI MCP tools/list and deferred ToolSearch availability. Establish which transition diverges in an isolated reproduction and whether the supported CLI responds to a standards-based list-change signal without respawn. Record counts, revisions and bounded correlation identifiers; tool names and paths may also contain private corporate data.

Define subsequent bounded changes for (a) catalog delivery to the existing CLI and (b) client discovery/cache publication after plugin mutation/recovery. Reuse existing callbacks, UI and logs. Decide separately whether a server snapshot request/ack is needed; a new WS message is not automatically required when client push exists. Do not prescribe a global dotenv watcher, unconditional retries, one universal spawn-time rewrite, or fixed debounce/heartbeat constants without testing their lifecycle and resource costs.

If GET SSE is selected, require per-session authentication and ownership, teardown/abort cleanup, bounded queues/timers, no cross-session delivery, supported protocol negotiation, reconnection/resumption behavior and delivery on only one stream when multiple streams are present. Compare semantic catalog content (including schema/description changes), not array length alone. Do not announce list-change capabilities for resources/prompts without implementing them. Absence of a GET subscriber alone is not proof that a model's catalog is stale; define an honest fallback state and recovery path.

Both server and client sources live in this repository. Follow its separate bounded Change/Fix PR and coordinated release flow; the supplied instruction to use two repositories or deploy server-first is not an established requirement. Preserve old/new client and supported CLI compatibility, existing tools/call/truncation behavior, session identity and transcript writer ownership.

## Acceptance and missing evidence

Use disposable synthetic plugin versions and fake data only. Cover cold and warm schema caches; a marketplace background update versus manual plugin update; old-directory removal before first lazy call; connector failure/recovery; explicit Test; add/remove/disable of a dormant connector; zero tools; same-count schema changes; multiple authenticated tabs; detached/reattached sessions; interrupted notification delivery; and permanently broken servers without retry churn. Show separately whether each client mutation changes the local catalog, WS snapshot, server snapshot and actual CLI view.

For a later fix, added/changed tools must become discoverable and callable in the same live conversation without restarting KaminIDE, replacing the conversation or forcing CLI respawn for supported combinations. Removed/disabled tools must converge according to the agreed lazy/error contract; an updated plugin must not launch its removed version. Include automated protocol/cache/lifecycle tests, shipped extension/webview rebuilds and actual Windows runtime acceptance. A visible compatibility fallback for unsupported combinations is not proof of seamless hot refresh.

Missing historical evidence: original timestamped client/CLI logs, the actual update action, deployed bundle provenance, exact CLI version/protocol, before/after server snapshots and tools/list requests, and whether the observed reconnect reused or replaced the CLI. These are verification limits, not blockers to registration. The unrelated reported HTTP 421 belongs to the external connector HTTP exchange; the single line does not identify whether service validation, ingress or client URL/headers caused rejection. Do not fix it in this task or label ingress at fault without evidence. Registration claims no functional fix or runtime reproduction.
