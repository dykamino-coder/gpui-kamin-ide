## Reported symptom, not an attributed cause

The operator reports a ChatGPT thread banner followed by a Claude CLI mod
fallback warning, no visible chat-history entry, a detached/running session
with zero message/context counters, and a large memory number in Dashboard.

or process measurement establishing why the first turn did not appear.

## Source audit

Baseline: `2212d6e14d701b3184a200cd742413667175ad08`.

| Boundary | Current source and bounded finding |
| --- | --- |
| Requested engine | `extension/src/main/ws/connection-manager.ts` includes the tab's engine in create/resume; `noteSessionEngine` adopts the server's reported engine and drops a model belonging to a refused engine. |
| Chosen engine | `server/src/core/pty/session-ws.ts` calls `chooseEngineForNewChat` for new chats and returns the actual engine plus any fallback notice. `engine-auth.ts` treats a network-failed account probe as unknown, not signed out (#1205). Existing fallback policy is retained. |
| Spawned engine | `session-core.ts` returns from `createCodexSession` before reaching the Claude CLI/mod setup. Resume uses the conversation segment/transcript's engine. |
| Claude warning | The exact warning originates in `SessionCliControl.warnFallback`; its control is created in the Claude branch. A genuine fresh Codex branch does not instantiate that control. Mixed/stale console output or an engine transition remains a hypothesis; the report does not identify its source session. |
| App-server initialize | `codex/app-server.ts` starts explicit `app-server` over stdio, sends initialize/initialized with a 20 s handshake deadline and includes stderr on startup failure. This path is distinct from browser TUI daemon startup. |
| Threads | `codex-session.ts` issues thread/start or thread/resume, attaches a single sink per thread and refuses a duplicate live attachment. Thread creation alone starts no model turn. |
| First prompt | `session-io.ts` routes typed text through `agentInput`; `CodexSessionBinding.deliver` checks account state and calls the Codex agent. `codex-session.ts` serializes turn/start, includes prompt/submission identity, model and effort, and normalizes notifications. |
| MCP | `session-codex.ts` holds an authenticated MCP endpoint during thread startup and registers the session before the watcher/console path. Existing e2e tests exercise the real Bridge MCP handler with a fake app-server; the pinned binary gate exercises isolated local model/MCP peers. |
| Events and errors | `CodexSessionBinding` projects normalized transcript entries and streams activity/text/usage. It reports account/delivery failures, restart failures and a silent-turn stall. A fresh empty thread is distinct from a submitted stalled turn. |
| Empty history | `session-codex.ts` documents that a fresh transcript appears at the first projected entry; Codex may not have a rollout before the first turn. Existing tests resume an empty chat onto a fresh thread after restart. This can explain zero entries before submission, but does not prove what happened to the operator's prompt. |
| Retention and lease | Hibernation consults `agentInput.liveWork()`: active turns, in-flight submissions and recovery stay awake. An idle thread remains a live shared-home writer until stopped/hibernated. The terminal registry deliberately refuses acquisition while any thread is attached. No idle session is killed or evicted by this investigation. |
| Network reuse | `startHost` builds proxy/CA env at process creation and `host()` reuses that process. A later settings update cannot rewrite a running child's env. A fresh Bridge/app-server starts with current settings. Stale env as the cause of the reported session is unproven; no forced restart of other users' active chats is introduced. |
| Memory | Current `VirtualPty.pid` is 0; Dashboard `getProcessTreeStats` traverses children even if the root PID is absent. Starting at PID 0 can therefore count the Linux container tree for a Codex thread. This bounded accounting defect is tracked separately in INC-2026-0132; attribution of the operator's exact number remains unproven without its originating field/capture. |
