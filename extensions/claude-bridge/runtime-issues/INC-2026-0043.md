## Owner sequence and scope

On September 10, Console became black during work in an active session, and Chat stopped reflecting streamed messages. The owner manually closed KaminIDE, reopened it and selected the same conversation while the server-side agent continued working. The screenshot is from after that restart: Console contains ongoing output, but Chat shows older conversation entries around 18 minutes ago followed by a fresh assistant fragment and an unfinished tool-argument placeholder. Generation remains active.

This is a reported gap in a populated Chat, not BR-22's completely empty drawable window. It is also not evidence of an automatic whole-IDE restart or a Windows sleep/RDP trigger. The initial Console failure and the post-restart history discrepancy may have different causes. Console and Chat intentionally use different presentations; compare committed conversational entries and tool lifecycle identities, not identical rendered text.

## Source countercheck

All paths below are relative to the audited repository baseline.

- `src/kamin-host/exthost-bridge/parent.ts:264` records the child's actual exit and supervises respawn. On a subsequent ready event it broadcasts `kamin:exthost:respawned` (`:212`). BR-04 already owns complete provider/view/state recovery after that event. The supplied trail establishes an exit; it does not establish whether that generation recovered successfully or caused the black panel.
- `src/kamin-host/incident-log.ts:60` opens raw `host.log` with `rotateOnOpen: true` and zero backups, while incident records retain startup/child-exit events. Thus the supplied post-start raw log cannot reconstruct pre-restart stderr. This is a concrete limit of the available evidence, not a new crash cause.
- `extensions/claude-bridge/server/src/core/pty/session-ws.ts:342` already finds and reattaches a still-live conversation, avoiding unnecessary CLI replacement, and `:391` calls the watcher's full replay. `extensions/claude-bridge/server/src/core/pty/jsonl-watcher.ts:865` stops the live tail, replays the current file, then resumes polling; initial replay has generation cancellation, tail preview and backpressure handling. Do not add a second unconditional replay or respawn the live agent on the assumption that reattach is missing.
- `extensions/claude-bridge/extension/src/main/ws/handle-server-message.ts:131` routes PTY output separately from live `streaming:entry`/delta (`:159`) and canonical `jsonl:entries` (`:196`). Live proxy output and a pending streaming fragment therefore do not prove that historical JSONL rows arrived or were persisted.
- `extensions/claude-bridge/extension/src/main/ws/connection-manager.ts:685` can paint the local mirror before network reconciliation. `:694` replays cached entries/status and then the cached current streaming stub; `:964` handles transcript fingerprints and mirror reconciliation. `extensions/claude-bridge/extension/src/main/ws/transcript-mirror.ts:258` initializes an empty mirror from replay and deliberately avoids overwriting a nonempty mirror. Trace actual file identity, cursor, coverage and delivery instead of assuming any existing mirror is complete or prescribing unconditional truncation.
- `extensions/claude-bridge/webview/src/components/jsonl-viewer/JsonlViewer.tsx:189` requests replay for an empty store or outstanding refill debt. Its render path applies compaction segmentation, merging, visibility filtering and a bounded window through `derived-cache.ts`. A populated but stale store and a fresh live stub are possible states to investigate; this source reading does not prove which branch produced the screenshot.
