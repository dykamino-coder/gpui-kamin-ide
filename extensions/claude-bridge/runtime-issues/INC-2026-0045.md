## Report and evidence limits

The owner clicks Compact in an existing chat with many earlier compactions. The context meter remains near full instead of reflecting the completed compaction. Restarting KaminIDE is a suspected workaround, not a verified recovery in this report.

The September 11 screenshot shows KaminIDE 1.0.55 and the selected **Current** segment with a count badge of 2 and multiple older segments. The manual compact divider reports **before 978,010 → after 15,098** and is labeled approximately seven minutes old. At the same time the header displays **98% / 978.1K**. The green reduction percentage and the header occupancy percentage have different meanings; the discrepant token counts are the relevant observation. A new summary and assistant/away-summary content are visible, but that does not establish that a new model turn carrying post-compact usage arrived.

Console reports Compacted followed by a non-blocking `SessionStart:compact` hook error. That error is the scope of INC-2026-0037, not proof that compaction failed or that it caused the stale meter. The image is one UI observation, not an independent measurement of actual model occupancy, exact elapsed latency, or a before/recovered pair. There is no evidence of data loss from this report.

## Prior implementation and bounded source findings

Baseline: `cd7689558b77d82237b9cd13e3c2a450c2c783f2`. Paths below are relative to `extensions/claude-bridge/`.

1. **A related fix already exists.** `webview/src/utils/session-cost.ts:113` explicitly documents the old post-compact frozen-meter report. `computeContextStats` uses the latest eligible assistant usage for Current and the peak for an archived segment. The implementation and matching tests are already present in initial import `dd0353e9f6cea615254ea2d9acb8ae39ef8470fd`; the available history does not identify a separate meter-fix PR. [PR #5](https://github.com/dykamino-coder/gpui-kamin-ide/pull/5) later changed Compact command delivery to `submitText`, not this counter algorithm. Do not reimplement the peak-to-latest fix or assume this observation proves its regression.
2. **The two displayed values have different inputs.** `webview/src/components/jsonl-viewer/SystemEntry.tsx:18` reads `compactMetadata.preTokens/postTokens`. `webview/src/utils/session-cost.ts:141` ignores non-assistant records, including `compact_boundary`, and skips synthetic/sidechain entries or rows without usage. It never consumes the boundary's post-token value. A completed boundary before the next eligible usage is therefore a specific uncovered transition to investigate. This alone does not prove why the owner's Current selection retained the old value: a post-boundary slice without eligible usage can instead return `null`.
3. **Trace selection, ordering and memoization.** `webview/src/components/chat-header/SessionStats.tsx:50–80` slices the resident JSONL entries using `compactSegments` and `activeSegmentIdx`; replay temporarily bypasses segmentation. Its cache key uses tab ID, structure version, segment index, replay state and model. `webview/src/signals/compact-segments.ts` derives resident ranges while the displayed strip can use the authoritative segment index. Verify the actual range, live/archive flag, chronological ordering and structural invalidation instead of inferring them solely from the Current label.
4. **Live compact index refresh is already implemented.** `server/src/core/pty/jsonl-watcher.ts:986` detects a same-file boundary and schedules `rebuildSegmentIndex` (`:577`), which resends boundaries/counts. `jsonl-watcher-live-compact.test.ts` covers this server-side path. An updated segment strip does not itself establish fresh header stats. Do not replace the investigation with another unconditional reload/index-refresh fix.
5. **Existing tests stop short of the reported transition.** `webview/src/utils/session-cost.test.ts:21` supplies newer post-compact assistant usage and checks that it wins over the old peak. It does not pass a real compact boundary followed only by summary/synthetic rows through the SessionStats/segment/replay lifecycle. Source and tests were inspected during registration; no test execution or native reproduction is claimed.

## Maintainer deliverable and acceptance

Use a synthetic session with several compactions and a high pre-compact count. Capture button submission → successful compact boundary → resident store and structure version → chosen range/live flag → stats input/output → visible meter. Cover the period before any further model call and the first subsequent real usage. Record only bounded metadata: entry type/identity/order, model, usage counters, compact metadata, segment selection and derived values; no full transcript, prompts or credentials are needed initially.

Compare repeated manual compacts, current versus archived selection, live tail during reverse replay, same-file and new-file compaction, reconnect/reopen, missing post-token metadata, failure/cancellation, synthetic summaries and subagent rows. Vary hook success/non-blocking failure to test rather than presume the relationship to INC-2026-0037. Use deployed extension/webview/server/container CLI provenance for field comparison; the application label alone does not identify those artifacts, and a Windows CLI installation is not required.

Define which authoritative value and freshness state the meter should show after a successful compact. It must stop presenting pre-compact pressure as fresh Current occupancy without requiring a restart or another user prompt. Where supported metadata establishes post-compact occupancy, reflect it; where it is unavailable or ambiguous, expose an explicit pending/unknown state rather than inventing zero or silently retaining an old value. A later real usage must supersede the provisional state, while delayed replay/old-segment/sidechain records cannot overwrite it.

Preserve archived peak semantics, cost accounting and model-limit behavior. Compact does not mean zero tokens, zero cost, a smaller on-disk transcript or lower process memory. Add meaningful boundary-to-render regression fixtures to the existing latest/peak tests; rebuild shipped artifacts and verify the exact Windows GPUI/CEF candidate without restart, pointer motion, focus change or resize assistance. Do not introduce polling or forced repaint as an unexplained workaround. Register a bounded child only if tracing establishes a separate defect. No product fix or deep attribution is part of this registration.
