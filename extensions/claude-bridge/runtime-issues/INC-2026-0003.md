# INC-2026-0003 — Sidebar session hover does not move sibling rows

- **Status:** rejected (verifiably not reproduced: no sibling reflow on hover)
- **Diagnostic PR:** `docs/br28-sidebar-geometry-baseline` (BR-28, batch `RB-2026-09-A`)
- **Fix PR:** none required; BR-29 proceeds without a sibling-layout fix
- **Private evidence:** [INC-2026-0003](https://github.com/dykamino-coder/gpui-kamin-ide-priv-evidence/tree/main/incidents/INC-2026-0003)
- **Dependencies:** none
- **Acceptance:** paired Windows GPUI screenshots before / on hover / after
  leave with pixel-band comparison inside the sidebar bounds
- **Corporate observation owner:** none
- **Execution:** BR-28 verify of `RB-2026-09-A`

## Symptom

A 2 September screenshot suggested that the session actions pill, shown while
hovering a session row, adds vertical space to the sessions list (a visually
different gap before `N inactive sessions`). BR-28 asked for paired bounds
without pointer movement or scroll between frames to tell a real reflow from
the constant indent of the inactive toggle.

## Confirmed facts

- Stand: KaminIDE 1.0.54 dev build (`origin/main` 830a6ce sources, shell
  binary from `8a1e6f9`), Windows 11, scale 1.25 (logical → physical px),
  sidebar bounds logical `x 56, y 42.4, w 332, h 1044`, scrollbar present,
  15 project groups, two open rows, one pinned row, one active row.
- Hover was injected with the probe (`WM_MOUSEMOVE` posted to the window),
  frames were captured from the main window only (the pill lives in a separate
  overlay window; `overlay` states reported `hover_pill` on every session row
  hover and `[]` after leave). Two idle frames were compared first to measure
  noise.
- Seven cases: open unpinned row, pinned row (twice), active row near the
  viewport bottom, plain open row, inactive row inside an expanded group, and
  the inactive-sessions toggle. In every case the only pixel band that changed
  between before and hover lies inside the hovered row's own 24 px band (the
  pin button expanding from 0 to 20 px, highlight and text colour); no band
  above or below it changed, and the after-leave frame equals the before frame.
- The one recurring band outside hovered rows (physical y 346–356 inside the
  sidebar box) is the live `Session 6` row's time label and status dot
  updating; it appears identically in before-vs-after and in idle frames.
- The pill never appears in the main-window capture, so it cannot occupy
  layout space in the sessions list.

## Hypotheses

- None left for a vertical reflow. The visible gap before `N inactive
  sessions` is the toggle's own indent (left padding 18 px, chevron 12 px,
  gap 6 px), as the source already stated.
- Not covered by the matrix: a sidebar without a scrollbar (this profile has
  more sessions than the viewport) and a hovered row whose label needs
  re-truncation because of the pin expansion; both would still be confined to
  the hovered row.

## Expected outcome

BR-28 closes as optical/expected indent. BR-29 (atomic hover-to-rename) uses
this artifact as its geometry baseline and does not include a padding change.
