## Symptom

Customize → Skills → New skill does not create a skill. It writes a legacy
custom slash command, `.claude/commands/<name>.md`, without frontmatter.
Claude Code has merged custom commands into skills, so new entries belong in
`.claude/skills/<name>/SKILL.md` with `name` and `description` frontmatter.
When no folder is open, the file is written relative to the host process
working directory instead of any project, and the Skills list reads legacy
commands from the same place.

## Confirmed facts

Source baseline: `origin/main` at `a0a21dc`.

- `extensions/claude-bridge/extension/src/main/ipc/skills-agents.ts`,
  `skills:create`, resolves `ctx.getUserCwd() || process.cwd()`, creates
  `<root>/.claude/commands`, and writes the form text verbatim to
  `<sanitized-name>.md`. It neither adds frontmatter nor checks for an existing
  file, so a repeated name silently overwrites the previous one.
- `getUserCwd` in `extension/src/bridge-host.ts` returns the first workspace
  folder or `null`. With no folder open the fallback is `process.cwd()` of the
  extension host, which is not a user project.
- `skills:list` scans project `.claude/commands/*.md`, user
  `~/.claude/skills/*/SKILL.md` and plugin content. Project
  `.claude/skills/*/SKILL.md` is not listed, so a correctly placed project
  skill does not appear in the panel.
- `skills:delete` accepts a bare file name and only removes
  `<root>/.claude/commands/<fileName>`; the webview offers Delete only for
  `project` rows.
- The form label reads "Skill name (used as /command)", and a failed
  `createSkill` call has no error display.

## Hypotheses

None required for the fix. Whether any field user already has stray
`.claude/commands` files under the host install directory is not known; the
fix does not migrate or delete such files.

## Expected outcome

- New skills are created as `<workspace>/.claude/skills/<slug>/SKILL.md`, or
  `~/.claude/skills/<slug>/SKILL.md` when no folder is open; never under the
  host process cwd.
- The slug follows skill naming (lowercase letters, digits, hyphens, at most
  64 characters). Missing frontmatter gets `name` and a `description` derived
  from the first line; author-supplied frontmatter is kept.
- An existing skill is not overwritten; the form shows the error.
- The Skills panel lists project skills alongside legacy project commands,
  which remain listable and deletable.
- Delete removes only a project/user skill directory or a legacy project
  command, by path; plugin content and other paths are refused.
