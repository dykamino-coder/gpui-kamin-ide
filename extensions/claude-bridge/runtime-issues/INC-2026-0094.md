## Symptom

ATON Studio embeds one workspace container per site and lets every signed-in
employee into it through its own sign-in policy. The engine assumes a single
owner. All users therefore see and drive the same sessions, drafts and
terminals, and all agent work runs under one Bridge identity. Studio asked
which of this is safe to share and where a per-user boundary is needed.

## Confirmed facts

- One process runs one shared runtime: `createSharedBackend` refuses a second
  instance (`workspace/src/runtime.ts`), and one BridgeHost owns one TabManager.
- The workspace holds one Bridge credential per `storage`
  (`workspace/src/credentials.ts`); every session of every browser talks to the
  Bridge server as that token's identity.
- The sign-in object (`WorkspaceAuth` or an embedder's policy) returns only an
  opaque cookie. The server keeps the
  cookie per socket for revalidation but passes no user identity to the backend:
  `WorkspaceBackend.attach(view)` receives no principal (`workspace/src/server.ts`,
  `workspace/src/protocol.ts`).
- Host events are broadcast to every attached view, so tab lists, transcripts,
  prompts, drafts (`workspace:draft:state`), shell state and terminal output are
  identical for all connected browsers.
- File panel state is keyed by a logical file view id that each document keeps
  in `sessionStorage`; it is per browser document, not per user.
- Preview state (`WorkspacePreview`) is one descriptor per process.

## Hypotheses

- Tabs, drafts and file views could be scoped per user by passing a principal
  from the policy to `attach` and filtering broadcasts; the Bridge identity and
  the project files likely remain shared per workspace.
- Concurrent prompts from two users into one session may need an explicit
  ownership or queueing rule.

## Expected outcome

A documented decision per state item (shared / per user / per view), the policy
API change to carry a principal, and the list of host tests that would prove
it. No behavior change is part of this registration.

## Missing evidence and blockers

None for the research step. Studio's intended product rule (one shared
workspace per team or per user) decides some items; the research records both
variants where the rule is not given.
