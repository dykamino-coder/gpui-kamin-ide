## Symptom and confirmed cause

The assignment reports missing `$RefreshSig$`, `dispatcher.getOwner` errors,
and counter state resetting during hot updates after #655. Source inspection
confirms that the host shares production React without the JSX development
runtime and does not install Refresh before ReactDOM. Federation loads the
container entry; depending on plugin entry injection, its Refresh preamble is
absent or installs a separate runtime. A resource request heuristic cannot prove
that a refresh boundary was updated safely.

## Expected outcome

The preview owns one development React/ReactDOM/JSX graph and one Refresh
runtime installed before renderer evaluation. Default remote plugin boundary
and signature handling controls safe state preservation and unsafe remounts.
The authenticated proxy carries native dev-server HMR without remote aliases
or a hand-written runtime/client entry. Chat remains usable during updates.

## Implementation choice and sources

The deferred preview renderer bundles development React, ReactDOM and both JSX
runtimes together before the outer production build can select their exports.
Refresh injection precedes renderer registration. This supports a normal
development remote's automatic JSX transform without production aliases.

The host observes the native webpack/Rspack web chunk queue before startup,
delegates the remote's Refresh API to its one runtime, and namespaces families
by remote. It drives native HMR check/apply through the authenticated WebSocket
proxy. The plugin retains ownership of boundaries and hook signatures; the
host suppresses the duplicate default dev-server client and removes the
resource-timing remount heuristic. Remotes without native HMR retain the
stable-entry reload fallback.

Mechanism references (implementation is original):

- [Rspack React integration](https://rspack.rs/guide/integrations/react): compiler transform plus Refresh plugin.
- [Module Federation Rspack HMR example](https://github.com/module-federation/module-federation-examples/tree/master/rspack_hmr): ordinary development federation and Refresh setup.
- [webpack HMR API](https://webpack.js.org/api/hot-module-replacement/): check/apply, status and invalidation.
- [React Refresh webpack plugin boundary handling](https://github.com/pmmmwh/react-refresh-webpack-plugin/blob/main/lib/runtime/RefreshUtils.js): signatures and boundary decisions stay with the plugin.

## Verification and remaining gates

The isolated Linux browser suite passes rendering, two counter clicks, a safe
component edit preserving `2` after the polling fallback interval, and a hook
signature edit resetting to `0`. Headless screenshots remain in private local
diagnostics. Focused tests exercise the compiled development graph, injection
order, runtime delegation, family signatures and native HMR decisions.

Support targets default webpack/Rspack web chunk queues and development module
IDs. Custom chunk transports or custom dev-server clients need separate
integration. The preview shares trusted same-context code, not a sandbox.

## Follow-up: documented dev-server path

After #680 merged, the lead reported that an owner deployment's dev server
accepted `/preview/remotes/demo/ws` but closed `/ws`. Source inspection confirms
that the proxy stripped the preview prefix for both transports. The original
acceptance fixture listened on `/ws`, so its passing run did not establish the
documented `preview_mount` configuration.

The follow-up forwards the original WebSocket path without fallback. HTTP assets
use the entry's upstream base: the documented root entry with `publicPath:auto`
maps to root assets; an explicitly prefixed upstream entry retains that prefix.
Entry URLs and redirects do not acquire a duplicate prefix, and relative
redirects resolve against the actual upstream request. This follows the separate
asset and WebSocket paths configured by [Rspack](https://rspack.dev/config/dev-server)
and [webpack](https://webpack.js.org/configuration/dev-server/), without retrying
requests or changing the browser page.

The corrected real Rspack/Refresh fixture and webpack fixture listen only on the
documented prefixed WebSocket path. Integration tests cover both HTTP bases,
query strings, redirects, credential stripping, origin checks and revocation.
The isolated browser run verifies rendering, clicks to `2`, a safe edit retaining
`2`, a changed hook signature resetting to `0`, and actual dev-server frames over
the prefixed socket. This is synthetic local acceptance, not an owner deployment
claim. Exact-head CI is required before READY; lead owns merge and deployment
observation. The incident remains open until lead acceptance.
