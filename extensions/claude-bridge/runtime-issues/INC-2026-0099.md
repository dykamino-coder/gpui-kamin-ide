- **Fix PR:** none

- **Dependencies:** none.

## Symptom

A session is started with effort High. The user picks "Extra high" in the
effort menu of the chat footer. The running CLI takes the change, but when the
CLI process of the session is restarted, the server starts it again with
`--effort high`. The footer keeps showing "Extra high" while the turns run
with `high`.

## Environment and versions

- KaminIDE 1.0.92 on Windows 11 (a copy of the owner profile), Bridge server
  image 6.3.169 in the acceptance container, Claude Code CLI 2.1.322, model
  `claude-opus-5-5`. Not re-run on 1.0.93 / 6.3.170.
- The chat was driven through CDP (`KAMIN_CEF_CDP`) without taking over the
  screen. The release exe has no `kamin-probe`; whether release acceptance
  should have such a tool is an open acceptance-tooling question, not a defect.
## Reproduction steps

1. Open a Claude Bridge chat session whose effort is High. On the server the
   CLI process of the session has `--effort high` in its command line.
2. In the chat footer open the effort menu and choose "Extra high".
3. Send a prompt. The assistant rows of this turn in the CLI transcript have
   `effort: "xhigh"`. The command line of the CLI process still has
   `--effort high` (expected for a running process).
4. End the CLI process of the session on the server (in the run: SIGTERM to
   its PID). The server starts it again.
5. Look at the new process and send another prompt.

Observed: the new process has `--effort high --resume <session id>`; every
following assistant row has `effort: "high"`; the footer still shows
"Extra high".

## Confirmed facts

- Seen once, with the order of events above taken from the step log, the
  process command lines and the transcript rows.
- Bridge builds the CLI arguments in `server/src/core/pty/session-env.ts`
  (`--effort`).

## Hypotheses

- The menu sends `/effort` to the live CLI only and the stored session
  effort that feeds the respawn arguments is not updated. Not checked in
  source.

## Expected outcome

After a CLI restart the session runs with the effort the user chose last, and
the footer shows the effort that is actually in use.

## Missing evidence and blockers

- Source check of where the menu choice is stored. Note for the executor:
  `server/src/core/pty/session-settings.ts` is being changed by another
  task; coordinate before touching it.
- Whether an ordinary restart path (server restart, session reopen) gives the
  same result as ending the process by hand.
