## Confirmed symptom and cause

During [INC-2026-0087](INC-2026-0087.md) behavioral parity work, a real plugin
process published a diagnostic with LSP `severity: 2`. The shared
`LspDiagnostics` tool returned `[Info]` instead of `[Warning]` through the
browser host's actual upstream MCP response.

`extension/src/main/mcp/tools/lsp.ts` concatenates native VS Code diagnostics
and raw plugin LSP diagnostics, then indexes a zero-based label array with
both. [LSP DiagnosticSeverity](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/types/diagnostic.md)
uses values 1–4; native VS Code diagnostics use 0–3. Error becomes Warning,
Warning becomes Info, Information becomes Hint, and Hint falls back to Error.
Both IDE and browser hosts reuse this handler.

## Scope and limits

Normalize only the plugin severity before combining diagnostics. Do not change
the language-server manager or duplicate handlers in the workspace. The stdio
fixture is a deterministic protocol peer, not a production language server.
Its end-to-end assertions cover actual discovery, process launch and routing;
they do not establish exhaustive LSP implementation compatibility or full
browser-workspace acceptance. INC-0087 remains open.

The lifecycle assertions use sessions with a received conversation ID. A separate
synthetic run found that closing an authenticated tab before that ID arrives
does not call the shared LSP/monitor cleanup callback. That independent
TabManager lifecycle defect is outside this severity conversion fix and remains
an open follow-up under INC-0087; normal-session cleanup is not evidence for it.
