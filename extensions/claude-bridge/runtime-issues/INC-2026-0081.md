## Reported symptom

After recreating the production container from Bridge 6.3.158 over existing
volumes, resumed conversations show `PreToolUse:mcp__user-tools__Grep` and
`PostToolUse` command-hook errors containing `{"error":"Unauthorized"}`.
The owner supplied a private screenshot. Production hosts, containers, volumes
and IDE profiles are outside this investigation's permitted scope.

## Confirmed source facts

`createAdmittedSession` creates a fresh Bridge session ID and `mcpToken` for
each CLI process. Reattach and live model/effort switches do not rotate that
token. Restart and resume create a new pair, potentially reusing the previous
conversation's settings directory.

Before the prepared fix, `writeSessionSettings` writes session-specific hook URLs into that shared
directory's `.claude/settings.json`; the relay takes its Bearer credential
from its own CLI process environment. Several awaited operations separate
the settings write from CLI spawn. The server correctly rejects a request
whose URL identifies another live session than its credential.

MCP Tasks #501 supplies a distinct durable MCP endpoint credential; it does
not rotate the per-process hook credential. The URL/environment split was
introduced by the secret-safe relay change #20 (`8b328850`); shared-directory
reuse already existed. This is source attribution of the mismatch mechanism,
not evidence that a recent release first introduced it. The owner's precise
historical launch sequence is not established by the screenshot.

## Reproduction and bounded fix

Overlapping resumes overwrite shared hook declarations before an earlier CLI
reads them. A deterministic server test pauses launch A, launches B against the
same conversation directory, then releases A: the original implementation
returns 401. A synthetic native CLI 2.1.312 probe also reproduces Unauthorized
on PreToolUse/PostToolUse and the lifecycle callbacks.

The fix captures hooks per launch and passes a unique, immutable settings file
through `--settings`. Shared project settings retain permissions and statusLine
but remove persisted hooks from older Bridge versions. The environment still
carries the credential, route authentication remains strict, and snapshots are
removed on PTY exit or spawn failure. No live-token rotation is introduced.

On the final implementation, server typecheck/lint and Prettier pass; 544 tests
pass with 5 existing opt-in skips. Six new cases cover resume interleaving,
stale volume settings, snapshot cleanup, large hook declarations and the
existing non-blocking Stop/SubagentStop status contract. The native CLI probe
performs one MCP Grep call, all six callbacks authenticate to launch A, and
Unauthorized is absent. A native hot-reload reproduction is not claimed.

The registry's `:main` image tag was unavailable (`manifest unknown`). Probes
used the exact 6.3.158 release image with CLI 2.1.312 and current main server
source plus the fix, in an owned temporary Podman container only.

## Separate Stop-loop assessment

The CLI's built-in `/goal` registers a prompt Stop hook. With a deliberately
unmet synthetic goal and background Bash, native CLI 2.1.312 reproduces nine
consecutive blocks while every Bridge status callback succeeds. A separate
401 Stop-relay probe is non-blocking and does not produce the cap warning.
Bridge Stop behavior is unchanged. Goal/task deferral and foreground Bash
grace changes are owned by the lead and remain outside this fix.
