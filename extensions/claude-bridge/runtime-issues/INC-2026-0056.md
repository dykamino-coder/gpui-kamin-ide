## Symptom

The owner asked for an investigation of apparent subagent disconnection, missed responses and incorrect status while a parent session coordinates multiple teammates. The supplied parent transcript contains a persistent teammate that became available, received a later `SendMessage`, and reported again. This establishes a follow-up work cycle, not a failed message delivery. The owner has not supplied a synchronized Agents-panel capture for this exact cycle.

## Confirmed facts

- An allowlist parse of the owner-supplied parent JSONL found a same-agent sequence on 2026-09-30: `Agent` spawn, `idle_notification`, acknowledged `SendMessage`, teammate report, another acknowledged `SendMessage`, report and `idle_notification`. The raw transcript remains outside Git; the private extract contains only line numbers, UTC timestamps, an alias, event types and tool acknowledgement. It has no message bodies or real agent names.
- The checked `Agent` call has no `team_name`, so `useAgentTree.ts` places this agent in `standaloneAgents`. On `idle_notification`, that parser marks a running agent `done`. Its `SendMessage` branch searches only `tree.teams`, appends a lead message there, and never changes an idle agent back to `running`. `touchAgentAlive` updates only `lastSeenAt`; cleanup removes non-running agents from the live tree after five seconds. Consequently this source path cannot represent the observed follow-up as live work, even though the CLI accepted the messages and the child reported afterward.
- No `Agent` or `SendMessage` tool result in the bounded sequence reported an error. The transcript alone does not establish transport loss, a crash, the exact sidebar display at runtime, or why the parent sometimes judged work complete early.

## Hypotheses and boundaries

The Agents panel may undercount or archive a persistent teammate during a follow-up, especially after cleanup or reconnect. Confirm this with a synthetic state test and Windows runtime observation. Parent-agent decisions about whether to wait for an active child may be prompt/CLI coordination rather than Bridge delivery; do not treat them as a proven transport defect. INC-2026-0039 already owns the report-versus-idle model-input contract, so this incident owns only the repeat-work status representation and its UI consequences.

## Expected outcome

The maintainer maps the relevant CLI events to `useAgentTree` transitions and chooses an explicit state contract for available, reactivated and terminated teammates. A follow-up to an available teammate must be represented accurately in the live Agents view through reply, next idle, cleanup and replay without inventing a second agent or confusing same-name agents in different parent sessions. The linked Change/Fix PR includes the synthetic matrix above and the applicable Windows gate. This diagnostic registration does not close the incident or request a release.
