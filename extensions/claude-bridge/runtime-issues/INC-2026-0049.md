## Symptom and scope decision

The owner could not find how to obtain a session folder/reference for passing
an ID to Bridge. The old note does not distinguish copying directory contents
from copying its path or identifier. Scope the first deliverable to obtaining
the correct reference for a selected session; do not implement export of the
folder or invent a new import/migration operation from this ambiguous note.

## Research deliverable and expected outcome

Trace local project path, server settings/session directory, Bridge tab/session
ID and Claude conversation ID from source to any supported lookup, attach or
resume consumer. Determine stability across reconnect, restart and tab switch;
verify whether current UI already exposes the needed value and whether it can
be obtained without searching server files. Do not treat these values as
interchangeable or expose a transport URL/credential as a session reference.

Deliver the exact supported workflow and identifier contract. If a reachable
existing action satisfies it, document the steps with a disposable example
for maintainer acceptance instead of adding a duplicate control. Otherwise
propose a minimal explicitly labelled copy action for the established
reference, including unavailable/disconnected state, per-session isolation,
clipboard failure feedback and keyboard access. If source inspection still
cannot identify the intended receiving operation, ask the owner one precise
question naming the plausible consumers and keep this task open.

Acceptance requires that a user can select the intended session, obtain an
unambiguous reference and use it in the supported Bridge workflow without
copying unrelated session contents. Test two sessions and a reconnect; any
new UI must copy the selected value once and preserve neighboring focus and
mouse behavior. No raw session directory, user transcript or credentials
should be published to demonstrate the workflow.
