- **Completion target:** a message sent before the tab is ready either reaches the CLI once the tab is ready, or stays in the input with a visible error. It is never lost silently.

- **Next step:** the stand check on a build at or after 1.0.118: server restart, send within seconds, the turn starts once (or the input shows the error and keeps the text), 3 of 3. Owner: the executor of the fix.

- **Deployment observation owner:** the executor of the fix (stand check after release).

## Symptom

Every Bridge release restarts the server. Right after a restart, while a Claude tab is still reattaching, a message sent from that tab starts no turn. It does not appear in the chat, no error is shown and nothing is queued.

## Confirmed facts

- Path: `bridgeCmd.send`, which is the same path as the Send button (`sendMessageToTab`).
- At the moment of sending the tab reports `promptReady: false`, `busy: true`, `queued: 0`. About 45 s later: no new user entry, no assistant entry, `queued: 0`, `promptReady: true`, the text is not in the chat.
- A/B, 3 attempts each, a fresh Claude chat with one finished turn, send right after `/health` answers again:
  - candidate 1.0.117 / 6.3.194: dropped 3 of 3;
  - published 1.0.116 / 6.3.193: dropped 3 of 3.
  So it predates 1.0.117 and is not caused by #1048.
- Sending the same text again once the tab is ready works.

## Boundary (2026-11-20, `kacc23`)

Stand: own KaminIDE copy with the `origin/main` bundles, own Bridge server from source with the fake Claude CLI and the fake codex app-server, the server killed and started again, the tab back within 3–5 s.

- Send button while the tab is `connecting`: `InputBar` returns without sending and without any notice; the text stays in the box. Nothing is sent after the tab is back. Claude and ChatGPT chats alike.
- Scripted send (`bridgeCmd.send`, the probe path above): the host refuses it back to the composer with an IDE notification ("Message not sent: the chat is reconnecting"), which the probe did not read. Nothing is sent after the tab is back.
