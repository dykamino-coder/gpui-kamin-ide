# INC-2026-0059 — Editor minimap shows another file and ignores unsaved edits

- **Status:** confirmed
- **Registration author:** @dykamino-coder (owner-directed live acceptance follow-up)
- **Priority:** P2
- **Diagnostic PR:** pending
- **Fix PR:** none
- **Next step:** change — keep one minimap mirror per editor tab, switch it with the active tab and resynchronise it after buffer edits and external reloads; Change/Fix PR by the implementer, acceptance by the maintainer.
- **Private evidence:** pending
- **Dependencies:** none
- **Acceptance:** automated tests for the mirror ownership/sync logic where feasible, plus **Windows runtime merge gate:** required — open several files in an isolated KaminIDE instance, switch tabs back and forth and type into one tab; the minimap of every active tab must show that tab's current buffer.
- **Deployment observation owner:** none

## Symptom

During live Windows acceptance of the GPUI shell, the file `app.ts` was opened
and then the already open tabs `main.rs`, `package.json`, `main.rs` and
`README.md` were activated in turn. Every activated tab showed the `app.ts`
silhouette in its minimap. The minimap also showed the on-disk text without the
tab's unsaved edits. The same result was observed on the integration line and
on `main` at `a0a21dc`.

## Confirmed facts

Source checked at `259925d` (`origin/main`):

- `RootView.ed.minimap_input` is a single `Option<Entity<InputState>>`
  (`crates/shell/src/state/model_editor.rs`), not a per-tab value.
- It is replaced only in `frame_editor_open`
  (`crates/shell/src/state/frame/editor.rs`) when a **new** editor tab is
  created from `pending_editor`. Activating an existing tab
  (`EdEvent::FileOpened` for an open path, `SelectEditorTab`, close/LRU
  eviction, session tab-set switch) does not touch it, so the minimap keeps
  the text of the most recently created tab.
- The mirror is filled once with `set_value` of the opening text. The tab's
  `InputEvent::Change` subscription sets `minimap_stale = true`, but no code
  reads `minimap_stale`; external reloads via `pending_reload` also update only
  the main buffer. Edits therefore never reach the mirror.
- `crates/shell/src/state/columns/file_editor_body.rs` passes this single
  mirror to `ui::editor_minimap::minimap` for whichever tab is active; the
  thumb geometry comes from the active buffer, the silhouette from the mirror,
  so they can disagree.

## Hypotheses

None for the cause. The fix needs a bounded resynchronisation policy (for
example resync the active tab's mirror at most once per frame after a change)
so large files are not copied on every keystroke of an inactive tab.

## Expected outcome

The minimap always renders the active tab's current buffer: correct file after
any tab activation, and unsaved edits and external reloads reflected after the
next frame. Closing or evicting a tab drops its mirror.
