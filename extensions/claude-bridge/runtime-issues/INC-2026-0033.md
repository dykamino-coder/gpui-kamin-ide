## Symptom and available evidence

The owner reports malformed rendering of an assistant response intended to be copied as a prompt. A September 4 screenshot shows mixed prose, monospaced/code-like content, isolated backtick fragments and a table in central Chat, with Console providing a different presentation of the response.

## Limits and deduplication

The original message payload is not supplied for this example. The screenshot does not establish whether Markdown was malformed at generation, altered during normalization, or rendered incorrectly. Console and Chat intentionally use different presentations, so visual difference alone is not proof of a renderer defect. This is distinct from BR-22's empty window and BR-16's scroll anchoring.

## Maintainer research deliverable

Locate the source message and compare immutable input, normalized blocks and rendered output. Start with extensions/claude-bridge/webview/src/components/jsonl-viewer and its Markdown/code/table renderers. Build a small synthetic equivalent using prose, fenced code containing backticks, inline code, table and a long path; exclude private prompt content.

Check fence boundaries, escaping, HTML sanitization, streaming block completion and width/overflow at representative pane widths. Decide whether the product mishandles valid input or is correctly displaying invalid Markdown. Do not select an escaping or CSS fix before this distinction.

## Acceptance and next handoff

Produce a minimal input and expected output contract with a failing renderer/normalization case, or a documented expected behavior outcome. If the screenshot cannot be classified, name the exact message export required. Any later fix must preserve text and safe rendering, pass focused regression tests and applicable Windows CEF visual/selection/copy checks.
