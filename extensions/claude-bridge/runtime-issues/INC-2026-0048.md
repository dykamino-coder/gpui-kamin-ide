## Symptom

After a period without using the IDE, existing sessions did not start. The
owner recalls marketplace-related errors and reports that disabling automatic
updates at startup allowed sessions to load. The original error text, duration,
restart sequence and affected versions are unavailable. The observation is a
correlation, not a proven causal relationship with the update toggle.

## Checked source and hypotheses

At `14a154b477c92cee5905db6d0e951126a10fb408`, [extensions/claude-bridge/extension/src/main/ipc/marketplaces.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/14a154b477c92cee5905db6d0e951126a10fb408/extensions/claude-bridge/extension/src/main/ipc/marketplaces.ts)
schedules the marketplace sweep in the background after eight seconds. This
alone does not establish a blocking dependency between refresh and session
launch. Audit extension-host work, session restore/start, plugin/hook approval
and runtime reload only as potential shared boundaries; do not attribute the
incident to network/authentication or a particular private marketplace.

## Research deliverable and expected outcome

Use a disposable Git/plugin fixture and controlled unavailable, slow and
failing sources. Compare persisted auto-update on/off, cold/warm startup,
restored versus new sessions, an unchanged versus changed source, and one
failing source among healthy ones. Capture session launch requests/outcomes,
extension-host liveness, update start/completion and visible loading state.
Separate not-requested, delayed, failed, blocked-on-explicit-policy and
successful-but-unpainted states. Check that toggling auto-update was actually
the only relevant difference in a controlled comparison.

Define whether any update is legitimately required to start a session. A
nonessential failed refresh must not prevent independent sessions from
starting; a required plugin/approval failure must have a truthful bounded
state and an explicit recovery path that preserves approval/security policy.
Do not solve this by disabling all updates, swallowing failures, bypassing
hooks or silently launching with inconsistent plugin state.

A later fix needs automated failure/timeout/recovery tests and Windows
startup/restore checks with multiple sessions and neighboring UI interactions.
Preserve the eligibility/cache and error contracts from INC-0044/0041. The
maintainer must not seek private credentials; the deployment owner may
confirm the original private remote after normal delivery with sanitized
outcome/build metadata. Lack of that remote does not block synthetic research.
