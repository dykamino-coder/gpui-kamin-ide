## Confirmed symptom and cause

During [INC-2026-0087](INC-2026-0087.md) LSP parity testing, an authenticated
session used its plugin LSP process before receiving `session:conversation-id`.
Closing its last project tab left that process running; the synthetic peer
received neither `shutdown` nor `exit`. Giving the same fixture a conversation
ID made normal close cleanup pass.

`TabManager.closeTab` calls `onTabClosing` only when `tab.conversationId` is
truthy. BridgeHost attaches both `stopMonitorsForTab` and
`pluginLspManager.stopTab` to that callback. Neither lifecycle depends on a
conversation ID, which can arrive later or remain unknown for an empty session.
The condition therefore skips cleanup in both hosts.

## Scope and limits

Call the existing shared lifecycle callback unconditionally for an existing tab,
before disconnect and deletion. Keep missing/repeated tab closes as no-ops and
preserve the other tabs. Do not change language-server transport, monitor process
termination, identity binding, transcript persistence or session resume policy.
Full browser-workspace acceptance remains open under INC-0087.

## Prepared fix and verification

The shared manager now invokes `onTabClosing` for every existing tab before
connection disconnect and removal. Missing or repeated closes still return
without invoking it. The shipped extension bundle is rebuilt from this source.

- Real TabManager baseline: unidentified close and mixed close-all failed;
  identified close passed. After the fix all three regressions pass, including
  callback ordering, once-only invocation and preservation of the unrelated tab.
- Extension build, both TypeScript projects and full suite: 48 files / 240 tests
  passed. Repository conventions and exact-head CI are required before READY.
- Linux Podman independently rebuilds the real workspace and passes the three
  TabManager regressions plus the stdio runtime scenario from #676 with identity
  messages withheld. Baseline leaves the last project LSP process alive; fixed
  close stops it, preserves the other project and disposes naturally at shutdown.
  This supplemental fixture keeps the pre-#676 `[Info]` expectation to isolate
  lifecycle behavior; the committed severity fixture remains owned by #676.

The process proof uses an existing immutable dependency image, a read-only
allowlisted source copy and temporary synthetic HOME without network access.
No operator container or CLI authentication data was used. It does not establish
production language-server coverage or full workspace parity.
