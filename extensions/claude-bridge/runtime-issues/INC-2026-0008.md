## Symptom

Открытие Agents с большим completed transcript может удержать и смонтировать
значительно больше ожидаемых 600 записей. Последующие уникальные сообщения
наращивают UUID index даже после trim; закрытие sessions оставляет subagent
transcripts достижимыми. Длительная работа с множеством агентов поэтому не
ограничена заявленным per-agent cap и session cleanup.

## Confirmed facts

1. Host ограничивает один subagent slot до 5000 записей
   (`extensions/claude-bridge/extension/src/main/ws/connection-manager.ts:1041`)
   и передаёт весь cached slot одним batch на строке 716. Такой initial batch
   превышает renderer cap без нарушения host policy.
2. `extensions/claude-bridge/webview/src/hooks/useBridgeListeners.ts:504–510`
   сохраняет весь первый batch. Cap 600 применяется только при последующем
   `fresh.length > 0` на строках 511–518. Synthetic first batch 5000 и его
   duplicate replay оставили 5000 entries; duplicate не запустил trim.
3. Там же строка 498 добавляет все новые UUID в `seen`, а строка 517 удаляет
   только entries. После двух synthetic batches по 5000 уникальных записей
   actual callback оставил 600 entries и 10000 UUID.
4. `extensions/claude-bridge/webview/src/signals/agents.ts:69` содержит общий
   transcript map. Cleanup на строках 84–95 удаляет trees/live/history, но
   сохраняет transcripts; actual-source close fixture подтвердил retention.
   `extensions/claude-bridge/webview/src/components/agent-tiles/AgentsToolPanel.tsx:158`
   монтирует все entries reader без основного chat render window.

## Hypotheses

Не установлено, вызвал ли этот путь исторический OOM: нужны измерения BR-02.
Не определён безопасный bytes/heap threshold. Role gating уже исключает
subagent map из Console/Plan/Todos; finding относится к Chat и Agents.
Main JSONL eviction чистит другой store. Несколько aliases одного state не
следует считать несколькими копиями payload. Host cap 5000 ограничивает один
его slot, но не lifetime renderer UUID index и число сохранённых agent slots.
Identity исправление INC-2026-0007 само по себе не доказывает bounded retention.

## Expected outcome

Отдельный Change/Fix PR должен применять согласованный cap на каждом ingest
path, ограничивать dedup state с учётом replay semantics и освобождать или
явно ограничивать cache закрытых sessions. Reader должен ограничивать
одновременно mounted rows, сохраняя доступ к полной истории через понятный
on-demand path. Не снижать произвольно все project memory limits.

Automated acceptance: первый batch больше cap, повторный batch без fresh
entries, длительный live stream, repeated replay, много уникальных агентов,
закрытие sessions и повторное открытие. Проверить retained entries/UUID/slots,
отсутствие дублей и корректное восстановление после eviction. Windows CEF gate
измеряет heap и DOM при той же матрице, а также responsiveness reader, scroll
и switch. Synthetic counts не являются Windows performance evidence или
доказательством исправления OOM.

## Prepared fix (2026-10-09)

Branch `fix/inc-2026-0008-bound-agent-retention` from current main. Actual
listener fixtures failed before the fix: first 5000-entry batch, 10000-UUID
index and 200 retained slots exceeded the policy. Each ingest now retains
at most 600 records/UUIDs, 4 MiB serialized UTF-8 bytes per slot, 64 unique
slots and 32 MiB total; aliases do not multiply payloads. Close drops owned
slots. Readers include a recent-history label and full JSONL export for an
unambiguous file ID. Export resolves only the authenticated session's current
or server-owned compact alias directory; traversal and escape links fail.
File byte positions keep old replay from displacing the recent tail even
without timestamps. These cache limits are not a JS heap/OOM guarantee.
