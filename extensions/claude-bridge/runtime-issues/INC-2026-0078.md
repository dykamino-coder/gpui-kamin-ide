## Confirmed facts and evidence limits

Independent review at `dbf157479dfe53e75664d0358bab2fc6a4c3e8d2` extracted actual
functions into synthetic probes. Valid 70–177 MiB transcripts caused synchronous
repair stalls of hundreds of milliseconds; one dirty repair reached about
925 MiB RSS. These are local single-probe observations, not production percentiles
or proof of the owner's historical outage. Owner-reported growing memory, slow
health responses and stalled writes are consistent symptoms; their common cause
and the exact historical checkpoint error have not been reproduced end to end.

The bounded source findings are:

1. F01: resume/repair helpers synchronously read, parse and materialize whole files.
2. F02–F03: replay retains initial history, cancellation does not promptly stop
   reading, and permanently oversized frames are retried as temporary pressure.
3. F04/F08: sweeper retains whole tails, bypasses transaction limits for tool
   results, splits UTF-8 and advances durable cursors past incomplete records.
4. F05–F07: DuckDB has no exclusive writer/maintenance ownership, bounded
   cancellation-aware admission or coordinated process memory budget.
5. F09–F11: initial subagent refusal loses retry observation, unchanged NULL
   attribution repeats updates, and archive size ordering rejects newer shorter
   repaired generations.

Security finding F12 is explicitly outside this task. F14 is also outside scope.

## Required outcome and acceptance

Remove full synchronous scans from resume/request paths using bounded streaming
and worker parsing. Bound file-to-WebSocket work by bytes, including oversized
records, cancellation and slow/disconnected consumers. Preserve complete UTF-8
records and acknowledge only durable committed cursor positions. Apply count and
byte transaction limits to every event kind; retain subagent retry observation.
Use one DuckDB writer, exclusive drained maintenance, a bounded cancelable queue,
explicit database memory/threads within the process budget, distinct-value NULL
updates and verified archive generation ordering. Do not merely raise heap limits.

Run synthetic 70–177 MiB transcripts, torn tails, a giant tool result, parallel
resume/reconnect, a slow WebSocket and maintenance against an isolated local
worktree server or the specifically authorized acceptance container. Record
p95/p99 health and unauthorized-response latency, event-loop delay, peak RSS and
bytes in flight. Compare independently counted/hashed committed records and
archive generations; assert bounded queues, prompt cancellation and eventual
progress without loss, duplicate durable application or retry loops. Publish
fixture parameters, thresholds and measured results with the Fix PR. Do not
claim this proves the historical production root cause.
