## Request

On 2026-10-20 the owner asked for a tool that reads all sessions of a project
folder on the server, so that neighbouring chats in one project can read each
other, for example to restore history. The owner then widened the request to all
read capabilities:

- list the conversations of the caller's project, with titles, timestamps,
  sizes, and live/self markers;
- read them in full (user and assistant text, thinking, tool calls with
  arguments, tool results, attachments, system and compact boundaries, compact
  summaries, timestamps, model and usage), with filters by role or type, time
  range, entry range and tail mode;
- a raw mode returning the exact JSONL lines for exact recovery;
- full-text and regex search across all of the project's conversations;
- per-conversation outline and statistics;
- subagent and teammate transcripts of a conversation;
- a condensed continuation brief to seed a new chat.

All of this is read-only.

## Confirmed facts

Audited `origin/main` `9c4e5fd449d64cdc4ecefd3dd8756713802c76d9`.

1. The CLI reaches Bridge tools only through the per-session `user-tools` MCP
   server ([mcp-http-handler.ts](../server/src/core/pty/mcp-http-handler.ts)).
   Every `tools/call` is forwarded to the client host by `sendMcpCall`. No
   tool runs on the server, and no tool reads Bridge-side transcripts.
2. Transcripts live on the server under
   `~/.claude/projects/<slug>/<conversationId>.jsonl`. The slug is derived
   from the session settings directory
   `bridge-sessions/<tokenId>[-<sanitized cwd>]/<sessionId>`
   ([session-core.ts](../server/src/core/pty/session-core.ts),
   [session-settings.ts](../server/src/core/pty/session-settings.ts)).
   Subagent and teammate transcripts live in
   `<slug>/<conversationId>/subagents/`. Expired transcripts may survive only
   in the durable archive
   ([transcript-archive.ts](../server/src/core/pty/transcript-archive.ts)).
3. The client machine cannot read these paths: client `Read` runs on the
   user's machine. A chat therefore has no way to see the history of its own
   project's other conversations, including the intact old transcript in the
   INC-0070 scenario.

## Security constraints

The server is shared by several users, so these constraints are part of the
contract (compare the history-deletion hardening in
[#390](https://github.com/dykamino-coder/gpui-kamin-ide/pull/390)):

- resolve only inside the caller's token namespace **and** project directory;
  never enumerate other tokens' directories;
- refuse identifiers that could traverse paths, and refuse symlinked
  directories or files;
- read-only; no session or file is modified;
- log each access (caller, tool, target reference, returned size) without
  content;
- bounded memory (streamed reads) and a per-call byte cap with a continuation
  cursor;
- apply credential redaction to the returned text.

## Expected outcome

The CLI sees read-only tools, provisionally `project_sessions_list`,
`project_session_read`, `project_session_raw`, `project_session_search`,
`project_session_outline`, `project_session_subagents` and
`project_session_brief`. A chat can find a neighbouring conversation and page
through it, and a conversation belonging to another token or another project
is neither listed nor readable.
