## Symptom

In Customize > Connectors, a stdio server from `~/.claude.json` with
`"command": "C:\\Program Files\\nodejs\\node.exe"` shows `error`. Its connection log ends with:

- `[stdio] spawned pid=…`, `→ initialize`;
- stderr from `cmd.exe`: `"C:\Program" is not recognized as an internal or external command` (localized Windows message);
- `[stdio] process exited code=1`, then a reconnect is scheduled.

The same server with `"command": "node"` connects and lists its tool.

## Environment and versions

- Installed KaminIDE 1.0.94, and the #823 candidate built from `main` + #823 (`e17146b2`); same result on both.
- Windows 11, Node at `C:\Program Files\nodejs\node.exe`.

## Confirmed facts

- `extensions/claude-bridge/extension/src/main/mcp/transports/stdio.ts` `connectStdio()` calls
  `spawn(command, args, { shell: true, … })`.
- With `shell: true`, Node joins the command and the arguments with spaces and passes the line to `cmd.exe /d /s /c` without quoting. A command or argument that contains a space is therefore split by `cmd.exe`.
- Absolute paths under `C:\Program Files` are the default install location of Node and Python on Windows, so this affects ordinary configurations.

## Not checked

- Whether the native Claude CLI starts the same configuration (its spawn path was not compared).
- Arguments with spaces were not run live; they follow from the same command-line join.

## Expected outcome

The server starts with its command and arguments as configured, with no change for configurations that rely on the shell (for example `npx` resolved through `PATH`).
