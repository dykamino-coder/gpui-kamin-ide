# INC-2026-0147 — Start enabled external MCP connectors on first session admission

- **Status:** confirmed
- **Registration author:** @dvpetrochenko
- **Completion target:** ship the host-side startup fix and validate enabled standalone and plugin-installed connectors at deployment.
- **Acceptance:** automated merge gate for admission, routing and bounded recovery. Deployment owner verifies installed dependencies and authorization.
- **Private evidence:** not required. The isolated extension test creates a synthetic user config, installed plugin, stdio child and HTTP peers.

## Source finding

The host deferred discovery until after authentication, while the first session's readiness callback returned immediately if discovery had yet to start. Registering tools on the Bridge before engine discovery only helps with schemas already available on the host. A temporary failure of the first HTTP initialize request also had no close or exit event to trigger recovery.

## Acceptance

Open a new chat after cold host startup with enabled user and plugin connectors. A ready connector should be declared on session creation and callable on both engines without pressing Test. A slow connector may publish after admission. The host bounds the wait and simultaneous new stdio processes. Temporary HTTP failures use the existing bounded backoff. Rejected authorization stays visible until addressed. Check a reconnect, switching engines and a real installed plugin at deployment.
