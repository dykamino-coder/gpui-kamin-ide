## Symptom and evidence boundary

The owner supplied an agent investigation of a September 7 Windows incident: a plugin-local `.env` and related subdirectories were missing inside a marketplace checkout while the marketplace root remained. The supplied report places a single remaining `clone` reflog entry inside the interval between a successful configuration read and the owner noticing the missing file. Exact times, paths, identities and excerpts remain in private evidence.

These are reviewed second-hand observations, not independently acquired Windows logs. A fresh clone inside the interval does not identify who removed the old files, prove a failed pull, or establish that the installed KaminIDE payload performed the operation. The remaining repository's HEAD tree does not establish the files' tracked/ignored status before the incident. Paired `SessionStart` hooks do not prove an application restart.

Known incident versions: KaminIDE **1.0.55** (owner confirmation), Bridge Server **6.3.132** and container Claude Code CLI **2.1.236** (supplied report). Current source manifests agree with the app/server versions; mapping the affected installer payload to an exact source commit remains a research step. Do not require a Windows Claude CLI version unless process evidence actually identifies such an executable.

## Confirmed current-source boundaries

Source baseline: `53fb216648903bf91f294f727313d1f334d61399`. These findings describe the inspected source and checked-in Bridge bundle, not a forensic identification of the affected installer.

- The conversational CLI is spawned on the server with a server settings directory. Host file/tool operations can be forwarded to the user's machine; container placement alone does not exclude a remotely requested local operation. See [session-core.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/server/src/core/pty/session-core.ts#L328) and [plugin-snapshot.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/sync/plugin-snapshot.ts).
- Client `BridgeHost` registers marketplace IPC. The delayed background sweep invokes `refreshMarketplaceOnce`, which calls local `git pull --ff-only` through `runGit` / `spawn('git', ...)`, without Claude CLI. The failed-pull branch returns an error and contains no remove/re-clone fallback. See [registration](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/ipc/marketplaces.ts#L57), [refresh](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/refresh.ts#L23) and [Git spawn](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/lib/git-async.ts#L39).
- The PAT form exists. `setMarketplaceAuth` rewrites stored authentication and Git `origin`, without re-cloning. It also updates `lastUpdated`; that timestamp alone cannot prove a successful pull. See [auth.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/auth.ts#L24).
- Separate add/remove paths can delete directories: add removes an existing destination when `.git` is absent; remove recursively deletes the recorded installation and installed plugin paths. Their execution in this incident is unproven. Trace callers and user intent before attributing loss. See [clone.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/clone.ts#L78) and [remove.ts](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/remove.ts#L6).

## Hypotheses and withdrawn assumptions

Possible initiators include a separate client add/remove/recovery path, an explicitly requested host tool operation, or another local process. No candidate is established by the supplied reflog. The container binary's re-clone strings are not evidence that this executable ran against the Windows checkout.

Do not implement the supplied five-part fix list as an established solution. `CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE` does not control the client's direct Git call; its relevance and coverage would require identifying a Claude-owned updater. Do not add a re-clone warning to PAT save, which does not re-clone. A backup/restore design, if warranted, must first identify the destructive owner and avoid copying credentials into logs or evidence.

The supplied plugin-side migration moves its configuration outside the marketplace clone and was reported present on one installation. This mitigates that reported placement but does not prove global migration or resolve the underlying attribution question. The reported installation count does not establish how many users had local configuration files or suffered loss.

## Maintainer research deliverable

1. Map the affected installed extension bundle to source. Trace marketplace update/add/remove, sub-clone/cache maintenance and forwarded local tool execution to concrete entry points. Inventory existing diagnostics before claiming that client version or operation logging is absent everywhere.
2. Correlate process ancestry, operation source (startup/manual/tool/other), working directory, sanitized Git operation/result, relevant client logs, metadata and reflog. Record app, Bridge and container CLI versions separately. Obtain any additional executable version only after identifying that process.
3. Use a disposable synthetic marketplace and isolated application profile, with fake marker files only. Cover failed pull/auth/network/divergence, successful update, PAT save, explicit remove/re-add, existing destination without `.git`, and concurrent actors if found. Never change a production remote or use a real `.env`/PAT for reproduction.
4. Produce either an evidenced deletion sequence and bounded preservation/recovery proposal, or an explicit unknown-initiator outcome naming the precise next capture and its owner. If a separate defect is established, register/link it rather than declaring this field incident explained by proximity.
