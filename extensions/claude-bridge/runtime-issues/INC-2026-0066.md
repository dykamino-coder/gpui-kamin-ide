## Confirmed bounded defect

Bridge records the starting model in generated per-session
`.claude/settings.local.json` as well as passing `--model`. A live `/model`
changes the CLI but leaves that pin behind. Claude Code then warns that the
old model will return on restart, although Bridge may recover the new model
from its selection store or the subsequent assistant transcript and regenerate
settings before spawning. The warning can therefore contradict the actual
next launch without any model rollback.

The same explanation becomes confusing to the agent: native CLI settings are
in the server container, whereas its MCP file/shell tools inspect the user's
computer. Searching local user settings cannot disprove the existence of a
generated container settings file. The current built-in instructions do not
explain that distinction for native settings, use an incomplete tool list,
call a persisted Bridge directory temporary and incorrectly identify the
current conversation by the newest file in a shared transcript directory.

## Available evidence and source

- Released baseline: KaminIDE 1.0.75 / Bridge 6.3.152; native CLI 2.1.296.
- `server/src/core/pty/session-settings.ts`: writes the extra `model` pin.
- `session-ws.ts`: a live switch does not update that generated file.
- `session-core.ts`, `model-selection.ts`, `session-env.ts`: model recovery and
  launch arguments already select the conversation model on respawn.
- `system-prompt.ts`, `bridge-default-claude-md.ts`: current instruction text.
- Isolated native CLI comparison reproduced the warning with the old pin and
  removed it without that pin. Both accepted switch and explicit resume
  requested the selected model from the synthetic API. This does not verify
  Anthropic model availability or the full Windows UI.

## Expected result and limits

1. Keep one Bridge-owned model selection at launch through CLI arguments and
   existing recovery; do not generate a second starting-model pin.
2. Regenerating settings removes older generated pins. Preserve other generated
   settings, old conversation models, explicit choices and new-session defaults.
3. Instructions distinguish native CLI settings from user-tools file locations,
   retain native agent routing and require verifying transcript identity rather
   than selecting another conversation by modification time.
4. Do not edit the container-wide user default as part of this fix, force old
   sessions to a new model, or claim the separate INC-0053 UI matrix passed.
