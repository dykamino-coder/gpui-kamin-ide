## Symptom and confirmed source facts

Background marketplace refresh cannot convey the failed-pull result through its current completion notification. A caller of the aggregate IPC also receives `{ok:true}` after the sweep even when an individual marketplace refresh returned `{ok:false,error}`. This hides an actionable update failure behind a notification that contains only the marketplace name.

Source baseline: `53fb216648903bf91f294f727313d1f334d61399`.

1. [refreshMarketplaceOnce](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/refresh.ts#L23) executes `git pull --ff-only`; its catch constructs a `RefreshResult` with `ok:false` and `error`. A normal Git failure is therefore a resolved promise, not an exception for the outer startup catch.
2. [refreshAllMarketplaces](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/marketplace/refresh.ts#L94) awaits each call without inspecting or forwarding the result. It then emits `marketplaces:updated` with `{name}` and a `MarketplaceUpdated` hook regardless of that result. Its empty catch also discards unexpected thrown failures.
3. [Marketplace IPC](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/ipc/marketplaces.ts#L44) returns unconditional `{ok:true}` for `plugins:refresh-all-marketplaces`. The delayed startup sweep uses the same implementation; its outer rejection logger does not see normal returned failures.
4. [MarketplaceChip](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/webview/src/components/customize/plugins/MarketplaceChip.tsx#L28) handles the background notification by clearing its updating state and refreshing the listing, without a failure payload to display. In contrast, its manual single-marketplace update explicitly displays an error toast for a failed result.
5. These functions are also present in the checked-in Bridge extension bundle. This confirms current-source wiring, not the exact installed payload or a Windows reproduction.

The narrow confirmed defect is loss of the per-marketplace refresh outcome at the sweep boundary. It does not establish that every Git error is unlogged, that a success toast is always shown, that PAT save re-clones, or that failure deletes files. Sub-clone/cache failures already have warning calls; their partial-success policy needs explicit preservation or a bounded contract decision.

## Implementation handoff

- Preserve each marketplace's success/failure/skipped outcome across startup refresh, aggregate IPC and UI delivery. Continue updating unrelated marketplaces after one fails, but do not report all-success or emit success-only hooks for a failed operation.
- Define whether existing completion events are neutral completion or success events. Preserve compatibility for existing listeners; add explicit outcome/error delivery as needed. Include a bounded, understandable user-visible failure and a persistent diagnostic result using the existing logging facility.
- Keep manual single-update error handling functional. Preserve disabled auto-update and directory-backed marketplace semantics, sequential/bounded scheduling, unchanged-success behavior, and the documented best-effort sub-clone policy unless a separately justified change is needed.
- Review final error text before logging or UI delivery. [runGit](https://github.com/dykamino-coder/gpui-kamin-ide/blob/53fb216648903bf91f294f727313d1f334d61399/extensions/claude-bridge/extension/src/main/lib/git-async.ts#L60) constructs error messages from command arguments or stderr; redacting only a separate `stderr` field is insufficient to assume the final message is safe. Use synthetic credential-bearing URLs to verify redaction. Never publish real PATs, raw environment data or corporate URLs in tests/evidence.
- Keep error notifications bounded across repeated refreshes and check disposal/recreation so delayed results neither strand a spinner nor notify a disposed view. Do not introduce delete/re-clone fallback, backup/restore, global CLI flags or unrelated telemetry changes in this fix.

## Verification and acceptance
