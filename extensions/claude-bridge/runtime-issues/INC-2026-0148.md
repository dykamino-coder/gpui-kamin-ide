# INC-2026-0148 — Open Windows project text links from chat

- **Status:** confirmed
- **Registration author:** @dvpetrochenko
- **Completion target:** a click on an explicit Windows project-file link opens the native text editor at the requested one-based line and column.
- **Private evidence:** not required. The synthetic location and fixture tests reproduce the renderer and host contracts.
- **Dependencies:** the target project belongs to the active chat. Hosted native acceptance is tracked in INC-2026-0144.
- **Acceptance:** automated renderer, host path resolution and event routing checks. Check the visible click, tab and cursor in the native Windows client before declaring UI acceptance.
- **Deployment observation owner:** integration maintainer.

## Symptom and scope

The shared chat renderer recognized external URLs. A Markdown link such as
`[Example](<C:/Fixture/sample file.ts:4:2>)` stayed as markup. In the native
Windows client, text-file navigation belongs to the active project's editor.
Only explicit drive paths and local drive file URLs participate. Browser
workspaces keep their container file routing.

## Verification

Check a synthetic file with spaces, Unicode and a cursor location. The native
editor uses the same file-read and tab-selection path as the project file tree.
Files outside the current project, missing files and directories must not open.
The debug acceptance probe can report the open editor and its one-based cursor
without exposing file contents.
