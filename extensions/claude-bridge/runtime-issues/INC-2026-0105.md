## Symptom

An application that embeds the workspace host
(`@kaminide/bridge-workspace-host` 6.3.170) with
`@kaminide/bridge-browser-client` reports three gaps.

- **B.** After the host restarts, or the session ends while the page is not
  connected, the client reconnects forever. It never reaches
  `authentication-required`, so the page does not ask the user to sign in.
- **A.** The page can list, rename and read files, but cannot create a folder.
- **C.** The preview renderer loads the remote from `/preview/remotes/<name>/`
  at the root of the page origin and opens the HMR socket there. A gateway
  that publishes HTTP and WebSocket routes under different prefixes cannot use
  it.

## Confirmed facts

B:

- For a `/bridge` upgrade whose cookie has no live session the host destroys
  the TCP socket before the handshake (`workspace/src/server.ts`, `refuse`).
- A browser reports a failed handshake as close code 1006 without a reason.
  The client treats only 4001, 4002 and 4008 as terminal
  (`browser-client/src/socket.ts`); every other close is retried with backoff.
- The built-in sign-in policy keeps sessions in memory unless persistence is
  configured, so every host restart produces this state.
- The host already closes open sockets with 4001 on logout and on failed
  revalidation; only the upgrade path differs.

A:

- The host serves `file-tree:list-dir`, `file-tree:rename` and
  `file-viewer:read`; there is no channel that creates a directory.

C:

- `createPreviewRenderer` builds the remote entry, chunk, asset and HMR socket
  addresses from the fixed path `/preview/remotes/<name>/` of the page origin;
  `createBridgeClient` already accepts `origin`, `fetch` and `createSocket`.

## Hypotheses

None; the three causes are read from the source.

## Expected outcome

- **B.** A same-origin `/bridge` upgrade without a live session is accepted
  and closed at once with code 4001. Before the close the host sends no frame,
  attaches no message handler and does not reach the backend. Other refusals
  (cross-origin, other path, limits, shutdown) stay as they are. A live
  session behaves as before. The client reaches `authentication-required` and
  opens no further socket.
- **A.** One call creates a folder inside the same path boundaries as rename
  and list-dir; an existing folder gives an explicit result; error codes
  follow rename. The client package has a typed method and documents the
  contract.
- **C.** One option of the preview renderer sets where remote files and the
  HMR socket are addressed, HTTP and WebSocket independently. Every preview
  address is built in one place. Without the option nothing changes.

`headless.cjs` of `kaminide-bridge-workspace-host-6.3.171.tgz` and the page
used the files of `kaminide-bridge-browser-client-6.3.171.tgz`; both archives
were downloaded from the GitHub Release.

| Item | Check | Result |
| --- | --- | --- |
| B, [#745](https://github.com/dykamino-coder/gpui-kamin-ide/pull/745) | restart the host while the page is signed in | pass: the client reports `authentication-required`, opens no new socket in 25 seconds, the session is unauthenticated, and a new sign-in connects again |
| A, [#748](https://github.com/dykamino-coder/gpui-kamin-ide/pull/748) | `client.files.createDirectory` | pass: a new folder gives `created: true` and appears in the listing, the same call again gives `created: false`, a missing parent is rejected with `ENOENT`; a path outside the root is accepted, as documented |
| C, [#749](https://github.com/dykamino-coder/gpui-kamin-ide/pull/749) | `base: { http, ws }`, modes auto and absolute, an HTTP prefix and a WebSocket prefix on another port | pass: the remote entry, the hot update files, the state and the unmount requests go under the HTTP base, the hot-reload socket under the WebSocket base, an update is applied in place, no request or socket goes to the origin root, no errors |

Limits of this run: the host code and the client files are the released ones,
but the npm dependencies of the host and the page scaffolding (browser driver,
bundler, the sample remote) were taken from a repository checkout; the
packages were not installed with `npm install`. Windows only. Not run: a
Linux host for A and B; for C a webpack remote, a `type: 'module'` remote, a
base on another site and CSS or image assets of a remote.
