# INC-2026-0140 — Restore the live terminal after the client accepts its session

- **Status:** confirmed
- **Registration author:** @dvpetrochenko
- **Completion target:** deliver the change in a paired release and verify it in the client.
- **Acceptance:** automated merge gate.
- **Private evidence:** not required. The synthetic checks below exercise the public contract.

## Symptom

Opening an existing chat could leave Console connecting until the next turn. The durable chat transcript remained visible.

## Cause and acceptance

On live reattach the server sent buffered terminal output before `session:created`. The host accepts output only on an authenticated connection. A two-client WebSocket test checks the exact replay bytes and their position after the handshake before the second client sends any user message. Cold startup creates a new terminal with its own output buffer. Field attribution and late mounting of a separate console panel are independent observations.
