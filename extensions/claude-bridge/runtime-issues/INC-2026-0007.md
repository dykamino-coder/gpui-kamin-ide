## Symptom

При переключении между sessions с одинаковым именем агента reader второй
session может показывать записи обеих sessions, хотя agent IDs различаются.
Заголовок и metadata относятся к текущей session, а canonical transcript
выбирается из общего name-based cache. Дефект подтверждён на synthetic данных;
случай смешения реальных пользовательских transcripts не заявлен.

## Confirmed facts

1. Host сохраняет `agentId` при доставке subagent entries:
   `extensions/claude-bridge/extension/src/main/ws/handle-server-message.ts:293`
   и `extensions/claude-bridge/extension/src/main/ws/connection-manager.ts:716`.
   Уникальность host ID поэтому сама по себе не устраняет downstream collision.
2. `extensions/claude-bridge/webview/src/hooks/useBridgeListeners.ts:487`
   проверяет arriving tab, но строка 492 выбирает
   `get(agentId) ?? get(agentName)` в глобальном map. Первый batch создаёт name
   alias на строке 509; batch другой session с новым ID попадает в старый alias
   и добавляется к тому же state на строке 512.
3. `extensions/claude-bridge/webview/src/signals/agents.ts:124` читает canonical
   entries по name/type; `agentEntriesWithLive` на строке 142 применяет tabId
   только к дополнительным live stubs. Shipping reader использует этот результат:
   `extensions/claude-bridge/webview/src/components/agent-tiles/AgentsToolPanel.tsx:131`.
4. Actual-source synthetic callback получил A-1, затем B-1 с разными agent IDs
   и одинаковым display name. Reader B вернул `[A-1, B-1]`; нового ID B в map
   не появилось. `clearAgentTabState` не удаляет canonical cache
   (`extensions/claude-bridge/webview/src/signals/agents.ts:84`), поэтому закрытие
   A не восстанавливает изоляцию.

## Hypotheses

Runtime frequency и Windows presentation ещё не измерены. Incoming active-tab
guard защищает текущую доставку, но не retained state после switch; UUID dedup
не помогает разным UUID. BR-27 исправляет lifecycle partition, а этот incident
касается identity transcript reader. Existing INC-2026-0002 не является
доказательством cross-session contamination: его исходная матрица относится
к одной session. Тот же name fallback требует проверки для двух teams и
повторного запуска агента в одной session.

## Expected outcome

Отдельный Change/Fix PR должен согласовать ingest, aliases и reader lookup по
session и стабильному agent ID; name/type fallback допускается только внутри
однозначного session namespace. История завершённых агентов должна оставаться
доступной без смешения с новым одноимённым запуском.

Automated fixtures: A→B→A с одинаковым name и разными IDs, поздний replay,
две teams с одноимёнными агентами, close A при открытой B. Reader никогда не
возвращает UUID другой session. Windows CEF gate повторяет эти переключения,
открытие/Back reader и закрытие соседнего tab; metadata и transcript должны
оставаться согласованными. Native UI приёмка в этом исследовании не выполнялась.
