## Symptom and confirmed source contract

A KaminIDE 1.0.75 / Bridge 6.3.152 capture shows five RUNNING agents in the
Agents view while Console visibly lists one child beside the parent. The
session has just auto-compacted. This is a presentation discrepancy, not a
process census or evidence of cross-session contamination.

At source baseline `6c3e5a6a`, `JsonlWatcher.rebuildSegmentIndex()` emits
`watching` with `segmentIndex` and no `replayComplete`. The extension forwards
that status. `useBridgeListeners` tests `!status.replayComplete` for replay
start, so an absent flag opens a new staging generation and removes the tab's
live flag. Subsequent agent events stay staged because this index-only update
has no matching replay completion. The last published RUNNING rows remain.

A disposable actual-source probe calls the real server-message dispatcher,
status listener, replay store and partition. Five synthetic agents followed by
four idle notifications produce Active 1 in the control. Inserting the live
index-only status produces Active 5 and four staged events; a later full replay
recovers Active 1. No native CLI, real hook or user transcript was executed.
The relevant source is unchanged between released 1.0.75 and 1.0.76.

## Expected result

Index/progress-only updates preserve the current replay generation and live
state. Explicit replay starts still stage all history and live arrivals;
exactly their matching completion publishes once. Cache/reveal must not
replay an incomplete status after an index update or leave a renderer staged.
Do not force every status to completed or discard genuine staged history.

Field observation after release: with two parent sessions and multiple children,
observe a natural compact with Agents visible/hidden, reveal, terminal events,
parent switches and reconnect. Use the linked checklist. This does not replace
BR-25/31's independent native delivery acceptance or establish field causality.

## Prepared implementation — 2026-10-19

The host distinguishes legacy bare watching replay starts from index/progress
metadata, normalizes genuine starts to explicit false and preserves the cached
replay lifecycle across metadata updates. The listener starts a generation only
on explicit false, so index/progress do not reset staging or cancel completion.
No server protocol upgrade is required; older server starts are normalized.

Four new host regressions and three actual-listener regressions failed on the
baseline and pass with this fix. Cases cover cached reveal state, an unfinished
replay, progress while completion is pending, four delivered idle events after
an index update, legacy start/one-shot compact handling and same-name parent
isolation. Full extension and webview suites, typecheck and production builds
are run for the Change/Fix PR; shipped artifacts are rebuilt. Native Windows
observation has not been run. Source acceptance follows the separate #381
decision; source acceptance was completed on 2026-10-20 below.
