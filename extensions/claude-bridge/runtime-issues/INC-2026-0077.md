## Symptom and confirmed facts

The owner reports that an agent sometimes receives a rejection while the user
has not pressed a button, and wants hook-triggered decisions visible in Chat.
This registration isolates one independently reproducible MCP reason defect;
it does not identify which permission/hook path produced the owner's episode.

At source `f819b57b8be6db54a00073e3f57fcf37561534a0`:

1. `extension/src/main/ws/mcp-call-pipeline.ts:checkToolPermission` returns false
   for a stored deny rule without publishing `permission-request`. It also
   reduces a pending decision callback to a boolean.
2. `handleMcpCall` reports every false result as `User denied permission`, so a
   policy decision is attributed to the user even without a displayed question.
3. `connection-manager.ts:disconnect` resolves pending permission callbacks with
   `deny`. The pipeline therefore uses the same user-denial reason for this
   automatic cancellation. Keeping the operation blocked is necessary; the
   misleading actor/reason, not fail-closed cancellation, is the defect.

Three disposable probes exercise the actual pipeline: policy deny with no
question, the callback used by teardown resolved without a click, and an ask
remaining pending before a response. The teardown probe calls the callback;
it does not execute ConnectionManager teardown or a real disconnection.
Thirty existing executor/relay/display tests also pass. These observations do
not attest a native CLI hook prompt, Chat buttons or Windows acceptance.

## Expected outcome and maintainer handoff

and transport failure wherever applicable. Preserve request/session ownership
and a stable single terminal outcome. Do not auto-allow, silently retry tools,
erase pending requests without an outcome or describe an automatic cancellation
as an explicit user action. A hook's intentional `deny` need not show an approval
dialog and must not become an overridable Ask.

late/duplicate response, no-input pending state and failed delivery. Reconcile
pending tool/UI state without executing an operation a second time. Do not
introduce an unrelated global timeout or broaden bypass permissions.
