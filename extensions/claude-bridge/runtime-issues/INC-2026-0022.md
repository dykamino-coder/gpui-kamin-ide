## Symptom

Accelerated CEF frame copying does not balance the owned device/context references
returned by GPUI. On device replacement, it can also submit a texture opened on
the previous device to the new context during the same call. These violate the
interop lifecycle contract; their contribution to the reported sleep/RDP failure
or observed memory use has not been established.

## Confirmed facts

Audited source: `a34ab4892058bcacc00de8d97ae951fb60551780`.
Short `web/` paths below are relative to `crates/shell/src/`.

- `vendor/gpui/src/platform/windows/directx_renderer.rs:359–369` returns
  `clone().into_raw()` for both device and context: each getter supplies an
  owned AddRef reference, forwarded through the window APIs.
- `web/shared_texture.rs:146–151` obtains fresh references on copy passes.
  DEVICE retains the new raw device pointer, but its swap discards the previous
  ownership without Release, even when the pointer value is unchanged. Initial
  storage at line 35 similarly has no retiring ownership path.
- `web/copy_frame.rs:70–71,134–135` wraps the references with `from_raw`, then
  converts them back to raw pointers without releasing them. The context has no
  retaining owner; the device storage loses each superseded ownership as above.
  Do not count these descriptions as two leaks of the same device reference.
  The popup path at `web/popup.rs:134–136` also obtains and discards both refs.
- `web/shared_texture.rs:122` clones the incoming texture before observing the
  device swap at 151. Clearing INCOMING/SLOTS/OWN at 154 and 261–269 does not
  invalidate that local owner. Line 158 passes the old incoming texture with
  the new device/context to `CopyResource` (`web/copy_frame.rs:127`).

Independent source review and a source-anchored deterministic ownership model
agree on these transitions. The model does not call Rust, COM or Windows.
[COM AddRef](https://learn.microsoft.com/en-us/windows/win32/api/unknwn/nf-unknwn-iunknown-addref)
and [Release](https://learn.microsoft.com/en-us/windows/win32/api/unknwn/nf-unknwn-iunknown-release)
define the required reference balance.

## Hypotheses

Retained device generations and invalid cross-device copies can obstruct recovery;
driver behavior, live-object counts and memory impact require measurement. An
AddRef is not a new allocation and does not imply linear byte growth per frame.
The getter-owned references contradict an earlier borrowed-pointer use-after-free
hypothesis. The accelerated path may be inactive when CEF starts under RDP in
software mode. GPUI atlas device references are replaced normally during reset.

## Expected outcome

Give the interop boundary explicit owning/borrowing semantics and a device
generation policy shared by normal and popup frames. Balance every acquired
reference, including early returns and replacement. Retire old caches and local
in-flight frames before copying with a new context; wait for or reopen a frame
for that generation through a controlled path.

Automated checks cover repeated same-device frames, early returns, popup copies,
device replacement and an old incoming frame already cloned before invalidation.
Assert ownership balance and matching source/destination/context generations.
A disposable Windows gate checks repeated accelerated-CEF device recreation,
D3D diagnostics/live objects, frame/input recovery and resource return to baseline;
also verify software fallback. No native runtime result or functional fix is
included. Keep INC-2026-0020 open until its field crash is independently attributed.
