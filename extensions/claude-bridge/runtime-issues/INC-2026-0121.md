- **Fix PR:** pending.

## Symptom

In a Bridge session the model asks for a 200 KB file, or runs a command with a
long output, and gets back a notice instead of the content:
`Output too large (236.3KB). Full output saved to: /home/bridge/.claude/projects/...`.
That path is inside the server container. The model's Read and Grep run on the
client machine, so they cannot open it, and the rest of the result is lost.
Native Claude Code does not lose it: Read refuses a whole-file read above
256 KB and asks for a range, and Bash keeps its full output in a file on the
same machine as Read.

## Confirmed facts

Runs with Claude CLI 2.1.322 and server image 6.3.180, client KaminIDE 1.0.103
on a profile copy:

- One live session: a whole-file Read of a 200 KB file came back as the
  `saved to` notice above (236.3 KB of numbered text). `seq 1 200000` came back
  as the same notice for 118.6 KB: the client had already cut the 1.29 MB output
  to its first 100 KB, so the end of the output was lost twice.
- The CLI moves an MCP result to that file when it is longer than 50,000
  characters (results of 49,000 characters stayed inline, 51,000 did not).
- `_meta["anthropic/maxResultSizeChars"]: 500000` on the tool **definition** in
  `tools/list` keeps such a result inline. The same key on the **result** does
  not; the server comment that relied on it, and on a 720 KB cap, was wrong.
- Grep cut by `head_limit` returned the first N lines with no marker. Native
  Grep appends `[Showing results with pagination = limit: N]`.

Source (main `e3682bf2`): `server/src/core/pty/mcp-http-handler.ts` (tools/list
and `truncateMcpResult`), `extension/src/main/mcp/tools/file-system.ts`
(`readFile`), `shell-foreground.ts` (100 KB per stream, rest dropped),
`grep-tool.ts` (head_limit paths).

## Bounded change

- `tools/list` declares `anthropic/maxResultSizeChars` = 500,000 on every tool;
  the server keeps truncating just below that same limit.
- Read refuses a whole-file read above 256 KB, and a range whose text is above
  256 KB, with a hint to use `offset`/`limit` or Grep.
- Bash and PowerShell return up to 100 KB per stream as is. Beyond that the
  whole stream goes to a file under the client's temp directory
  (`kamin-bridge-output`), and the result carries the first and last 40 KB and
  the path. Saved files are removed after 24 hours, or oldest first once all
  of them together exceed 1 GB, at extension start and before each new file;
  a file still being written is never removed.
- Grep appends the native pagination marker when `head_limit` cut the result.

## Acceptance

Automated: server test that every `tools/list` entry carries the key and keeps
its other `_meta`; extension tests for the Read limits, the saved output (read
back through the client Read), the directory bounds, and the Grep marker on
ripgrep and the fallback.

Live on the exact head: one session reads the 200 KB file inline, gets head,
tail and a client path from `seq 1 200000` and reads that path with Read, and
sees the Grep marker. Do not inspect or alter the container's authentication
volume or CLI authentication directory.
