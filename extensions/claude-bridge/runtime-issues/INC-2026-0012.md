## Symptom

Несколько одновременных запусков могут превысить настроенный global session
limit. Открытие архивной conversation через cold resume дополнительно обходит
per-user limit. Приоритет P2: штатная работа с несколькими sessions способна
создать больше PTY, proxy и watcher ресурсов, чем предусматривают защитные
лимиты сервера. Фактическая величина нагрузки не измерена.

## Confirmed facts

Source snapshot: `a34ab4892058bcacc00de8d97ae951fb60551780`. Все пути ниже
относительны `extensions/claude-bridge/`.

- `server/src/core/pty/session-ws.ts:140–149` проверяет per-user cap 10 только
  в `session:create` и до `await createSession`. Cold `session:resume` в
  строках 402–421 вызывает создание без этой проверки. Core считает только
  зарегистрированные running sessions (`session-core.ts:921–926`).
- Global проверка `sessions.size` находится в `session-core.ts:87–89`, до
  `await` snapshot lock, native import и streaming settings
  (строки 171, 179, 196). Регистрация новой session происходит в строке 399.
  Слоты для уже принятых, но ещё создаваемых sessions не резервируются.
- Обычный клиент выбирает `session:resume` для сохранённой conversation
  (`extension/src/main/ws/connection-manager.ts:425–437`). Tab manager допускает
  открытие нескольких архивных conversations. Background warm pool теперь
  загружает только данные и не подключает все tabs при старте; этот прежний
  сценарий не используется как доказательство дефекта.
- Actual-source synthetic harness с global cap 2 допустил четыре concurrent
  creates и четыре mocked PTY spawn. Следующий последовательный create был
  корректно отклонён. Отдельный actual-handler тест при per-user count 10
  отклонил create, но принял cold archive resume.
- Независимый cross-review усилил тест: подключил настоящий `sync/lock.ts` и
  одинаковый synthetic bearer hash для всех creates. Результат остался 4 при
  cap 2: snapshot lock начинается после admission check. Per-conversation
  resume lock сериализует только одну conversation, а не общий ресурсный бюджет.

## Hypotheses

Не измерены production burst size, RSS, PID/FD pressure и задержки startup.
Synthetic tests заменяют filesystem, PTY и proxy границы инертными stubs;
настоящие CLI процессы и Linux load test не запускались.

Global cap работает для последующих последовательных requests. Live reattach
не создаёт новую session и намеренно должен оставаться доступным при заполненной
квоте. Нельзя описывать результат как полное отсутствие ограничений или
неконтролируемое подключение всех сохранённых tabs при каждом запуске.

## Expected outcome

Отдельный Change/Fix PR должен объединить cold create/cold resume admission,
резервировать global и per-token capacity до первого `await`, освобождать её
при ошибке/cancellation и ровно один раз переводить reservation в live session.
Live reattach не должен расходовать дополнительный слот. Эта карточка
подтверждает source contract; functional fix ещё не сделан.

Automated gate: concurrent creates разных conversations/пользователей около
лимитов, cold resume при 10 sessions, ошибки каждого startup этапа, отменённый
startup, replacement при restart, reattach живой session при полной квоте.
Сохранить regression case с настоящим snapshot lock. Disposable Linux gate
должен сверить число реально запущенных PTY и возвращение capacity после
ошибки; production mounts и authenticated provider для admission proof не нужны.

BR-05 содержит недостающий max-sessions UI gate, но не implementation этого
admission defect. Связать проверки без закрытия BR-05 одним unit test.

## Prepared fix and verification (2026-10-09)

Branch `fix/inc-2026-0012-session-admission`. Shared core reserves global and
per-token capacity synchronously before any startup await. Conversion to live
is synchronous with map insertion; release is idempotent on success, failure
and cancellation. Cold create/resume share the 10-session token cap. A failed
registered startup receives normal bounded teardown. Live reattach consumes
no slot; replacement removes the stopped old session before new admission.
Optional AbortSignal checks block a cancelled startup before PTY spawn.
WS startup ownership/connection cancellation wiring remains INC-0013.

Two initial regression tests failed on current-main behavior: four concurrent
starts passed cap 2 while the real snapshot lock blocked them; cold resume
passed the token cap. An early test mock allowed a real native import in one
concurrent path; that harness was corrected before counted verification. A
single cached lazy native import keeps the startup boundary consistent.

PASS exact commands: `npm --prefix extensions/claude-bridge/server ci`,
`npm --prefix extensions/claude-bridge/server run typecheck`,
`npm --prefix extensions/claude-bridge/server run lint`,
`npm --prefix extensions/claude-bridge/server test` (35 files; 189 passed,
1 opt-in Linux PTY test skipped on Windows). Final changed-file Prettier
check in server cwd: `node node_modules/prettier/bin/prettier.cjs --check
src/core/pty/session-admission.ts src/core/pty/session-admission.test.ts
src/core/pty/session-core.ts src/core/pty/session-ws.ts`. `git diff --check`
passed. Webview/extension artifacts, Rust/root checks N/A: unchanged.

Disposable Linux gate PASS in a copied isolated server under WSL Ubuntu,
Node 22.18.0/npm 11.5.2: `BRIDGE_PTY_ACCEPTANCE=1 npm test --
session-admission.test.ts` (12/12). Real node-pty launched only two inert

acceptance. BR-05 Windows max-sessions UI gate is unrun and remains separate.
Card remains open for maintainer review/acceptance.
