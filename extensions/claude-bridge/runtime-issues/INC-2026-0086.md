## Symptom

In KaminIDE 1.0.84, the terminal reported that the main response was complete with a background MCP task still running. The chat continued to show its busy state and two new messages remained queued.

## Confirmed facts

A working MCP task keeps its owner from being reaped. The chat's busy state comes from readiness, main activity and MCP connection initialization. The server CLI controller can report busy when its CLI mod still has a main turn ID even after receiving a main OSC completion. A synthetic replay reproduces this signal disagreement. The historical signal sequence is unavailable.

## Expected outcome

An idle main prompt can receive chat messages while background work remains live. A foreground turn and an actual prompt that awaits a user decision retain their existing protections. Reconnection preserves the current state and queued input is neither dropped nor duplicated.
