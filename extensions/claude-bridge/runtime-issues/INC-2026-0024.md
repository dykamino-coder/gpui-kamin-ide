## Symptom

The native `cache/diag.log` can grow throughout a long IDE session despite its
5 MiB rotation constant, including while all measured activity is zero. The
supplied file reached approximately 184 MB. Restart can then truncate the whole
file instead of retaining a bounded recent diagnostic history.

## Confirmed facts

Audited source: `a34ab4892058bcacc00de8d97ae951fb60551780`.
Anchors refer to `crates/shell/src/web/diag.rs`.

- `emit_line` at 205–228 compares file length against `ROTATE_BYTES` only inside
  the static FILE initializer. That check executes on the first write per
  process. Later writes at 229–233 never check size or rotate the open file.
- `report` at 126–188 rate-limits reports to an elapsed interval of at least
  one second but emits its long metrics row unconditionally. The header's
  claim that logging occurs only after activity does not match that branch.
- Supplied evidence has 245,091 metric rows; 169,398 have every activity counter
  zero, excluding the persisted tree-row state. No runtime size cap stopped the
  growth. These are historical counters, not evidence of equivalent elapsed
  seconds or measured CPU consumption.
- The boot line supplies version only; periodic rows have no timestamp, PID or
  elapsed-interval field. This limited correlation of pre/post-termination
  samples with the timestamped crash log in INC-2026-0020.
- BR-01/BR-30 concern the separate Node `incident.log` writer and its atomic
  rotation. Their completed tests do not exercise this native FILE lifecycle.

Two independent source reviews check the one-time size test and its caller.
No product writer was executed on Windows. The raw log and its checksum remain
private. This defect is not an established cause of the CEF crash, GPU load or
process memory use.

## Expected outcome

Enforce a bounded total diagnostic history during writes in one long-running
process, with complete records and bounded backup generations. Preserve useful
pre-crash evidence across restart instead of discarding the entire oversized
history. Suppress repeated idle rows or emit a bounded low-frequency heartbeat.
Keep the independent housekeeping timer: it also drives browser sleep/reap and
recovery. Zero published counters do not prove that every process is idle.
Include privacy-safe timestamps, process/run identity and actual sample interval
so retained metrics can be correlated without assuming one line equals one second.

Tests must cross the size limit without recreating the writer, exercise idle and
active periods, restart, UTF-8 record boundaries and write failures, and verify
the total retained-byte bound. Validate Windows file-handle rotation behavior.
Keep this task separate from CEF crash attribution and existing Node incident-log
acceptance. No product change or release is included in this Diagnostic PR.

## Implementation candidate (2026-10-09)

`web/diag_log.rs` checks the next complete record against 5 MiB on every append,
closes each handle before rotation, and retains `diag.log.1` and `.2` (15 MiB
maximum across the three generations). A legacy oversized file is read only at
its bounded tail and trimmed at newline boundaries, retaining recent complete
UTF-8 records rather than discarding the whole file on restart. Rotation/open
errors stop that append and remain retryable; a partial write is rolled back to
the prior length when the filesystem permits it. The writer assumes the existing
single-shell-process contract; it does not introduce cross-process locking.

The report clock retains the independent housekeeping pump. Active intervals
still emit immediately; idle summaries emit at most once per minute. Tree-row
state alone is not activity. Records carry UTC epoch milliseconds, PID, a run
start identifier and monotonic elapsed milliseconds; summaries name the actual
sample interval. This does not establish the cause of INC-2026-0020 or a CPU gain.

Windows standalone tests of the actual writer/clock modules: 9/9 passed,
including one writer crossing the production 5 MiB limit repeatedly, UTF-8,
exact boundary, restart/legacy tail, invalid record, open/rotation failures,
and an exclusive Windows file handle followed by retry after unlock. The
standalone harness compiles the repository modules without GUI/CEF dependencies;
it is not a replacement for full crate compilation. Full Rust checks and PR CI
are tracked in the fix PR; no unrun check is claimed here. No additional private
runtime evidence was collected: fixtures are synthetic temporary files.
