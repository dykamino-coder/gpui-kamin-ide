## Symptom

The release `engine_bench` dies with `STATUS_STACK_OVERFLOW` on a document of 1026 nested `<div style='float:left'>` elements:

```
<!doctype html><div style='float:left'><div style='float:left'>… (1026 levels) …</div></div>
```

Command: `engine_bench.exe <page> --viewport 800x600 --runs 100 --mode both --json --snapshot <output>`.

## Confirmed facts

- Reproduced on exact `origin/main` builds `94e72fb2`, `28dea526` and on candidate branches whose float code is unchanged, so it is not caused by any open branch.
- The main stack reserve is unchanged at 8,388,608 bytes. The release profile uses `opt-level = 3`, fat LTO, `codegen-units = 1` and `panic = "abort"`.
- Block, inline, grid, math, table and multicol documents of the same depth complete in the same release build on the same stack.
- The documented depth contract comes from [#430](https://github.com/dykamino-coder/gpui-kamin-ide/pull/430) (Gecko-depth documents on an 8 MiB stack).

## Hypotheses

- Each nesting level enters the float host path (band flow) recursively, and its per-level frames on some phase are larger than for block flow. Which phase overflows is not measured yet.
- Nested floats may re-enter intrinsic sizing per level, so the recursion is deeper than the DOM depth. This is not verified.

## Expected outcome

- Find the phase and the recurring frames that overflow, and fix the cost on that path (smaller frames, iteration instead of recursion, or work moved out of the recursion).
- Raising the stack size or capping float depth silently is not acceptable.

## Missing evidence and blockers

- The overflowing phase and per-level frame sizes in the release build. Owner: maintainer.
- Whether the debug and agent profiles overflow at a smaller depth. Owner: maintainer.

`crates/html/src/depth_tests/special.rs` already generates the nested float
fixture and has an ignored `special_path_probe` parameterized by

rewrite, but retain the release `engine_bench` render as the original gate:
the test context is not evidence of completed DirectX rendering.

The separate 7.5 MiB float test in `depth_tests/limit.rs` uses a 2,053-level
document that already reports `TraversalKind::BoxBuild` degradation. Its
success would measure stack headroom on that bounded path, not prove the
1,026-level undegraded release case. Record profile, stack reserve, phase and
degradation state together after the shared slot is released. No current
overflow or accepted fix is inferred from the existence of either test.
