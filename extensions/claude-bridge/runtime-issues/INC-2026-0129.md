## Symptom and evidence boundary

The operator reports Codex 0.170.0 interactive startup exiting in a Debian
slim container because the daemon startup path invokes the absent `ps` utility.
The same operator reports successful TUI inference with `--no-daemon`.
Those runtime observations were supplied by the operator, not rerun by the
maintainer on macOS.

## Confirmed source facts

Baseline `2212d6e14d701b3184a200cd742413667175ad08` launches Interactive/Usage
with no flags and Resume with `resume --last`. The runtime image pins Codex
0.170.0 and does not install procps. Bridge already owns the terminal process
and exclusively leases its shared CODEX_HOME until the process exit callback.

## Resolution and limits

Pass the global `--no-daemon` flag before the Resume subcommand as well as for
Interactive/Usage. This avoids a separate background account writer rather
than adding a daemon dependency to the image. `login status` remains a
read-only invocation; sign-in/sign-out stay in the shared account API.

No Docker, Windows runtime, corporate CA, real account or real model inference
was exercised locally. The corporate deployment observation remains open;
this card does not claim the separate KaminIDE app-server symptom fixed.
