## Symptom

After `/clear` followed by `/resume <session id>` the chat stays almost
empty: it shows only the local command output row. The history of the resumed
session appears only after the next prompt is sent.

## Environment and versions

- KaminIDE 1.0.92 on Windows 11 (a copy of the owner profile), Bridge server
  image 6.3.169 in the acceptance container, Claude Code CLI 2.1.322, model
  `claude-opus-5-5`. Not re-run on 1.0.93 / 6.3.170.
- The chat was driven through CDP (`KAMIN_CEF_CDP`) without taking over the
  screen. The release exe has no `kamin-probe`; whether release acceptance
  should have such a tool is an open acceptance-tooling question, not a defect.
## Reproduction steps

1. Open a Claude Bridge chat session and run two or three turns. Note its
   session id.
2. Send `/clear`. The chat becomes empty.
3. Send `/resume <id from step 1>`.
4. Wait at least 30 seconds without sending anything and read the chat.

Observed: the chat shows one "SYSTEM (LOCAL_COMMAND)" row with an empty
`<local-command-stdout>` element and nothing else (about 280 characters of
page text including the footer). The state was the same about 15 and 30
seconds after the command. On the server the transcript file of the resumed
session exists and is unchanged since before the command.

5. Send any prompt.

Observed: within the time of the answer the chat shows the full history of the
resumed session followed by the new turn.

## Confirmed facts

- Seen once with the timings above. In an earlier `/resume` of the same run
  the next prompt was sent 3 seconds after the command, so the delay could not
  be seen there.
- The CLI did resume: the turn of step 5 was written to the transcript of the
  resumed session.

## Hypotheses

- The chat follows the transcript file that received the latest write; a
  resume without a new row writes nothing to the resumed file, so the view
  does not switch. Not checked in source.

## Expected outcome

The history of the resumed session is visible as soon as `/resume`
completes, without sending a prompt.

## Missing evidence and blockers

- The same check on Linux and in the browser Bridge.
- Behaviour of `/resume` without a preceding `/clear`.

## Source-trace follow-up — 2026-11-13 (cxstats)

Source baseline: `32109f31cd9a4940726d216e5deae03aef1220d5`, compared with
`origin/main` `848ac4618d81dad519958060fccb7200489bc5d9`. No CLI session or
runtime reproduction was started for this follow-up.

The candidate identity boundary is narrower than file discovery:

1. `server/src/core/hooks/types.ts::HookInputPayload` declares `session_id`
   and optional `transcript_path`. This is a Bridge type declaration, not
   evidence that CLI 2.1.322 emits a usable identity on every inline resume.
2. `hooks/routes.ts` routes the hook to its live PTY and invokes
   `applyDeterministicStatus`. In `bridge-status-hooks.ts`, `SessionStart`
   changes readiness/activity only. It does not adopt those identity fields.
   The function also returns early when CLI control is authoritative. Any
   verified transcript identity handoff must remain independent of that
   activity-precedence decision, including while the client is detached.
3. `pty/jsonl-watcher.ts::switchToFile` is currently a private compaction path.
   Its conversation-id callback in `session-jsonl-wiring.ts` records every
   changed id as an old-to-new compact link. Reusing that callback unchanged
   for an explicit resume could incorrectly make the old conversation resolve
   to an unrelated resumed one. A resume transition needs its own reason and
   must not be persisted as auto-compaction.
4. `readInitialContent` already cancels the old replay generation, resets
   counters and guards asynchronous delivery against a stale generation.
   `replayAll` replays the selected file; it cannot discover a different one.
   Preserve these properties when adding a verified identity transition.

**Next artifact:** server executor pairs the pinned CLI's actual resume hook
with the PTY identity and selected path, without a model turn. Then a regression
must cover an older unchanged transcript, unrelated newer files, native status
precedence, stale replay cancellation, and absence of a false compact link.
Startup `--resume`, compaction tests and the hook payload interface alone do
not satisfy that gate. The incident and its live confirmation gate remain open.
