# INC-2026-0128 — Deleted sessions keep their file editors in memory

- **Status:** verify. Cause found in the shell source; the fix is in the same Change/Fix PR (see **Fix PR**).
- **Registration author:** `kacc30`, KaminIDE executor, lead-directed (2026-11-24). Found while checking the memory of the 1.0.126 release candidate.
- **Completion target:** creating a session, opening files in it and deleting it, repeated, keeps the main process memory flat.
- **Diagnostic PR:** none; registered together with the fix in [#1187](https://github.com/dykamino-coder/gpui-kamin-ide/pull/1187) (cause known, bounded fix).
- **Fix PR:** [#1187](https://github.com/dykamino-coder/gpui-kamin-ide/pull/1187), which also registers this card.
- **Next step:** maintainer review of the fix PR; after release, one run of the acceptance below on the published build. Owner: KaminIDE executor.
- **Private evidence:** not required. The measurements use synthetic two-file projects and a fresh profile; no user data.
- **Dependencies:** none.
- **Acceptance:** the shell unit tests of the stash rule, plus a Windows runtime run: 30 rounds of "new session in a folder, open two files, delete the session" in one process; the main process private memory from round 10 to round 30 stays within the run-to-run spread.
- **Acceptance rationale:** the rule (which stash entries may stay) is pure and unit-tested; whether dropping them releases the memory only shows in the running application.
- **Deployment observation owner:** the executor of the fix.

## Symptom

Each round of "new session in a folder, open two small files, delete the session" left about 7 MB more private memory in the KaminIDE main process (1.0.126, 12 rounds: 256 → 339 MB, one session alive at any time). The same growth appears on 1.0.125.

## Confirmed facts

- File tabs are bound to a session. When the active session changes, the shell moves the old session's tabs (each with a code editor and a minimap editor) into `editor_tabs_stash`, and its Web URL into `browser_url_stash`, keyed by the session id (`crates/shell/src/state/frame_ctx.rs`).
- An entry leaves the stash only when its session becomes active again. A deleted session never does, so its editors stayed until exit.
- Bisecting the round by steps: palette, quick open, tooltip, theme switch, layout popover, idle and repeated file opens in one session were flat; growth needed a new session with open files.
- Closing a session tab (`kamin:sessions:deactivate`) keeps the session in the list, and reopening it brings its tabs back from the stash. Closed sessions therefore keep their stash by design; that memory is bounded by the sessions in the list and is not changed here.

## Hypotheses

- How much of the about 7 MB per two-file session is the editors themselves (text layout and highlight caches of two editors and two minimaps) was not split further.

## Expected outcome

A stash entry exists only for a session in the latest host snapshot: the tabs of a deleted session are dropped when it stops being active, and an inactive session deleted later loses its entry on the next snapshot. Before the first snapshot nothing is dropped.

## Missing evidence and blockers

None for the fix. The runtime acceptance on a published build is the remaining gate.
