## Source-trace follow-up — 2026-11-13 (cxstats)

Source baseline: `32109f31cd9a4940726d216e5deae03aef1220d5`, compared with
`origin/main` `848ac4618d81dad519958060fccb7200489bc5d9`. Source trace only;
no fault-injection server, build or runtime experiment was started.

`server/src/core/pty/session-error.ts::sendSessionError` marks `session:error`
fatal and closes the current socket. In the extension,
`ws/handle-server-message.ts` passes its error text to
`ConnectionManager::terminateSessionWithError`, which closes the socket and
uses the ordinary reconnect path. Fatal for this socket is therefore not a
classification of the underlying cause as permanently non-retryable.
`scheduleReconnect` backs off to 30 seconds and stops for intentional
disconnect or `resumeParked`; the separate resume-not-found path enters an
identity hold. Do not assume all these terminal paths share one retry policy.

**Next artifact:** connection executor distinguishes a generic `session:error`,
explicit resume-not-found, and a repeated fast resumed-process exit in the
existing two-tab fixture. Record the original reason, socket generation,
park/identity-hold state and retry owner, plus tab-close cancellation. Preserve
the original server reason before the UI replaces it with the next retry
countdown. This narrows fault injection without attributing the historical
loop or proposing a blanket reconnect disablement.
