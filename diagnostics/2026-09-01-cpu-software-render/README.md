# Разбор жора CPU, 2026-09-01 (KaminIDE 1.0.53)

Логи, снятые с прод-машины, и разбор по ним. Это evidence под две правки,
которые ушли в `main` 2026-09-02 **без прогона `cargo` — тулчейна на машине
сборки не было**, поэтому проверять их придётся по этим же логам:

* **#19** `perf/software-render-throttle` — троттлинг перерисовки и глушение
  бесконечных анимаций без GPU. Разбор и способ проверки:
  [Fix_software_render_throttle.md](Fix_software_render_throttle.md)
* **#21** `fix/webview-hidden-state` — `was_hidden` для скрытых вью и канал
  `viewState` для exthost. Разбор и способ проверки:
  [Fix_webview_hidden_state.md](Fix_webview_hidden_state.md)

В обоих файлах есть раздел «куда смотреть в новых логах»: что должно
измениться в `diag.log` и в `cpu.txt` после правок, и чего ожидать не надо.

## Коротко, что нашли

Машина без видеокарты (облачная VM в RDP-сессии): gpui рисует через **WARP**,
программный растеризатор D3D. Каждый кадр окна растеризует процессор на всех
ядрах, причём **мимо счётчиков gpui** — `Present` только ставит команды в очередь.

Один CSS-спиннер 19×19 в шапке чата держал 120–139 кадров CEF в секунду,
22–27 кадров окна и стоил **6,8 ядра из 8**. Он же снятый — 0,28 ядра и ноль
кадров. Встроенная диагностика объясняла из этих 6,8 только ~0,8.

## С чего начинать чтение

1. `cpu.txt` — кто ест: главный процесс шелла (136,84 CPU-сек за 20 с), а не
   Chromium-renderer'ы и не Node.
2. `modules.txt` — почему: загружен `d3d10warp.dll`, аппаратных драйверов нет.
3. `cache-diag.log` — посекундные строки `[cef] за секунду` и `[sw]`; разбор
   полей и посчитанные срезы — в `Fix_software_render_throttle.md`, раздел 5.
4. `anim.txt` — зонд изнутри страниц: единственная работающая анимация и
   `visibilityState=visible` у панели, которой нет на экране.

## Что здесь ещё лежит непрочитанным

Разбор закрыл не всё. В `cache-diag.log` остаются два следа, по которым правок
пока нет:

* **`переиграно вью 0`** — во всех 6739 замерах, максимум ноль. Кэш элементов
  gpui не переигрывает ничего, каждый кадр окна собирается с нуля (раскладка
  ~300 мс/с, taffy ~230 мс/с). На машине с видеокартой это станет главной
  статьёй расходов.
* **`[sw] ... dirty в среднем 2–4%`** при полной копии кадра — software-путь
  копирует весь буфер, хотя меняется малая часть.

А в `cache-crash.log` — серия `TS_PROCESS_CRASHED / STATUS_BREAKPOINT` по четырём
вью сразу; в этом разборе она не исследовалась.
