## 1. Что было сломано

Offscreen-браузер CEF рисует, пока ему не сказали обратное. В коде был ровно один
вызов `was_hidden(0)` — при создании браузера (`browsers.rs`, `on_after_created`).
Вызова `was_hidden(1)` **не было нигде**. То есть Chromium считал каждое вью
видимым вечно и, соответственно:

* рисовал его на полной частоте, даже когда панель ушла с экрана;
* не тротлил его таймеры, `requestAnimationFrame` и CSS-анимации (Chromium делает
  это только для страниц, которые считает скрытыми).

Тот же пробел оставлял неотправленным канал `kamin:webview:viewState`. exthost его
**принимал**, но никто не слал — кроме момента выгрузки вью. Последствия на стороне
Node: посты копились в очередь невидимого iframe, а его `resolvedHtml` (~1,6 МБ на
вью) держался до dispose, которого после reap не бывает. Это пункт **0.2**
мастер-плана (`plan/102-master-plan.md`).

Дороже всего пробел обходился чату: `claudeBridgeChat` состоит в списке `NEVER_REAP`,
то есть его renderer не выгружается никогда — скрытым он жил вечно.

## 2. Доказательства в логах этой папки

Два независимых свидетельства, с разных сторон границы процесса.

### 2.1. Со стороны шелла — `cache-diag.log`

Разбивка лога по 300-секундным блокам показала участок, где Chromium исправно слал
кадры, а окно не рисовалось вообще:

```
блок  300- 600 c: кадров 56/с, сцена 0 мс/с, кадров окна 0
```

`кадров окна 0` при `кадров 56/с` означает буквально: вью работают вхолостую —
их кадры никто не показывает. Это и есть незакрытый `was_hidden`.

Для сравнения, соседние блоки того же лога:

```
блок 3600-4200 c: кадров  0/с, сцена  2 мс/с, кадров окна 0,3   ← всё тихо, вью спят «сами»
блок 4500-4653 c: кадров124/с, сцена597 мс/с, кадров окна 25    ← активная работа, окно рисует
```

### 2.2. Со стороны страницы — `anim.txt`

Зонд выполнялся внутри самих вью через probe-канал (`wvjs`), вывод собран из
`chrome_debug.log`:

```
[anim] claudeBridgeChat        vis=visible hidden=false n=1 :: _spinner_1yjoq_35/_spin_1yjoq_35
[anim] claudeBridgeConsoleView vis=visible hidden=false n=0 ::
```

`claudeBridgeConsoleView` отвечает `vis=visible, hidden=false` — **хотя этой панели
на экране не было**. Страница не знала, что её скрыли, потому что ей об этом не
сказали.

Там же видно, что `requestAnimationFrame` тикает 60 раз в секунду в обоих вью
независимо от того, видны они или нет:

```
[raf2] claudeBridgeChat        rafPerSec=60 vis=visible anims=0
[raf2] claudeBridgeConsoleView rafPerSec=60 vis=visible anims=0
```

## 3. Что изменено и почему именно так

Учёт видимости вынесен из `web/mod.rs` в новый модуль `web/visibility.rs` и теперь
управляет обоими сигналами — флагом Chromium и каналом exthost.

### 3.1. Пробуждение мгновенное, усыпление — через тик

Состав видимых вью пересчитывается на **каждое событие** (`RootView::sync_panels`)
и на отдельных кадрах «дребезжит»: тул может ещё не доехать в реестр после смены
сессии или рестарта ext-host.

* **Усыпление отложено** на секундный тик насоса (`visibility::sleep_hidden`,
  зовётся из `pump.rs` рядом с `reap_hidden`). Мгновенное усыпление на дребезге
  останавливало бы рендер живой панели. Секунда лишнего рисования не стоит ничего.
* **Пробуждение немедленное**, прямо в `mark_visible`. Здесь симметрия вредна:
  опоздать с пробуждением — значит показать пользователю застывшую картинку.

### 3.2. Оба множества под одним замком

Первая версия держала «видимые» и «усыплённые» в раздельных мьютексах. При вычитке
нашлась гонка:

1. тик насоса читает «вью скрыто»;
2. UI-поток между этим и записью показывает вью — будить нечего, усыпить ещё не успели;
3. тик усыпляет уже видимое вью;
4. дальше пробуждения не будет: вью в составе видимых, менять нечего.

Итог был бы «панель застыла навсегда до следующего скрытия». Поэтому оба множества
живут в одной структуре под одним замком, и решение о переходе принимается атомарно.

### 3.3. Разбуженному мало снять флаг

На статичной странице Chromium сам кадра не шлёт — панель сохранила бы картинку,
застывшую в момент скрытия. Поэтому показ сопровождается `was_resized` +
`invalidate` (тем же дуплетом, что и `browsers::nudge`); заодно размер панели мог
поменяться, пока вью спало.

### 3.4. Про замок во время вызова CEF

`wake` намеренно вызывается **с захваченным** замком. `on_browser` не ходит в CEF
синхронно — он ставит задачу через `cef::post_task` в очередь потока CEF. Отпусти
замок раньше, и «усыпить»/«разбудить» могли бы встать в эту очередь в обратном
порядке.

### 3.5. При создании браузера говорим факт

`on_after_created` теперь передаёт `visibility::hidden_flag(id)` вместо жёсткого
нуля: создание браузера асинхронное, и пока оно шло, вью могло уйти с экрана.

## 4. Куда смотреть в НОВЫХ логах, чтобы проверить

Файл: `%LOCALAPPDATA%\kaminide-gpui-dev\cache\diag.log`, строки `[cef] за секунду`.

**Проверка 1. Скрытое вью замолкает.**
Открыть чат, переключиться на другую панель, подождать пару секунд. Поле `кадров`
должно упасть к нулю. Сейчас (до правки) скрытый чат продолжает слать кадры — это
видно как ненулевое `кадров` при нулевом или почти нулевом `кадров окна`.

**Проверка 2. Возврат не оставляет застывшей картинки.**
Вернуться на чат. Панель обязана показать актуальное содержимое сразу, не дожидаясь
следующего изменения страницы. Это главный риск правки — смотреть глазами.

**Проверка 3. Дребезг не гасит живую панель.**
Быстро переключаться между тулами туда-обратно. Активная панель должна продолжать
рисовать. В логе — `кадров` не должно проваливаться в ноль, пока панель видна.

**Проверка 4. Неполный реестр.**
Сменить сессию, перезапустить ext-host. Панели не должны «пропадать» — за это
отвечает ветка `mark_visible_union`.

**Проверка 5. Со стороны страницы.**
Тем же зондом, что дал `anim.txt`, спросить скрытую панель. После правки
ожидается `vis=hidden` (или `hidden=true`) вместо прежнего `vis=visible`:

```powershell
$c = New-Object Net.Sockets.TcpClient('127.0.0.1',9333)
$s = $c.GetStream(); $w = New-Object IO.StreamWriter($s); $w.AutoFlush=$true
$r = New-Object IO.StreamReader($s)
$js = "console.log('[vis] ' + document.visibilityState + ' hidden=' + document.hidden)"
$req = @{ cmd='wvjs'; id='claudeBridgeConsoleView'; js=$js } | ConvertTo-Json -Compress
$w.WriteLine($req); $r.ReadLine() | Out-Null
$c.Close()
Start-Sleep -Seconds 2
Select-String -Path "$env:LOCALAPPDATA\kaminide-gpui-dev\cache\cef\chrome_debug.log" -Pattern '\[vis\]' | Select-Object -Last 5
```

Панель при этом должна быть **закрыта** (не активна) — иначе ответ `visible`
правильный.

**Проверка 6. Память exthost.**
Косвенно: после долгого щёлканья по панелям рабочий набор `kaminhost.exe` не должен
монотонно расти. Это тот самый `resolvedHtml`, который раньше не освобождался.

## 5. Как откатить

Отдельного переключателя у этой правки нет — она чинит инвариант, а не добавляет
режим. Откат = не мержить PR #21 либо вернуть коммит `da07d83`.

Если после мержа обнаружится «панель застывает», самое вероятное место —
`visibility::wake` (пробуждение не доехало) либо `set_hidden` (дуплет
`was_resized` + `invalidate` не сработал на конкретном вью). Быстрый обходной путь
до разбора: закрыть и открыть панель заново — вью пересоздастся и получит
актуальное состояние в `on_after_created`.

## 8. Что из разбора осталось несделанным

1. **`переиграно вью 0`** — кэш элементов gpui не переигрывает ни одного вью, каждый
   кадр окна собирается с нуля (раскладка ~300 мс/с, taffy ~230 мс/с). На машине с
   видеокартой это станет главной статьёй расходов.
2. **Безусловный `repaint_requested()`** на каждый кадр вью (`render_handler.rs`) —
   без проверок «вью видимо» и «картинка изменилась». После этой правки стало менее
   острым: скрытые вью замолчат сами.
3. **Копия всего кадра при `dirty` 2–4%** в software-пути (`render_handler.rs`).
   После троттлинга из PR #19 выигрыш падает примерно до 0,02 ядра.
4. **PTY шлёт событие на каждые 8 КБ вывода** без коалесценции, и на каждое событие
   безусловно вызывается `sync_panels`. Эффект не измерен — в снятых логах терминал
   не использовался.
5. **Node-поллинг**: `TAIL_POLL_MS = 200` на сессию и полный ре-парс JSONL в
   `replayAll()` (фаза 2 мастер-плана). На этой машине Node был на нуле.
6. **Probe-канал открыт в дистрибутиве** — `default = ["probe"]`, TCP 9333 без
   токена, принимает `click`, `type`, `wvjs`. Мы им пользовались для этой
   диагностики, но решение (убрать из релиза / потребовать токен / оставить
   осознанно) — продуктовое.
