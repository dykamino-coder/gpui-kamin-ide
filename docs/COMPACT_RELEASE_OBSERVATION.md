# Проверка compact и Agents после выкладки

Владелец проверки — оператор окружения развёртывания. Мейнтейнер публикует
проверенные artifacts, но не имеет доступа к этому серверу. Эта проверка
относится к INC-2026-0067/0068 и не закрывает BR-25/31 либо INC-0037.

## Что уже подтверждено и что предстоит проверить

Автоматическая приёмка проверяет host/listener replay state и server file-I/O
recovery на реальных обработчиках с искусственными данными. Она не доказывает
причину старого screenshot, CEF delivery/paint или исчезновение field симптома.
Проверенная поставка: KaminIDE 1.0.77 / Bridge 6.3.154,
[release](https://github.com/dykamino-coder/gpui-kamin-ide/releases/tag/kaminide-v1.0.77).
Точные accepted PR, source и delivery proof записаны в обеих карточках.

Проверить после обычной выкладки обоих компонентов по
[deployment runbook](../extensions/claude-bridge/server/DEPLOYMENT.md).
Поставка содержит принятые #377 и #378. Записать client/server versions,
source revision или image digest и интервал UTC. Старый клиент не содержит
исправления host/webview #377.
Не менять tokens, не удалять volumes, не перезапускать сервис только ради
наблюдения и не запускать неизвестный cleanup hook на живом транскрипте.

## Сценарии

1. В отдельной сессии без production data запустить несколько детей и дать
   части из них завершиться. При доставленных idle/terminal событиях Active
   и Completed должны согласованно отражать состояние; проверить также новую
   работу того же ребёнка после acknowledged follow-up.
2. При естественном compact проверить новую Current-вкладку/summary и
   продолжение сообщений без перезапуска. Повторить наблюдение с открытой и
   скрытой Agents panel, затем открыть её. Панель должна показывать актуальное
   состояние без движения мыши или повторного toggle.
3. Переключить две parent sessions (допустимы одноимённые дети), открыть старый
   compact segment, вернуться в Current и переподключиться. История и статусы
   должны принадлежать своему parent и продолжать обновляться.

Это наблюдение не требует искусственно повреждать JSONL. Shrink/replacement
проверены disposable filesystem tests; если реальная запись переписывается,
сохранить естественно возникшее событие, не повторять неизвестный hook.

## Результат и повторное открытие

Записать для каждого выполненного сценария ожидаемое и фактическое поведение.
Невыполненный сценарий оставить `not run`, а не `passed`. Успешная публикация
или отсутствие случая compact сами по себе не считаются успешной проверкой.

При повторении сохранить версии, UTC, затронутый parent, bounded status/lifecycle
metadata и screenshot через private intake; не помещать payloads в public issue.
Для tail recovery полезны file identity, размер и consumed offset до/после,
без текста сообщений. Переоткрыть соответствующий INC с новым capture; определить
границу watcher → host → listener → CEF до нового исправления. Не называть
примесь других сессий, потерю данных или общий hook cause доказанными по одному
расхождению интерфейса.

Ошибка `SessionStart:compact` отдельно принадлежит
[INC-0037](../extensions/claude-bridge/runtime-issues/INC-2026-0037.md).
Сначала использовать уже восстановленный private supplement из карточки: там
есть полный stderr связанных вызовов с `MODULE_NOT_FOUND`. Не запрашивать его
повторно и не обещать новые исторические файлы. Для нового события сохранить
его отличие и effective handler declaration/provenance; новый stderr нужен,
если это другой вызов. Этот release не объявляет неизвестный hook исправленным.
