HTML+CSS в GPUI — карта соответствий

Справочник по крейту kamin-html: что из разметки мы рисуем сами, во что оно превращается и где проходит граница возможного.

Зачем это нужно

Что это. kamin-html — переводчик разметки в элементы интерфейса KaminIDE. Он принимает фрагмент HTML со стилями и возвращает дерево элементов GPUI — тех же самых, из которых собран весь остальной интерфейс приложения.

Зачем. Часть нашего интерфейса исторически написана как веб-страница, поэтому её рисует встроенный Chromium. Цена известна и измерена на рабочей машине: семь дочерних процессов браузера держали 810 МБ при общем потреблении приложения 1,36 ГБ. Причина не в объёме данных, а в устройстве: каждая панель — отдельный процесс со своей копией и данных, и всей платформы (движок скриптов, DOM, композитор, сеть, хранилища). На длинной сессии счёт доходит до двух гигабайт.

Ключевая мысль. Браузер нужен там, где выполняется чужой код — панели сторонних расширений. Там, где мы рисуем свою разметку и скрипты в ней всё равно запрещены, браузер — это накладные расходы без выгоды.

Два таких случая у нас уже есть:

  • Виджеты ShowWidget — модель присылает HTML+CSS+SVG, скрипты в них не исполняются по построению.
  • Разметка ответов модели — заголовки, списки, таблицы, блоки кода, выделения.

Обе задачи — «нарисовать статическую разметку», и обе решаются без браузера.

Охват в цифрах

Цифры получены обмером нашего собственного кода, а не оценкой на глаз: 94 файла CSS плюс инлайновые стили в 172 файлах разметки — 7045 объявлений.

87%бокс, флекс, текст, цвет
+10%позиционирование, прокрутка, состояния
~3%требуют того, чего в GPUI нет
82%селекторов — одиночный класс

Отдельно показательно, чего в нашем CSS нет вовсе: ни одного float, ни одной табличной раскладки, ни одного адаптивного @media, ни одной множественной тени, ни clip-path, ни трёхмерных трансформаций. Это не случайность — современная вёрстка держится на флексе, а флекс в GPUI есть целиком.

Как пользоваться

Два вызова: разобрать и отрисовать.

use kamin_html::{parse, render, RenderOpts};

// 1. Разбор: HTML + таблица стилей приложения (тема).
let nodes = parse(html, theme_css);

// 2. Отрисовка: базовый стиль текста задаёт приложение.
let opts = RenderOpts { text: window.text_style(), table_min_col: 80. };
let elements = render(&nodes, &opts);

// 3. Элементы вставляются как любые другие.
div().flex().flex_col().children(elements)

Почему тема отдельным параметром. Документ не должен знать цвета приложения: одна и та же разметка обязана выглядеть правильно и в светлой теме, и в тёмной. Приложение передаёт свою таблицу стилей, документ её переопределяет только там, где задал явно.

Промежуточная структура вычисленного стиля (шаг 3) существует не для красоты: она проверяется тестами без окна и рендера, и именно её поля задают границу охвата. Есть поле — свойство поддержано; нет поля — свойство пропущено осознанно.

Бокс-модель

Что это. Отступы снаружи (margin), рамка (border) и отступы внутри (padding) — та самая коробка, из которой собрана любая вёрстка.

Зачем. Это самая массовая группа: в нашем коде padding встречается 475 раз, margin с вариантами — свыше 350. Без неё документ выглядит как сплошная стена текста.

Как пользоваться. Пишите как в CSS — сокращённая запись раскрывается по правилам стандарта.

Разметка

<div style="padding: 8px 12px;
            margin: 6px 0;
            border: 1px solid #333">
  Карточка
</div>

Во что превращается

div()
  .pt(px(8.)).pr(px(12.))
  .pb(px(8.)).pl(px(12.))
  .mt(px(6.)).mb(px(6.))
  .border_t(px(1.)) /* …4 стороны */
  .border_color(rgb(0x333333))
СвойствоСтатусПримечание
padding, padding-*полностью1–4 значения, px / rem / %
margin, margin-*полностьювключая отрицательные
border-width, border-*полностьюпо каждой стороне отдельно
border-colorчастичноцвет ОДИН на элемент: у примитива GPUI одно поле цвета рамки
border-styleчастичносплошная и пунктир; dotted, double и прочие — нет
box-sizingнетвсегда border-box — так считает движок раскладки
outlineнетрисуется вторым слоем вручную, свойства нет

Почему разноцветные стороны рамки не поддержаны. Прямоугольник в GPUI рисуется одним примитивом с одним полем border_color. Четыре стороны разного цвета потребовали бы четырёх отдельных примитивов с масками — то есть другой схемы отрисовки, а не «дописать свойство».

Флекс

Что это. Раскладка строками и колонками с выравниванием и распределением свободного места.

Зачем. На флексе держится вся современная вёрстка: display:flex в нашем коде — 346 вхождений против 16 у grid. В GPUI флекс поддержан целиком, поэтому именно эта часть переносится один в один.

Разметка

<div style="display: flex;
            flex-direction: column;
            align-items: center;
            justify-content: space-between;
            gap: 8px">…</div>

Во что превращается

div()
  .flex()
  .flex_col()
  .items_center()
  .justify_between()
  .gap_x(px(8.)).gap_y(px(8.))
СвойствоСтатусПримечание
display: flex / inline-flexполностью
flex-directionполностьювсе четыре значения
flex-wrapполностью
flex-grow, flex-shrink, flex: Nполностьюиз сокращения берётся первое число

Grid

Что это. Раскладка по сетке из колонок и строк.

Зачем. Нужна там, где элементы обязаны выстроиться по общим колонкам: панели статистики, сравнительные таблички, галереи.

Как пользоваться. Поддержан произвольный список дорожек — не только равные колонки.

<div style="display: grid; grid-template-columns: 120px auto 1fr; gap: 8px">
  <div>Дата</div><div>Статус</div><div>Описание</div>
</div>

→  div().grid().grid_template_cols(vec![
       GridTrack::Pixels(px(120.)),   // фиксированная
       GridTrack::Auto,               // по содержимому
       GridTrack::Fraction(1.0),      // остаток строки
   ])
ДорожкаСтатусСмысл
120pxполностьюфиксированная ширина
1fr, 2frполностьюдоля свободного места
autoполностьюпо содержимому
min-content, max-contentполностьюминимальная / без переносов
minmax(a, b)частичноберётся верхняя грань; нижняя всегда min-content
repeat(3, 1fr)полностьюразворачивается в три дорожки
grid-template-areas, auto-flow, subgridнет

Как это появилось. Штатный GPUI умел ровно «N равных колонок», хотя движок раскладки под ним поддерживает полный CSS Grid — наружу это просто не было выведено. Мы добавили тип дорожки и проброс в слой совместимости (около сотни строк). Отдача несоразмерна затратам: вместе с дорожками открылись колонки по содержимому, а на них стоит вся раскладка таблиц. До этого таблица из даты и длинного текста делилась пополам.

Размеры

Что это. Ширина, высота и ограничения на них.

Зачем. Без ограничений длинная строка растягивает контейнер, а картинка ломает колонку.

<div style="width: 50%; max-width: 480px; min-height: 40px">…</div>

→  div().w(relative(0.5)).max_w(px(480.)).min_h(px(40.))

remполностьюсчитается от 16px
emчастичносчитается от базового размера, а не от родительского

Позиционирование

Что это. Вынос элемента из общего потока: значки поверх карточки, бейджи в углу.

<div style="position: relative">
  <span style="position: absolute; top: 4px; right: 6px">•</span>
</div>

→  div().relative().child(div().absolute().top(px(4.)).right(px(6.)))
ЗначениеСтатусПримечание
relative, absoluteполностьювместе с top/right/bottom/left
fixedчастичноведёт себя как absolute; привязки к окну нет
stickyчастичноведёт себя как relative: прилипания нет
z-indexнетпорядок отрисовки определяется деревом, а не числом

Важное отличие в поведении. В CSS абсолютный элемент ищет ближайшего позиционированного предка и может «пробить» несколько уровней вложенности. В GPUI он всегда считается от непосредственного родителя. Разметка, рассчитанная на дальнего предка, встанет не туда — это единственное расхождение, которое не видно по стилю и проявляется только на экране.

Прокрутка и обрезка

Что это. Что делать с содержимым, которое не помещается.

<div style="max-height: 360px; overflow-y: auto">…</div>
ЗначениеСтатусПримечание
overflow: hidden / clipполностьюпо каждой оси отдельно
overflow: scroll / autoчастичнообрезка есть; сама прокрутка требует состояния и включается приложением

Тонкость, о которой стоит знать. Обрезка в GPUI — всегда прямоугольник. Поэтому overflow: hidden вместе со скруглением НЕ срежет углы у детей: угол ребёнка вылезет за скруглённый угол родителя. Лечится тем же скруглением на ребёнке.

Фон и градиенты

Что это. Заливка элемента цветом или переходом цветов.

Как пользоваться. Цвет принимается в любой распространённой записи: #rgb, #rrggbb, #rrggbbaa, rgb(), rgba() (и с запятыми, и в пробельной записи со слэшем), плюс около 60 именованных цветов.

<div style="background: #1e1f29">                     → .bg(rgb(0x1e1f29))
<div style="background: rgba(0 0 0 / 50%)">           → .bg(hsla(…, a = .5))
<div style="background: linear-gradient(90deg, #000, #fff)">
     → .bg(linear_gradient(90., stop(чёрный, 0.), stop(белый, 1.)))
ВозможностьСтатусПримечание
background-colorполностью
linear-gradientчастичноберутся первый и последний цвет: примитив GPUI имеет ровно два стопа
направления словами (to right)полностьюпереводятся в градусы
radial-gradient, conic-gradientнетпримитива нет
background-image: url()неткартинка в GPUI — отдельный элемент, не заливка

Рамки и скругления

Скругление поддержано по каждому углу отдельно — это ровно то, что нужно для карточек, чипов и кнопок.

<div style="border-radius: 8px 8px 0 0">
     → .rounded_tl(px(8.)).rounded_tr(px(8.)).rounded_br(px(0.)).rounded_bl(px(0.))

Эллиптические радиусы вида border-radius: 50% / 20% не поддержаны: у угла в GPUI одно скалярное значение, а не пара полуосей.

Тени

Что это. Мягкая тень под элементом — главный инструмент разделения слоёв в плоском интерфейсе.

<div style="box-shadow: 0 2px 8px rgba(0,0,0,.4), 0 8px 24px rgba(0,0,0,.2)">

Обе тени доедут: GPUI хранит список теней, а не одну. Разбор устойчив к запятым внутри rgba().

Внутренние тени (inset) отбрасываются намеренно. Примитив тени рисует только внешнюю; нарисовать внутреннюю внешней — значит показать не то, что просили. Пропуск честнее: расхождение видно сразу, а не всплывает у пользователя.

Прозрачность

<div style="opacity: .6">  →  div().opacity(0.6)

Отличие от браузера. В CSS полупрозрачная группа сначала рисуется целиком, а потом гасится как единая картинка. В GPUI прозрачность умножается в каждый примитив по отдельности — отдельного слоя нет. Для группы с перекрывающимися детьми результат будет отличаться: места нахлёста окажутся плотнее. На одиночных элементах разницы нет.

Свойства текста

Что это. Шрифт, размер, начертание, цвет, подчёркивание, выравнивание.

Зачем. Самая частая группа во всём корпусе: color — 791 объявление, font-size — 683.

<p style="font-size: 15px; font-weight: 600; color: #e6e6ee;
          line-height: 1.6; text-align: center">Заголовок</p>

→  div().text_size(px(15.)).font_weight(FontWeight(600.))
        .text_color(rgb(0xe6e6ee)).line_height(relative(1.6))

Инлайн-поток

Что это. Абзац, внутри которого текст перемежается выделениями, ссылками и кусками кода.

Зачем это отдельный раздел. Здесь проходит главное расхождение между HTML и GPUI, и его стоит понимать до того, как результат удивит на экране.

В браузере абзац — поток строк: в него встраиваются куски любого размера, и строка растёт под самый высокий из них. В GPUI текстовый блок — лист раскладки: размер шрифта у него один на весь блок, метрики строки тоже одни.

Как мы это решаем. Стратегия выбирается по факту содержимого:

1. Один блок текста — когда куски однородны

Если все куски абзаца одного размера и ни один не несёт собственного бокса, они собираются в единый текст с прогонами. Перенос по словам тогда честный — ровно как в браузере, сквозь границы тегов.

<p>Обычный, <b>жирный</b> и <a href="#">ссылка</a> в одной строке</p>

Прогон несёт свой цвет, вес, начертание, подчёркивание и зачёркивание. Это покрывает подавляющее большинство разметки.

2. Гибкая строка — когда кусок выбивается

Если кусок задаёт свой размер шрифта или несёт собственный бокс (фон, рамку, отступы — как <code> с подложкой), он становится отдельным элементом в строке с переносом.

<p>Вызовите <code style="background:#2a2b36;padding:2px 4px">render()</code> здесь</p>

Цена: перенос идёт по кускам, а не по словам внутри них. На длинном фрагменте кода это заметно. Зато размеры и подложки честные — а не притворяются работающими.

Чего не будет. Вертикального выравнивания по базовой линии для кусков разной высоты, обтекания картинки текстом, vertical-align. Это следствие отсутствия строчного контекста, а не пробел в реализации.

Наследование

Что это. В CSS вниз по дереву передаются только текстовые свойства: цвет, размер, начертание. Отступы и фон принадлежат элементу и не наследуются.

Мы воспроизводим это правило точно.

<div style="color: #ff5555; padding: 10px; font-size: 20px">
  <span style="font-weight: 700">текст</span>
</div>

Внутренний <span> получит:  цвет #ff5555 ✔  размер 20px ✔  вес 700 (свой) ✔
                            отступ 10px ✘ — остался у родителя

Списки

Что это. Маркированные и нумерованные перечни.

Как устроено. Свойства list-style в GPUI нет, поэтому маркер рисуется явным элементом: точка либо номер в колонке фиксированной ширины, содержимое — рядом.

<ul><li>Первый</li><li>Второй</li></ul>

→  строка [ • ][ Первый ]
   строка [ • ][ Второй ]

Плюс подхода: многострочный пункт выравнивается по тексту, а не заезжает под маркер. Минус: типы маркеров (disc, circle, square, римские цифры) не различаются — точка и арабский номер.

Таблицы

Что это. Строки и колонки с общей шириной по всей таблице.

Зачем отдельно. Табличной раскладки в GPUI нет как класса. Мы строим таблицу на сетке — и это стало полноценным решением только после того, как появились произвольные дорожки.

<table>
  <tr><th>Дата</th><th>Событие</th></tr>
  <tr><td>05.08</td><td>Длинное описание, занимающее остаток строки</td></tr>
</table>

Дорожки:  minmax(min-content, auto)   ← колонка «Дата» сжимается по содержимому
          minmax(min-content, 1fr)    ← последняя забирает остаток
ВозможностьСтатусПримечание
колонки по содержимомуполностьючерез дорожки сетки
<thead>, <tbody>, <tfoot>полностьюразворачиваются в строки
colspan, rowspanнетвыражаются через размещение в сетке, пока не сделано
border-collapseнетрамки соседних ячеек не схлопываются

Честная оговорка. Ширина колонки считается по строке, а не по всей таблице: каждая строка — своя сетка. Для документов это незаметно, потому что содержимое ячеек однородно, но с настоящей табличной раскладкой это не совпадает.

Блоки кода

Что это. <pre> — текст, где переводы строк и пробелы значимы.

Как устроено. Обычный текст в HTML схлопывает пробелы; внутри <pre> этого делать нельзя. Поэтому содержимое режется на строки, и каждая рисуется отдельным элементом.

<pre>fn main() {
    println!("привет");
}</pre>

→  три элемента-строки в колонке, отступы сохранены

Подсветка синтаксиса приходит из разметки: генератор оборачивает лексемы в <span> с классами, а цвет им задаёт таблица стилей темы. Никакого разбора кода на нашей стороне не происходит.

Почему внешние адреса не грузим. Документ рисуется в чате, и загрузка по сети означала бы обращение к чужому серверу от лица пользователя — ровно то, что запрещено политикой webview. Вместо тихой пустоты показывается alt: дыра в разметке без объяснения хуже.

Векторная графика

Что это. Тег <svg> внутри документа: графики, диаграммы, схемы, значки.

Зачем. Это не второстепенная деталь: инструмент ShowWidget прямо предлагает модели рисовать графики через SVG, и без него виджеты теряют главное содержание.

Как устроено. Поддерево <svg> сериализуется обратно в разметку и растрируется — теми же библиотеками, что уже стоят внутри GPUI. Результат отдаётся как готовое изображение.

<svg viewBox="0 0 100 40">
  <rect x="0"  y="10" width="18" height="30" fill="#3b5bdb"/>
  <rect x="24" y="4"  width="18" height="36" fill="#2b8a3e"/>
</svg>

→  растр 2× → img(ImageSource::Render(…)) с размером из viewBox

Почему не через штатный элемент значков. В GPUI есть путь для SVG, но он превращает рисунок в одноцветную маску — это сделано для иконок, которые красятся цветом текста. График, прошедший через него, стал бы одноцветным силуэтом. Поэтому мы добавили в GPUI отдельную функцию растеризации из строки — и специальный тест следит, что красный и синий прямоугольники остаются красным и синим.

Плата. Это растр: при сильном увеличении картинка не пересчитывается. Рисуем с двойной плотностью, чего хватает для дробных системных масштабов. Если разметка не разбирается — показывается запасной текст, а не пустое место.

Наведение

Что это. Правила :hover — подсветка кнопки или строки под курсором.

Как устроено. Такие правила не попадают в базовый стиль — иначе элемент выглядел бы всегда наведённым. Они собираются отдельным слоем и отдаются GPUI как состояние наведения, которое он переключает сам.

<style>
  .btn        { background: #2a2b36; color: #b9bcc9 }
  .btn:hover  { background: #3d3f51; color: #ffffff }
</style>

→  базовый стиль применяется цепочкой методов,
   слой наведения — через .hover(|s| { s.background = …; s.text.color = … })

Каскад и приоритет

Порядок применения — как в CSS, от слабого к сильному:

#ИсточникЧто задаёт

Внутри одного уровня работает специфичность — (идентификаторы, классы, теги) — а при равной специфичности выигрывает правило, записанное позже. !important распознаётся и отбрасывается: значение применяется, приоритет не повышается.

Что не переносится

Список сознательный. Ни одна из этих возможностей не заменяется приближением.

ВозможностьПочему нет
transform (поворот, масштаб, сдвиг)матрица есть только у одного примитива из семи; для группы потребовался бы промежуточный буфер отрисовки
filter: размытие, яркость, контрастнужен многопроходный рендер в буфер — его нет
clip-path, maskобрезка в GPUI — всегда прямоугольник, и он входит в каждый примитив

transitionэлементы пересоздаются каждый кадр — нет «предыдущего значения», от которого идёт переход
@keyframesмеханизм анимации в GPUI есть, но императивный: интерполяция пишется руками, а не объявляется
@media, @container, @supportsусловных правил нет; в нашем корпусе адаптивных запросов ноль

Почему именно так

Правило одно: не подменять. Если свойство невыразимо — не применяется ничего. Приблизительная замена (нарисовать inset-тень внешней, размытие — прозрачностью) выглядит как рабочая поддержка. Расхождение тогда всплывает не в тесте, а у пользователя, и искать его будут в разметке, а не в переводчике.

Три ограничения — архитектурные, и это стоит принять как данность, а не как список задач:

  1. Строчный контекст. Текстовый блок в GPUI — лист раскладки с единым размером шрифта. Всё, что требует потока строк, выражается только обходными путями.
  2. Семь примитивов отрисовки. Прямоугольник, тень, путь, подчёркивание, два вида спрайтов, чужая текстура. Чего нельзя сложить из них — нельзя нарисовать.
  3. Раскладка считается заново каждый кадр. Дерево раскладки не переживает кадр, поэтому большой документ обязан быть виртуализирован по блокам — рисовать только видимое. Это не оптимизация «на потом», а условие пригодности.

Как это проверено

43 теста, каждый — на конкретное правило, а не на «работает вообще»:

  • Значения: длины во всех единицах, цвета в шести записях, именованные цвета.
  • Разбор: запятые внутри rgba() не рвут объявление, !important не попадает в значение, комментарии и at-правила пропускаются.
  • Селекторы: специфичность, потомок против прямого потомка, отбрасывание неподдерживаемых целиком.
  • Каскад: инлайн бьёт таблицу, выше специфичность — тот и выигрывает.
  • Наведение: правило :hover не красит базовый стиль и попадает в отдельный слой; без таких правил слоя нет вовсе.
  • Маппинг: стиль применяется к настоящему элементу GPUI и читается обратно — проверяется сам перевод, а не представление о нём.
  • Граница: отдельный тест утверждает, что filter, transform, z-index и float не оставляют в стиле никакого следа.
  • Векторная графика: поддерево сериализуется обратно без потерь, размер берётся из атрибутов либо из viewBox, цвета переживают растеризацию, битая разметка не даёт пустоты.
  • Разметка: умолчания тегов, вложенные селекторы, выброшенные <script>, восстановление незакрытых тегов, display: none.
