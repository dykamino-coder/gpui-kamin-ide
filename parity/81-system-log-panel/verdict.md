## Цикл 35: MATCH

Последний остаток («в gpui нет управления переносом ВНУТРИ слова, длинный
токен не разорвётся») оказался НЕВЕРНЫМ — я его ни разу не проверил на живом
кадре, а по коду прочитал не то.

`LineWrapper::wrap_line` (`vendor/gpui/src/text_system/line_wrapper.rs:97-112`)
уже реализует семантику `overflow-wrap: break-word`: когда на строке не
набралось ни одного кандидата переноса (`last_candidate_ix == 0`), он рвёт по
ТЕКУЩЕМУ символу — `last_wrap_ix = ix; width = item_width`. То есть слово
длиннее строки разрывается само, без всяких патчей.

Проверка фактом. Добавлен probe-эмит
`{"cmd":"emit","kind":"syslog","name":"…"}` (иначе строку в системный лог
нечем положить), в панель отправлены две записи:

* `tok=` + 400 символов → разорвано на три строки внутри слова;
* `prefix words here ` + 300 символов + ` tail` → «prefix words here» осталось
  на первой строке, токен ушёл на вторую и там разорвался, «tail» дописан
  после.

Оригинал на той же строке (`scripts/orig_measure.mjs`, узел шириной 400 с
`word-break: break-word; overflow-wrap: anywhere`, JetBrains Mono 12):
7 строчных боксов, ширина ПЕРВОГО 112.2 — то есть Chromium тоже оставляет
префикс на первой строке и уносит токен целиком на вторую. Поведение
совпадает.

Разница `break-word` и `anywhere` — только во вкладе в `min-content`; у нас
ячейка сообщения `flex_1 + min_w(0)`, что даёт тот же результат.
