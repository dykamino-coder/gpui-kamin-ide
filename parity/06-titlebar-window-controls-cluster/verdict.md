## Цикл 35 (баг от пользователя): MATCH

«Кнопка уменьшения окна не работает». Кнопка работала — не работало ОКНО:
overlay это отдельное always-on-top окно поверх main, и при сворачивании
главного он оставался висеть на весь экран (замер: main 199×34 = свёрнут,
overlay 2578×1390 visible=True). Пользователь видел, что приложение не
исчезло.

gpui о сворачивании наружу не сообщает — `WM_SIZE` с `SIZE_MINIMIZED` он
гасит у себя (`events.rs:175`), а `sync()` overlay'я ездит из РЕНДЕРА main,
которого у свёрнутого окна нет. Поэтому на главное окно повешен свой
сабкласс: `SIZE_MINIMIZED` → `ShowWindow(overlay, SW_HIDE)`,
`SIZE_RESTORED`/`SIZE_MAXIMIZED` → `SW_SHOWNOACTIVATE`; дальше цепочкой
`CallWindowProcW` в родной WndProc gpui.

Проверено перечислением окон процесса: после клика по «−» видимым остаётся
только main (свёрнутый), после восстановления overlay возвращается и снова
отдаёт `HTTRANSPARENT` (клики проваливаются в main).

Отдельно зафиксировано на будущее: `(Get-Process).MainWindowHandle` у нас
указывает на OVERLAY, а не на главное окно — все замеры окон надо делать
перечислением с фильтром `WS_EX_TOOLWINDOW`, иначе «сворачивается/не
сворачивается» читается по чужому окну.

## Цикл 35 (баг от пользователя, 2): MATCH

«Сворачивание работает, а restore после максимайза — нет». Причина в gpui:
`Window::zoom_window()` на Windows ВСЕГДА шлёт `SW_MAXIMIZE`
(`platform/windows/window.rs: fn zoom`) — восстановления в нём нет вовсе.
Нативный путь окна это делает правильно (`events.rs:1042`:
`(HTMAXBUTTON, HTMAXBUTTON) => if is_maximized { SW_NORMAL } else
{ SW_MAXIMIZE }`), но до него клик не доходит: у нас свой титлбар.

Добавлен `overlay::toggle_main_maximize()` — `IsZoomed` → `SW_RESTORE` либо
`SW_MAXIMIZE` по главному HWND. Подключён и к кнопке, и к двойному клику по
титлбару (там был тот же `zoom_window`).

Проверено probe-кликами по ИЗМЕРЕННЫМ координатам кнопки: развёрнутое окно →
клик → `IsZoomed=False`; восстановленное → клик → `IsZoomed=True`.

Замечание к методике: координаты кнопок брать только из `probe metric`
(`win-min`/`win-max`/`win-close`) — при максимизации они уезжают с 1330 на
1978, и «клик не сработал» оказывается промахом мимо кнопки.
