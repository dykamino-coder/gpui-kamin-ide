## Цикл 25: DIVERGES

Ревью зоны. Его главная находка подтверждена мной по исходнику
`@vscode/codicons/dist/codicon.css`: `:35-39` даёт
`codicon-spin 1.5s steps(30) infinite`, но `:50-53` для `.codicon-loading`
перебивает `animation-duration: 1s !important` и
`animation-timing-function: cubic-bezier(.53,.21,.29,.67) !important`.
`!important` бьёт шорткат — значит период 1000 мс, плавно, БЕЗ шагов.
Вердикты ц.22/24 записали спиннер в «закрыто» с неверным законом.

Закрыто в этом цикле:
- спиннер: 1000 мс + честный `cubic-bezier(.53,.21,.29,.67)` (бисекция по x,
  подстановка по y) вместо 1500 мс `steps(30)` — правка в `ui/icon.rs`
  чинит разом корень, узлы и бейдж Indexing;
- корневая строка реагирует на `on_click`, а не на mouse-down: корень — тот
  же `FolderNode` (`FileTreeView.tsx:184`); узлы починили в ц.23, корень
  тогда выпал;
- бюджет усечения имени корня уменьшен на indentPx(0)=8 — «…» появлялся на
  8 px позже, чем у узлов;
- бейдж декорации без своего `ThemeColor` подхватывает
  `.row:hover { color: text-primary }` (был прибит к text-secondary).

Осталось: ползунок тела (у оригинала 8 px В ПОТОКЕ с thumb на всю ширину,
у нас overlay gpui-component 16/6-8); горизонтальная ось скролла
(`overflow: auto` обеих осей — эффект близок к нулю при `.row{width:100%}`,
но пункт не закрыт); `.root { flex: 1 }` против нашего `size_full`.

## Цикл 35: MATCH

**Ползунок.** Оригинал не рисует свой — работает штатный
`::-webkit-scrollbar` (`theme/global.css:25-29`): дорожка 8px, трек
прозрачный, thumb `--bg-overlay` НА ВСЮ ширину дорожки с радиусом
`--radius-xs` = 4, ховер `--text-disabled`. Вендорный gpui-component давал
дорожку 16 с thumb'ом 6/8 внутри и «толстеющим» активным состоянием.
Метрики поправлены в вендоре (`scroll/scrollbar.rs`, маркер `KaminIDE patch`,
реестр: 16 файлов / 61 маркер): WIDTH 8, THUMB_WIDTH 8, радиус 4, инсеты 0,
активное состояние совпадает с обычным. Цвета уже были правильные
(`theme_sync.rs:423-424`). Кадром подтверждено: узкая полоса у правой кромки
без внутреннего зазора.

**Горизонтальная ось.** Пункт закрыт разбором, а не кодом: `.label` строки
имеет `flex: 1; overflow: hidden; text-overflow: ellipsis`
(`FileTreeView.module.css:139-143`), а сама строка — `width: 100%`. Значит
контента шире бокса не возникает ни у оригинала, ни у нас, и вторая ось
`overflow: auto` у `.body` фактически мертва. У нас метка режется тем же
эллипсисом (`text_fit`), поведение совпадает.

**`.root { flex: 1 }` против `size_full`.** Высоту корню задаёт родитель
(колонка), поэтому оба варианта дают одинаковый бокс; замер `flex_1` в ц.25
давал 2293 против 833 у колонки — именно из-за того, что flex-basis считался
от контента. Эквивалентность зафиксирована комментарием в коде.
