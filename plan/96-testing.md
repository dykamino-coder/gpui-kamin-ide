# 96 — План тестирования (техническое + визуальное)

Пишется ДО имплементации; каждая фаза кода закрывается только через свои тест-гейты. Эталон всегда = kamin-ide 0.2.87 (Tauri, main) — он остаётся установленным рядом как «золотой» экземпляр для сравнения до конца миграции.

## Что дают авторы библиотек (проверено 2026-07-24)
- **GPUI**: `#[gpui::test]` + **TestAppContext** (headless, детерминированный executor, симуляция ввода) + **VisualTestContext** (оконные тесты: окно с компонентом, simulate_click/simulate_keystrokes, draw) — Zed сам тестирует так редактор. **Inspector** (debug-сборки, `dev::ToggleInspector`): пик элемента, bounds/layout, live-правка стилей, переход к коду — только интерактивный (Div-only, без автоматизации/скриншотов); держим включённым в dev как ручной инструмент.
- **gpui-component**: паттерн **story-крейта** (Gallery-приложение — их storybook) — наш `--gallery` строим по нему же; `.claude/skills/` в репо + опубликованные скиллы **gpui-style-guide** и **gpui-test** — скопировать в наш `.claude/skills/` на старте (паттерны компонентов и тестов).
- Скриншот/visual-regression инструмента и MCP инспекции НЕ существует ни у Zed, ни у longbridge → пиксель-дифф и probe — свои (ниже).

## 0. Ключевая проблема и её решение: у нативного окна нет CDP

Сейчас весь E2E/верификация — Playwright→CDP (память: «любой UI-элемент проверять LIVE»). GPUI-окно — не браузер, CDP нет. Решение — **kamin-probe**: debug-RPC внутри GPUI-шелла (dev/test-сборки, `--probe-port`, loopback+токен; в release компилируется вон через feature-flag):
- `tree` — дамп UI-дерева: id/роль/текст/bounds(x,y,w,h)/видимость/hover-состояние — аналог snapshot.
- `click/hover/drag/key/type/scroll` — синтетический ввод через GPUI dispatch (не SendInput — не трогаем реальную мышь пользователя).
- `screenshot` — рендер окна в PNG (render-to-texture, БЕЗ CopyFromScreen — запрет из инцидента с Outlook).
- `metric <id>` — bounds+резолвнутый стиль элемента (font-size, padding, radius, цвет) — для метрик-асертов.
- Клиент — mjs-скрипт `scripts/probe.mjs` (как launch-cdp.mjs сейчас), чтобы я мог гонять проверки из CLI.
kamin-probe пишется **первым UI-кодом проекта** (сразу после «пустое окно рисуется»), иначе всё дальше не верифицируемо.

Вебвью (gpui-wry = WebView2) сохраняют CDP: `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` + Playwright attach — чат Бриджа тестируется как сейчас, без изменений.

## 1. Техническое тестирование

### 1.1 Rust unit (cargo test, на каждый коммит)
- `theme`: резолв токенов dark/light, предвычисление ВСЕХ color-mix тинтов (вход: token+%, выход: точный rgba — таблица из plan/23 как фикстуры), glint-стопы, contributed-theme резолвер (workbench-ключ → токен → fallback-граф из plan/25; фикстуры = реальные json тем: Catppuccin, One Dark, светлая).
- `metrics`: константы существуют и равны plan/23 (генерируемый тест: таблица значений дословно из дока).
- `layout`: математика сплиттеров — клампы (мины 100, сплиты 0.7 [0.2–0.85] / 0.55 [0.15–0.85], ratio-клампы FILE 0.05–0.6 / BOTTOM 0.1–0.8), collapse/restore, layout.json сериализация (schema из plan/50, включая факт «rightPanelSplit НЕ персистится»).
- `ws-protocol`: serde всех req/res/evt из plan/50 — golden-JSON фикстуры, снятые с живого kamin-host (см. 1.2); неизвестные поля не роняют (forward-compat).
- `state`: сторы (сессии, вкладки, дерево) — редьюсеры на последовательностях событий (реплей реальных логов).
- **Компонентное поведение — `#[gpui::test]` + VisualTestContext** (официальный путь Zed): окно с компонентом headless, simulate_click/simulate_keystrokes → асерты состояния/bounds. Кликабельность кнопок, hover-состояния, фокус, drag сплиттера — сюда, БЕЗ живого окна и probe. Паттерны — из скилла gpui-test (longbridge).
- Инструментарий: `cargo test` + `cargo clippy -D warnings` + `cargo fmt --check` (память: ревью покрывает Rust).

### 1.2 Контракт с kamin-host (protocol-contract, против ЖИВОГО хоста)
- Харнесс: спавним настоящий kamin-host (node kamin-host.mjs из kamin-ide) → handshake EVT_READY {extensions,wsPort,wsToken} → WS connect.
- Прогон каждого RPC-метода из plan/50 с записью req/res → эти записи и есть golden-фикстуры для 1.1 (регенерируемые скриптом, не руками).
- Негативные: неверный токен, обрыв WS (бэкофф-реконнект), host-рестарт (супервизор, лимит 3).
- kamin-host сам НЕ меняется → его 303 vitest-теста остаются в kamin-ide и гоняются там (`npm run check`); сюда не дублируем.

### 1.3 Интеграция шелла (в tests/, cargo test --test integration)
- Sidecar-цепочка: unpack payload (version+hash ключ — регресс c85fba2), спавн kaminhost.exe, Job Object убивает детей при выходе, парсинг ready-строки, рестарт-супервизор.
- Single-instance: второй запуск форвардит argv, событие open-folder доходит.
- Апдейтер: мок-сервер /updates/kaminide/* → проверка derive-эндпоинта из serverUrl, minisign-верификация (валидная/битая подпись), up-to-date ≠ ошибка.
- listFiles-гейт (Q5): гигантский workspace-фикстура (генерируем 50K файлов в temp) → activation ≤ 2s, onStartupFinished файрится.

### 1.4 E2E (kamin-probe + Playwright для вебвью)
Сценарии = plan/45 (каждый экран/кнопка). Приоритетный смоук (каждая сборка):
1. Холодный старт → окно видно → EVT_READY → activity-bar 7 слотов → чат-вебвью загрузился (Playwright: композер виден).
2. Сессии: создать → стрим идёт (данные с localhost:3456 реплики) → переключение сессий (регресс «flash предыдущего чата») → rename.
3. Файлы: открыть папку → дерево → открыть файл в редакторе → подсветка есть → LSP hover (провайдер с хоста).
4. Layout: драг каждого из 6 сплиттеров через probe → bounds меняются в клампах → рестарт → layout.json восстановился.
5. Терминал: открыть → `echo test` → вывод виден.
6. Elicitation: AskUserQuestion от CLI → виджет в чате → ответ уходит (Playwright в вебвью).
7. Все 14 built-in команд (plan/66 §A) через палитру.
Полный прогон (перед релизом): вся матрица plan/45 + 10 customize-страниц + контекст-меню.

### 1.5 Перф (CI-гейт, бюджеты ЖЁСТКИЕ — память feedback_perf_budgets_nonneg)
- cold start <800ms (запуск → первый painted кадр; замер как perf:cold-start сейчас), idle RAM <90MB (вся группа процессов шелла БЕЗ node-сайдкара — его меряем отдельно и сравниваем с текущим), бинарь: цель <30MB без payload.
- Нагрузочные регрессы из памяти: huge-session (JSONL 50MB) — переключение чата без фриза кадров >100ms (probe меряет frame-time); стрим на макс-скорости — UI-поток не блокируется; дерево 50K файлов.
- GPU: частота кадров при resize-драге (регресс «баг рендеринга при активном ресайзе» из Servo-теста фиксируем как анти-цель).

### 1.6 DLP-иммунитет (сама причина проекта)
- Тест на рабочей машине с siph64.dll: воспроизвести профиль нагрузки, который вешает Tauri (Monaco+стрим+churn, сценарий из investigation_not_responding_freeze) → GPUI-окно обязано пережить 8h-сессию. Freeze-diag слой (plan/10) портируется и остаётся в проде — verdict EXTERNAL/INTERNAL как в 0.2.53.
- Гейт фазы «пустое окно»: даже голый GPUI-шелл гоняется на рабочей машине сутки ДО того, как вкладываться в UI — если GPUI тоже виснет под DLP, узнать это на неделе 1, а не на месяце 3.

## 2. Визуальное тестирование (правило №0 — 1:1)

### 2.1 Два уровня проверки (дешёвый ловит 95%)
1. **Метрик-асерты (geometry, допуск 0):** bounds/font-size/padding/radius РОВНО равны константам plan/23. Первичный путь — **headless через VisualTestContext** (bounds элементов доступны в `#[gpui::test]`-окне — спайк на «пустом окне» подтверждает; так асерты живут в cargo test и гоняются на каждый коммит без живого окна). probe `metric` — дублирующая проверка на РЕАЛЬНОМ окне (реальный DPI/шрифтовый рендер) в E2E-прогоне. Сдвиг на 1px = красный тест с именем константы.
2. **Пиксель-дифф (эталон против золотого kamin-ide):** для того, что метриками не снять — градиенты, glint, тени, blur, шрифтовый рендер.

### 2.2 Пайплайн пиксель-диффа
- Эталоны: скрипт `scripts/capture-golden.mjs` гоняет kamin-ide 0.2.87 через существующий CDP-путь (launch-cdp.mjs) → фиксированное окно 1400×900, DPI 100%, обе темы → PNG в `golden/<screen>-<theme>.png`. Данные детерминированы: фикстурная workspace-папка + фикстурная сессия (замороженный JSONL) + отключённые анимации — иначе диффы флапают.
- Кандидаты: probe `screenshot` тех же экранов/темы/размера.
- Сравнение: композитный критерий — (а) геометрия: SSIM-структура / edge-map совпадает с допуском 0 (сдвиги ловятся); (б) цвет: per-pixel ΔE ≤ 2 на плоских областях; (в) текст: рендер DirectWrite и там и там, но AA субпиксельно отличается → на текст-областях допускаем локальный AA-шум ≤ N% пикселей при полном совпадении bounding-box строк (bounds уже гарантированы метрик-асертами). Порог подбирается один раз на «пустом окне» и замораживается.
- Diff-репорт: HTML со свайпером golden/candidate/heatmap — смотрю глазами каждый красный.

### 2.3 Матрица экранов
Оси: экран (11 хост-экранов plan/45 + DesignPanel + каждая тултип/поповер/меню-поверхность из plan/23) × тема (dark/light) × состояние (default/hover ключевых кнопок/active-таб/collapsed-панель) × масштаб (100%/150% DPI). Hover ставится через probe перед снятием. Вебвью-контент (чат) в дифф НЕ входит (он буквально тот же WebView2-код) — только его рамка/шторка/спиннер.

### 2.4 Компонентная галерея (аналог storybook)
Dev-экран `--gallery`: каждый GPUI-компонент изолированно во всех состояниях на нейтральном фоне. Скрин каждого тайла → сравнение с cropped-эталоном соответствующего компонента kamin-ide (кропы по bounds из CDP). Закрытие компонента в plan/40 = зелёный тайл в галерее. Тайлы для tricky-визуалов (plan/24): glint-surface, радиальный фон, свечение лого, тени-токены, параметрические градиенты сессий, скелетоны — по одному эталонному тайлу на приём.
- Два помеченных риска (backdrop-blur, ellipse-radial) получают спайк-тайлы ПЕРВЫМИ: решение «GPUI умеет / аппроксимация» принимается по диффу тайла, до массовой стройки.

### 2.5 Шрифтовый гейт (метрика всего layout — plan/22 §1)
До первого компонента: тайл «строка текста каждым fs-токеном (11/12/13/16/22) Bricolage + tabular-nums + ss01» против того же в браузере → ширина строки в px совпадает (допуск ≤0.5px/100 глифов). Если GPUI-шейпинг даёт другую ширину — это блокер уровня фундамента, узнаём сразу.

## 4. CI-пайплайн (порядок)
`cargo fmt --check` → `clippy -D warnings` → `cargo test` (unit+integration) → сборка dev-exe → kamin-probe E2E-смоук → метрик-асерты → пиксель-дифф (галерея + экраны) → перф-бюджеты. Красный любой ступени = фаза не закрыта. Полный E2E + full-матрица диффа — перед релизными тегами.

## 5. Что НЕ тестируем заново
- kamin-host / exthost / LSP / VSIX — без изменений, их 303 теста + corpus:compat живут в kamin-ide.
- Сервер Бриджа (:3456) — без изменений, vitest в open-claude-bridge.
- Контент чат-вебвью — тот же код тем же WebView2; тестируется существующими Playwright-сценариями, здесь только рамка/интеграция.
