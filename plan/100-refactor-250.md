# План 100 — разбор кода на модули ≤250 строк

Цель (постановка пользователя): «все файлы кода не больше 250 строк, всё
логично и понятно даже для джуна, разбито по папкам и модулям, UI-компоненты
отнесены от бизнес-логики и составляют дизайн-систему, весь текущий визуал и
функционал остаётся на месте и не ломается».

## Правила работы

1. **Ни одного изменения поведения.** Каждый шаг — перенос кода, а не правка.
   После шага: `cargo build` + `cargo test` + запуск и кадр-сверка затронутого
   места через probe.
2. **Шаг = один файл.** Разбираем по одному, чтобы падение сразу
   локализовалось.
3. **Сгенерированные таблицы — не код.** Они уходят в `assets/*.txt` рядом с
   ассетами, а в `.rs` остаётся загрузчик на десятки строк.
4. **Дизайн-система отдельно.** `ui/primitives/` — кнопки, иконки, тени,
   типографика, кольца фокуса: без знания о сессиях, редакторе и хосте.
   `ui/components/` — панели и списки, собранные из примитивов.
   Бизнес-состояние живёт в `state/`, связь с хостом — в `host/`.

## Целевая структура `crates/shell/src`

```
main.rs               запуск и ничего больше
app/                  окно, действия, жизненный цикл
state/                RootView по доменам: layout, sessions, editor, overlays
host/                 host_link по темам: клиент, реестр, сессии, ФС
platform/             win32: probe_*, wv_visual, os_clipboard
ui/
  primitives/         дизайн-система (кнопка, иконка, тень, типографика…)
  components/         панели, списки, меню
  icons/              наборы иконок + подбор по имени
```

## Мёртвый код, снятый после разбора

Чистка импортов открыла то, что раньше пряталось за «использованием» из
мёртвых же мест. Каждый кандидат проверен грепом по всему креиту, а не только
по предупреждению компилятора:

* `ui/minimap.rs` целиком (самопальная полоса-миникарта; живые —
  `editor_minimap` + `minimap_geom`) и её кэш `RootView.minimap_cache`;
* `glint::glint_surface` — панели рисует `glint_surface_wv_holed`;
* `wv/zone_query::{zone_of, zone_logical}` — `zone_of` вызывался ТОЛЬКО из
  `zone_logical`, у которого нет вызывающих: пара умирает целиком;
* `DraggedTreeNode.view` — идентификаторы едут в событиях `TreeDragStart` /
  `TreeDrop`, поле не читает никто; структура осталась как тип-маркер для
  `drag_over::<T>` / `on_drop`;
* `radial_bg::bake_glow` (живой — `bake_glow_edge`), `toast_card::set_hovered`
  (ховер берётся из `toast::cursor_over` в render), `codicon_text::render_any`,
  `activity::glyphs::tool_glyph`, константы `icon::{FOLDER_OPENED, FA_MOON}`;
* ранее: `probe_input::drag`, `probe_keys::{type_text, press_key}` (обёртки над
  `*_to`), вариант `ShellEvent::ToggleFileMenuOpenIn` без отправителей,
  `overlay::drive_webview_children` (эпоха wry), полезная нагрузка `WvLive`.

НЕ мёртвым оказался `apply_window_region`: лишним был только ре-экспорт в
фасаде `overlay/mod.rs` — сама функция вызывается из `region` и `diag_states`.

Итог: −198 строк, сборка БЕЗ предупреждений, 76 тестов. Кадр после удаления
снят (общий вид, редактор с миникартой и breadcrumb, contributed-вью,
внешний тост 493×185 — `toast_card` жив).

## Ноль предупреждений clippy

`cargo clippy --workspace --all-targets` давал 130 замечаний по нашему коду
(обычный `build` их не показывает). Осталось **0**.

Механические (`clippy --fix`, 89 штук): `Variant { .. }` на безполевых
вариантах — след разбиения `ShellEvent` (48), лишние `&` при автодерефе (25),
вложенные `if` (11), `contains` вместо `iter().any()`, `clone` у `Copy`-типов.
`cargo fix` требует VCS, а репозитория тут нет — перед запуском снял копию
`crates/` и прогнал с `--allow-no-vcs`.

Руками:

* **`CzEvent::IconThemeLoaded(String, IconTheme)` → `Box<IconTheme>`**: тема
  весит ~950 байт и раздувала ДО 984 байт КАЖДОЕ событие в канале, включая
  `WsConnected`;
* осиротевшие доки после удаления мёртвого кода: док `bake_glow_edge`
  начинался с «То же, но…» и прилип к кэшу свечений; док константы ширины
  Appearance описывал константу, которой больше нет (поповер меряется сам);
* `match` с единственной ветвью в `probe_host`, лишние скобки в `probe_cmds`,
  `StatusCounts` собирается литералом, `enumerate` вместо индексации,
  `&String` → `&str` в меню, псевдонимы для развесистых типов
  (`GlowCache`, `OverlayWinSlot`, `TestRig`), тест-модули в конец файла;
* 20 UI-функций с 8–12 параметрами помечены
  `#[allow(clippy::too_many_arguments)]`: это компоненты дизайн-системы,
  аргументы у них — пропсы. Сборка пропсов в структуры — отдельная задача.

Проверено: сборка без предупреждений, 76 тестов, все файлы ≤250 строк,
кадр живого приложения (общий вид + меню профилей терминала) прежний.

   по файлам — операции ушли в `editor.rs`, поиск стал своим `find_in_files.rs`.
3. **Папки вместо кучи.** Корень `shell/src`: 39 → 21 файла. Появились

### Страховка от молчаливой потери события

У каждого `apply_*` есть ветка `_ => {}`, поэтому неверный маршрут в
`dispatch.rs` компилятор не ловит — кнопка просто перестаёт работать.
Добавлен `scripts/check_event_routing.py`: сверяет, что каждый вариант события
маршрутизируется ровно в тот модуль, где у него есть ветка. До и после правок —
196 вариантов, 196 обработчиков, расхождений нет.

Проверено вживую (один экземпляр): метрики `titlebar`/`body`/`status-bar`/
`file-tree`/`session-chip`/`terminal` совпадают с дорефакторными до сотых;
панель «Найти в файлах» открывается из нового модуля; меню профилей терминала,
создание вкладки и закрытие крестиком работают из `terminal.rs`.
