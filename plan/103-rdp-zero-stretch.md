# RDP: ноль фризов с недорастянутой текстурой, ноль пересжатия (2026-08-04)

Цель юзера: на RDP **никогда** не должно быть фриза с недорастянувшейся
текстурой; растяжение/сжатие свести к 0. Аудит `rdp-render-scan` + правки.

## Ключевые факты аудита

- Единственный инструмент «без растяжения» — `ExternalTexture::cropped/region`
  (`vendor/gpui/src/scene.rs:663-693`), и он ЕСТЬ ТОЛЬКО у GPU-пути.
- SW-путь (RDP): `window.paint_image` (`vendor/gpui/src/window.rs:3247`)
  вписывает ВЕСЬ образ в прямоугольник — crop для `RenderImage` невозможен.
  Значит любой кадр ≠ панели = растяжение по каждой оси отдельно.
- Анти-залипание («кадр не того размера → nudge») жило ТОЛЬКО в GPU-ветке
  (`element.rs:78-84`) — на RDP застрявший `hold_resize` не детектился НИКОГДА.
- Браузер поднимался жёстко `800×600@1.0` (`mod.rs:287`) — первые кадры
  всегда чужого размера, в т.ч. при возврате вью после `reap_hidden`.
- Снэп ±1 лог.px (`element.rs:117-122`) при дробном scale (125/150% типично на
  RDP) даёт ПОСТОЯННЫЙ субпиксельный ресемпл в установившемся режиме.

## Сделано (1.0.29+)

1. **Подъём вью в правильном размере** (`web/mod.rs ensure_html_view`):
   `element::last_size(id)` + `browsers::scale_of(id)` вместо `800×600@1.0`.
   Снимает главный источник `big_mismatch` при старте и при возврате после reap.
2. **Анти-залипание в SW-ветке** (`element.rs`, RDP): проверка
   `|frame - want| > 2` → `diag::cropped()` + `browsers::nudge(id)`, как в GPU.
   Без этого RDP-кадр оставался сжатым до следующего события размера.
3. **Метрики нуля**: `diag::stretched()` / `diag::exact()` + вывод в секундной
   строке `[cef] … растянуто N, точно M`. Инкремент во ВСЕХ ветках
   масштабирования: `big_mismatch`, снэп ±1px, SW `paint_image` при
   несовпадении. Инвариант: `exact + stretched == paints`.

## Осталось (по убыванию отдачи)

4. **Crop для SW-пути** — закрывает пункт (а) цели полностью. Хранить в
   `frames.rs` `(image, w, h)` и добавить в vendored gpui
   `paint_image_region(bounds, tile_region)` (аналог `ExternalTexture::region`)
   ЛИБО резать буфер в `frames::put`. Тогда SW == GPU по качеству. M, риск M
   (правка vendored gpui — пометить «KaminIDE patch», занести в
   `scripts/vendor_patches.py`).
5. **Убрать снэп ±1px** — рисовать внешнюю текстуру по ФИЗИЧЕСКИМ границам:
   `paint_external_texture_px(bounds_dev: Bounds<DevicePixels>)` минуя
   `bounds.scale()` в `window.rs:1838`; и согласовать запрос размера так, чтобы
   `round(w_лог*scale)` совпадал с приходящим кадром (корректировать ±1 по
   факту первого кадра). Без этого «растянуто 0» недостижимо при дробном DPI.
6. **Латч на смене scale** (`browsers.rs:467`): держать прошлый кадр 1:1 и не
   принимать кадры со старым scale, пока не придёт кадр
   `coded ≈ round(bounds*scale_new)`; снимать по таймауту. Плюс: если
   `on_browser` не нашёл браузер (STARTING) — `NOTIFY_PENDING`, досылать из
   `on_after_created` (`browsers.rs:126`) — иначе CEF навсегда в старом scale.
7. **Отказ рисовать кадр не того размера** вместо растяжения: `big_mismatch`
   оставить ТОЛЬКО под таймаутом (>300мс без верного кадра), иначе 1:1 + подложка.
8. **Попап в физике** (`popup.rs` + `element.rs`): текстура в физическом
   `coded_size` рисуется в CSS-прямоугольник → на 150% дропдауны всегда
   растянуты. Рисовать `size = coded/scale` + `region(0,0,rw*scale,rh*scale)`.
9. **Пулы по размеру**: `copy_frame::OWN` расширить до 2-3 текстур (текущий и
   целевой размер) — при осцилляции ресайза не пересоздавать D3D-текстуру;
   в SW — пул `RenderImage` вместо аллокации на каждый `on_paint`.
10. **Коалесинг deliver** (`mod.rs:322`): `__kaminPull()` один раз за тик из
    `pump`, а не на каждое сообщение (на RDP каждый вызов = перевёрстка+кадр).

## Предел CEF при ресайзе (вопрос «а быстрее никак?»)

ФИЗИЧЕСКИЙ ПОТОЛОК: каждый `was_resized` = полная перевёрстка страницы в
renderer-процессе Chromium (для чата 30-150мс на RDP). Пока она идёт, кадра
нового размера НЕ СУЩЕСТВУЕТ. Обойти нельзя — Chrome при быстром ресайзе окна
ведёт себя так же (незакрашенные поля).

НАШ СОБСТВЕННЫЙ ТОРМОЗ (лечится):
- `RESIZE_EVERY=33ms` (`browsers.rs:467`): при драге CEF получает ~30
  команд/с, и каждая ОТМЕНЯЕТ незавершённую перевёрстку — он не «не
  успевает», он бесконечно начинает заново.
- Лечение: во время драга слать КВАНТОВАННО (шаг 24-32px) и реже, точный
  размер — один раз на отпускании (`end_drag`). Вместо 30 недоделанных
  перевёрсток 3-4 доделанные → кадры СОВПАДАЮТ по размеру, растяжение не
  нужно вовсе. Так делают редакторы с OSR-браузером: под драгом содержимое
  «застывает», но не плющится; по отпускании одна перевёрстка.
- Плюс: первое изменение слать НЕМЕДЛЕННО (сейчас ждёт окно дебаунса).

СДЕЛАНО (1.0.33+): растяжение переведено в аварийный режим —
`STRETCH_AFTER_MS=400` (`element.rs`): пока CEF догоняет, кадр рисуется 1:1
(жалоба «если быстро ресайзить, растягивается»); растягиваем только если
верный размер не пришёл дольше порога (спасает «кадр вдвое меньше навсегда»).

## Как доказать 0 (стенд)

`scripts/check_web_resize.py` (шаги 520→900→620→1150→480) прогнать с
`KAMIN_CEF_FORCE_SW=1`; дополнить проверкой «за прогон `растянуто == 0`»
и шагами: смена DPI (эмуляция RDP-реконнекта), свёртка/разворот окна,
возврат вью после reap. Плюс `size_lag_ms` (от `set_wanted` до первого кадра
совпавшего размера) — ловит залипший `hold_resize`.
