# 99 — Усушка node-хоста: node только под exthost + stdio-MCP

Цель: node остаётся ТОЛЬКО носителем VSIX-экстхоста и stdio-MCP серверов.
Всё, что не требует исполнения JS-расширений, живёт в Rust внутри
`kaminide-gpui`. Метрики (замерить до/после, не «на глаз»):

| Метрика | Сейчас | Цель |
|---|---|---|
| Старт расширений до готового чата | 10–15 с | < 3 с |
| RSS в простое (shell + node) | двойной набор данных | −40 % |
| Хопов на файловую операцию | shell → WS → node → fs | shell → fs |

## Инвентаризация: что уже в Rust, что ещё в ноде

Замер по вызовам `host_link` в `crates/shell/src` (17 неймспейсов):

**Уже нативно (ноду не спрашиваем):**
- листинг каталогов — `host_link.rs:390` `std::fs::read_dir` (ленивый, как
  worktree-скан Zed);
- слежение за ФС — `fs_watch.rs` (`notify`);
- иконочная тема (разбор/резолв) — `icon_theme.rs`;
- лейаут-математика и персист сплиттеров — `crates/metrics` + локальный JSON.

**Уводим в Rust (фаза 1, по убыванию выгоды):**
1. `kamin:index:findInFiles` / `findFile` / `status` → `ignore` (walker
   ripgrep) + `grep-searcher`/`grep-regex`. Это ГЛАВНЫЙ тормоз старта:
   в ноде `loader.activateStartup()` ждёт `workspaceHost.listFiles()`, и на
   большой папке активация расширений не наступает вовсе
   (зафиксировано в памяти по chrome-ветке).
2. `kamin:prefs:get|set`, `kamin:workspace:get|changed` → serde_json по
   файлу в data-dir; событие смены воркспейса рождает сам shell.
3. `kamin:sessions:*` (11 методов) → прямой WS-клиент к bridge-серверу
   (`crates/ws` уже есть). Ноде тут делать нечего: PTY и сессии живут в
   сервере на 3456, хост только пересылает.
4. Нативные диалоги → `rfd` (сейчас в ноде PowerShell `-STA` + TopMost-овнер
   форма — целиком лишнее звено).
5. Секреты → DPAPI через `windows` crate вместо node-crypto.
6. `env-collection` → сбор окружения процессом shell.

**Остаётся в ноде (это и есть exthost):**
`command:execute`, `registry:snapshot|update`, `extensions:*`,
`webview:*` / `webviewView:*`, `statusBar:*`, `output:event`,
`notification:show`, `fileDecoration:*`, а также `doc:*`, `lang:*`, `diag:*`
(LSP-клиенты форкает хост).

**Фаза 2 (после фазы 1, отдельным заходом):** LSP-клиенты в Rust
(`doc:*`/`lang:*`/`diag:*`) — тогда нода нужна строго под JS-расширения.

## Порядок и гейты

Каждый шаг: реализация → замер → удаление соответствующего сервиса из
`kamin-host` (не раньше, чем Rust-путь подтверждён живьём).

1. **Поиск/индекс.** Гейт: find-in-files по репозиторию kamin-ide отдаёт
   первые совпадения < 300 мс, полный проход < 2 с; активация расширений
   больше НЕ зависит от `listFiles`.
2. **prefs + workspace.** Гейт: настройки читаются/пишутся при выключенном
   ноде.
3. **sessions.** Гейт: список/создание/переименование/удаление сессий и
   пины работают при выключенном ноде (чат при этом мёртв — он VSIX).
4. **dialogs.** Гейт: «Open folder» из титлбара открывает нативный диалог,
   без PowerShell в дереве процессов.
5. **secrets + env.** Гейт: токен Bridge читается/пишется без ноды.
6. **Обрезка хоста.** Удалить из `kamin-host` перенесённые сервисы,
   оставить exthost-мост + stdio-MCP. Гейт: `RSS` и время старта по таблице
   выше.

## Риски

- **Ломать протокол постепенно.** У ноды остаётся exthost, который сам
  зовёт `workspace`/`fs`/`search` через свои сервисы — их API нужно
  сохранить, но реализовать как прокси в Rust (shell отдаёт данные хосту,
  а не наоборот), иначе VSIX-расширения потеряют `vscode.workspace.*`.
  Порядок обратного вызова (node → shell) уже есть: `requestRenderer`.
- **Двойной источник правды** на время миграции: пока сервис есть и там и
  там, читать ТОЛЬКО из Rust, ноду не опрашивать (иначе разъезд кэшей).
- Фоллбеков не делать: если Rust-путь упал — падать громко (правило
  проекта), а не тихо уходить в ноду.
