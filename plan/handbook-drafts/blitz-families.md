## Методологические оговорки

1. **SKIP выброшен.** В отчёте 10 460 тестов со статусом SKIP (у Blitz нет JavaScript — почти весь testharness скипается). Все проценты — относительно тестов, которые Blitz реально запускает. Их знаменатель НЕ равен полному числу тестов семейства в WPT. Наш стенд гоняет только reftests, так что колонка reftest — прямое сравнение, но следует сверить, что список файлов совпадает (у Blitz reftest-знаменатель = все reftests семейства на ревизии `a95401e4e`, включая те, что мы могли исключить).
2. **Тест-уровень, не subtest.** Все цифры здесь — pass/fail на уровне целого теста (для reftest это единственная метрика; для testharness Blitz тоже репортит test-level PASS/FAIL, subtests есть лишь у 936 тестов). Сайт blitz.is рисует subtest-процент (по css в целом 48.11%, 17 008/35 350) — он не равен цифрам этой таблицы.
3. **testharness у Blitz без JS** — 948 запущенных testharness-тестов это в основном check-layout-подобные тесты, которые их раннер умеет исполнять сам; остальной testharness в SKIP.
4. **crashtest почти всегда PASS** (566/567) — «не упал» ≈ pass; включение crashtests в «all» завышает семейства с их большим числом (css-multicol: 93 crashtests из 573 → all 28.4% против reftest 13.6%; css-break аналогично).
5. **Классификация по манифесту:** 37 тестов из отчёта не нашлись в манифесте (переименованы/вариантные URL) — учтены как unknown в итогах, в семейные reftest-цифры не входят.
6. **Данные:** repo `DioxusLabs/blitz-wpt-results`: `summary/areas/css/<family>.json` (тайм-серии, формат `[tests, servo_score, subtests, subtests_passed]`, reftest/testharness там НЕ разделены) + сырые `reports/<blitz-sha>.json.zst` (wptreport). Разделение по типам — только через сырой отчёт + WPT MANIFEST, что и сделано здесь.
