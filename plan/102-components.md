# 102. Компонентирование интерфейса (как в React/Angular)

## Зачем

Файловая модульность (120 файлов, правило ≤250 строк) дала читаемость и **ноль**
кадров: для gpui все эти функции склеиваются в ОДИН вью. Замер release после
победы над фризом (`plan/101-cef.md`, Ф6):

| что | цена на кадр |
|---|---|
| кадр окна целиком | 13–60 мс |
| taffy | 6–20 мс |
| узлов раскладки | 658–968 |
| **замеров содержимого** | **3100–4700** |

gpui умеет НЕ переделывать неизменившееся, но кэш работает по **сущности**:
`AnyView` с `cached_style` переигрывает записанные диапазоны prepaint/paint
(`vendor/gpui/src/view.rs:205,280` → `Scene::replay`). Условия: те же bounds,
маска, текстовый стиль, вью не в `dirty_views` и **`!window.refreshing`**.

У нас `impl Render` четыре: `RootView` (весь интерфейс), `OverlayWindow`,
`ToastView`, `KaminTooltip`; `.cached(` — ноль вызовов. Плюс мы будим окно
`cx.refresh()`, который ставит `refreshing = true` (`window.rs:1386`) и глушит
кэш на весь кадр. То есть механизм есть, а включить его нечем.

## Модель

Три сорта сущностей — ровно как «сервис / компонент / шаблон»:

1. **Стор** (`Entity<S>`, без `Render`) — срез состояния и вся его логика.
   Аналог сервиса Angular / стора React. Мутация всегда кончается `cx.notify()`.
2. **Компонент** (`Entity<V>` + `impl Render`) — держит хэндлы нужных сторов и
   свои **пропсы**. Ничего не копирует из сторов: читает при рендере.
3. **Композиция** — родитель вставляет `.child(child.clone().cached(style))` и
   ОБНОВЛЯЕТ пропсы через `set_props`, который зовёт `notify` только при
   реальном отличии. Это и есть change detection: не позвал — кадр переигран.

### Правила (нарушение = устаревшая картинка)

1. Компонент не хранит копию данных стора.
2. Любая мутация стора кончается `cx.notify()`.
3. Пропсы приходят ТОЛЬКО через `set_props`; он сравнивает и notify при отличии.
   Значит пропсы должны быть дешёвыми на сравнение (числа, флаги, `Rc`/id).
4. `.cached()` ставится только на компонент, у которого ВСЕ входы — сторы и
   пропсы. Читаешь глобальный статик или время — кэш запрещён.
5. `cx.refresh()` вне запуска и смены темы **запрещён**: он глушит кэш целиком.
   Приход кадра страницы будит `notify` её панели, а не всё окно.

## Порядок (каждый шаг замеряется)

Гейт после каждого шага: `check_web_anim`, `check_web_resize`, `check_chat_ipc` +
строка счётчиков (`узлов на кадр`, `замеров на кадр`, `taffy`) до/после.

1. **Дерево файлов**: `TreeState` → стор, `FileTreePanel` → компонент,
   виртуализация строк. Самое тяжёлое дерево и самое независимое состояние.
2. **Сайдбар сессий**: `SessionsStore` + `SessionsSidebar`, виртуализация групп.
3. **Правая колонка**: панели вкладов (там страницы CEF, дерево лёгкое).
4. **Статусбар и титлбар**: пропсы простые, кэш почти всегда попадает.
5. **Панель чата** — последней: её `notify` дёргает приход кадра CEF, и здесь же
   снимается `cx.refresh()` из `web/pump.rs`.
6. **Область Customize** — отдельным компонентом, она перекрывает всё.

Состояние (`RootView`, ~100 полей) расслаивается по ходу: поле уезжает в стор
того шага, который его использует. Пока поле общее — оно остаётся в `RootView` и
передаётся пропсом.

## Шаг 1: дерево файлов

* `TreeState` живёт в `Entity<TreeState>`; `RootView.tree` — хэндл.
* Чтение: `self.tree.read(cx)`; запись: `self.tree.update(cx, |t, cx| …)`.
* `FileTreePanel { tree: Entity<TreeState>, tx, props }` + `impl Render`,
  внутри — существующий строитель `ui::file_list::file_tree`.
* Пропсы: корень воркспейса, ширина панели, тема, «есть файл в редакторе»,
  «всё свёрнуто». Всё дешёвое на сравнение.
* Родитель (`file_top_tree`) отдаёт `self.file_tree.clone().cached(...)`.

## Что сделано (шаг 1) и что показали замеры

* `TreeState` живёт в `Entity<TreeState>`; чтение — `RootView::tree(cx)`, запись —
  `tree_mut(cx, …)`, который зовёт `notify` ТОЛЬКО когда замыкание сказало
  «изменилось» (трейт `Changed`).
* `FileTreePanel` — сущность с `Render` и пропсами; родитель
  (`state/file_tree_body.rs`) вставляет её `.cached(size_full)`.
* Пропсы обновляются **вне рендера** — `RootView::sync_panels(cx)` сразу после
  применения события (`main.rs`). Причина: `notify` из фазы отрисовки не ставит
  окну `dirty` и нового кадра не заказывает
  (`vendor/gpui/src/window.rs:117-127`), то есть проверка изменений молча не
  работала бы.
* `cx.refresh()` в насосе кадров CEF заменён на `notify` КОРНЕВОЙ сущности:
  `refresh` ставит `window.refreshing` и глушит кэш всех вью на кадр.
* Пропсом отдаётся ширина панели (раньше бралась из probe-реестра прошлого
  кадра — переигранный кадр prepaint не исполняет) и **поколение оформления**
  `kamin_theme::generation()` (палитра расширения и иконочная тема живут в
  статиках, `ThemeKind` при их смене не меняется).
* probe-регион панели свой на слот (`file-tree@sidebar` и т.д.): имя слота уже
  занято регионами колонок, дерево перетирало их прямоугольники.
* Панели снимаются со слотов, где тул дерева больше не активен.

Замер release в тихом состоянии (без потока кадров CEF):

| | до | после |
|---|---|---|
| узлов раскладки на кадр | 986 | 344–415 |
| замеров содержимого на кадр | 3361 | 1253–1412 |
| переиграно вью за секунду | 0 | 2–4 |

**Открытый вопрос.** Под нагрузкой (страницы шлют ~100 кадров/с) счётчик
переигранных вью снова падает в ноль: что-то помечает панель грязной каждый
кадр. Первый подозреваемый — анимации внутри дерева (спиннер листинга, вспышка
Locate) через `request_animation_frame` → `notify` панели. Проверять счётчиком
`переиграно вью` в секундной сводке.

## Следующие компоненты (по отчёту ревью, в порядке выгоды)

1. Статус-бар — пропсы простые, состояние меняется редко, препятствий нет.
2. Панель Problems — каждый кадр заново строит карту и сортировки.
3. Сайдбар сессий — нет виртуализации, ховер перерисовывает всё.
4. Customize (Design/Settings), панель расширений.
5. Терминал и редактор — последними: нужны свои сторы.

Из ревью же остались невыполненными: `apply` должен возвращать «изменилось» и
notify только по нему; белый список холостых событий; диффы там, где `PartialEq`
уже есть (`events/sessions.rs`); таймеры без источника заказов
(`state/contributed_webview.rs`) — их надо закрыть ДО перехода на точные заказы.
